# 线程安全的栈

```cpp
//定义一个异常类
struct empty_stack : std::exception
{
	const char* what() const throw();
};

template<typename T>
class threadsafe_stack
{
private:
	//内部还是用的std::stack
    std::stack<T> data;  //std::stack本身就是模版,所以这里要用到模版
    mutable std::mutex m;
public:
	threadsafe_stack1() {}  //无参构造
	
    threadsafe_stack1(const threadsafe_stack1& other)  //拷贝构造
    {
        //把other的锁加上(并保证自动解锁)
        //这样保证其他线程暂时操作不来other,让other可以专心复制给现在这个实例
        std::lock_guard<std::mutex> lock(other.m);  
        data = other.data;
    }

    //不允许赋值操作,拷贝赋值删掉
	threadsafe_stack& operator=(const threadsafe_stack&) = delete;

	void push(T new_value)
    {
        //push之前加锁
        std::lock_guard<std::mutex> lock(m);
        //直接move进来,减少一次拷贝
        data.push(std::move(new_value));
    }

    //智能指针版本pop
    std::shared_ptr<T> pop()
    {
        //pop之前加锁
        std::lock_guard<std::mutex> lock(m);
        if (data.empty()) throw empty_stack();
        //把data.top()用智能指针包裹
        std::shared_ptr<T> const res(std::make_shared<T>(data.top()));    
        data.pop();
        return res;
    }

    //引用版本pop
	void pop(T& value)  //传进来一个引用类型,用来接收data.top(),也是防止拷贝
    {
        //pop之前加锁
        std::lock_guard<std::mutex> lock(m);
        if (data.empty()) throw empty_stack();
        value = data.top();
        data.pop();
        //就不用返回了
    }

	bool empty() const
    {
        //清空之前加锁
        std::lock_guard<std::mutex> lock(m);
        return data.empty();  //清空
    }
};
```

下面进行更细的分析, 上面的代码会不会仍然有问题

push操作  如果push进去的变量太大,会不会崩溃?
    不会因为内部用的std::stack  它内部有这方面优化
    push操作失败 也不会影响到stack其他数据
    但是
    但是vector容器可能会有问题，
    因为vector存在内存不足时会重新开辟一片更大的空间, 然后把数据拷贝过去
    将数据拷贝转移到新空间的过程要是发生异常,那数据就丢了

解决办法
    想到的一个方式就是管理vector的capacity，
    每次push的时候要判断一下vector的size和capacity是否相等，
    如果相等则手动扩容并将数据转移到新的vector，再释放旧有的vector。
    但是
    这同样会存在一个问题就是会造成内存溢出，
    因为vector的capacity会随着数据增加而增加，
    当vector中没有数据的时候capacity仍然很大。
    就数据被移出去以后,vector里面没多少数据,但是还占着这么大空间,浪费空间了
    此时也可以通过swap的方式将当前大容量的vector和一个空的vector做交换，
    快速清空内存。
    但是这里我们就是知道一下,并不实现这个

上面的代码大佬仍然觉得有点问题
1. pop提供了两个版本，一个是返回智能指针一个是返回bool类型，比如`std::shared_ptr<T> const res(std::make_shared<T>(data.top())); `也很可能因为内存不足导致构造智能指针失败，或者`value = data.top();`赋值失败，这种情况下抛出异常虽然不会影响栈内数据,但大佬还是有所顾虑。

2. pop函数内部判断栈是否空，如果为空则抛出异常，这种情况大佬不能接受，异常是用来处理和预判突发情况的，对于一个栈为空这种常见现象，仅需根据返回之后判断为空再做尝试或放弃出栈即可。


于是大佬写了优化的版本
```cpp
template<typename  T>
class threadsafe_stack_waitable
{
private:
    std::stack<T> data;
    mutable std::mutex m;
    std::condition_variable cv;  //加了一个条件变量
public:
    threadsafe_stack_waitable() {} //无参构造

    //拷贝构造
    threadsafe_stack_waitable(const threadsafe_stack_waitable& other)
    {
        std::lock_guard<std::mutex> lock(other.m);
        data = other.data;
    }

    //不允许赋值操作,拷贝赋值删掉
    threadsafe_stack_waitable& operator=(const threadsafe_stack_waitable&) = delete;

    void push(T new_value)
    {
        std::lock_guard<std::mutex> lock(m);
        data.push(std::move(new_value));    // ⇽-- - 1
        cv.notify_one(); //通知任意一个在等待的线程
        //当栈为空时,线程若想pop,就挂起,直到这里push进新元素,就通知(唤醒)要pop的线程
    }

    //智能指针版本
    std::shared_ptr<T> wait_and_pop()
    {
        std::unique_lock<std::mutex> lock(m);
        //先判断谓词,栈是不是空 空返回false 然后就阻塞线程,临时释放锁
        //直到被唤醒 再获取锁,再重新判断谓词
        cv.wait(lock, [this]()   
            {
                if(data.empty())
                {
                    return false;
                }
                return true;
            }); //  ⇽-- - 2


        //这里和之前是一样的
        std::shared_ptr<T> const res(
            std::make_shared<T>(std::move(data.top())));   // ⇽-- - 3
        data.pop();   // ⇽-- - 4
        return res;
    }

    //引用版本
    void wait_and_pop(T& value)
    {
        //和上面同理
        std::unique_lock<std::mutex> lock(m);
        cv.wait(lock, [this]()
            {
                if (data.empty())
                {
                    return false;
                }
                return true;
            });

        value = std::move(data.top());   // ⇽-- - 5
        data.pop();   // ⇽-- - 6
    }

    bool empty() const
    {
        std::lock_guard<std::mutex> lock(m);
        return data.empty();
    }
};
```

但是仍有隐患
就是这句话`std::shared_ptr<T> const res(std::make_shared<T>(std::move(data.top())));`
引发异常 
虽然可以在外面捕获这个异常
但是可能栈顶元素就没了,走到下一句` data.pop();`就要报错了
或者栈顶元素根本没被pop掉,留在那里了

解决办法(前两种看看就好,别管)
1. `wai_and_pop`失败的线程修复后再次取一次数据。
2. 将`notify_one`改为`notify_all`，这样能保证通知所有线程。但是`notify_all`将导致所有线程竞争，并不可取。
3. 可以通过栈存储智能指针的方式进行，`std::shared_ptr<T> const res(std::make_shared<T>(std::move(data.top())));` 就是这句改成用智能指针构造智能指针(可能开销小一点不容易引发异常)

# 线程安全队列

先写一个和上面一样的队列版本
```cpp
#include <mutex>
#include <queue>

template<typename T>
class threadsafe_queue
{
private:

    mutable std::mutex mut;
    std::queue<T> data_queue;
    std::condition_variable data_cond; //条件变量

public:
    threadsafe_queue() {}
    //也可以搞一个拷贝构造,然后删除拷贝赋值(这里可能大佬懒得写了)

    void push(T new_value)
    {
        std::lock_guard<std::mutex> lk(mut);
        data_queue.push(std::move(new_value));
        data_cond.notify_one();    //一样的 通知任意一个在等待的线程 队列有元素了
    }

    void wait_and_pop(T& value)    //⇽-- - ②
    {
        std::unique_lock<std::mutex> lk(mut);
        //和上面栈是一个意思,只是这里简写了
        //cv.wait(lock, [this]()   
        //    {
        //        if(data.empty())
        //        {
        //            return false;
        //        }
        //        return true;
        //    }); 
        
        data_cond.wait(lk, [this] {return !data_queue.empty(); });
        
        value = std::move(data_queue.front());
        data_queue.pop();
    }

    std::shared_ptr<T> wait_and_pop()   // ⇽-- - ③
    {
        std::unique_lock<std::mutex> lk(mut);
        data_cond.wait(lk, [this] {return !data_queue.empty(); });   // ⇽-- - ④
        std::shared_ptr<T> res(
            std::make_shared<T>(std::move(data_queue.front())));
        data_queue.pop();
        return res;
    }

    bool empty() const
    {
        std::lock_guard<std::mutex> lk(mut);
        return data_queue.empty();
    }
};
```

队列的调用和上面栈的调用写的是完全一样的,就把类的名字改一改就好了,这里就不写了

顾虑是wait_and_pop的时候
如果`value = std::move(data_queue.front());`的时候异常了  就算后面这个线程恢复了,它可能"忘记"刚刚没pop成功  呈现的效果就是线程没pop出来元素
队列中的某一个元素因为这个故障 会被延迟消费(就是下一个线程来了再被消费)

所以要优化一下
```cpp
template<typename T>
class threadsafe_queue_ptr
{
private:
    mutable std::mutex mut;
    //队列现在存的是T类型的智能指针
    //好处 是智能指针和智能指针之间的构造,移动  开销比较小
    //可能只需要改变指向  或者  改变引用计数就好了  
    std::queue<std::shared_ptr<T>> data_queue;
    std::condition_variable data_cond;
public:
    threadsafe_queue_ptr(){}

    void push(T new_value)
    {
        //构造智能指针,并且是把new_value移动进来(防止拷贝)
        std::shared_ptr<T> data(std::make_shared<T>(std::move(new_value)));   
        
        std::lock_guard<std::mutex> lk(mut);
        data_queue.push(data);
        data_cond.notify_one();
    }
    
    void wait_and_pop(T& value)
    {
        std::unique_lock<std::mutex> lk(mut);
        data_cond.wait(lk, [this] {return !data_queue.empty(); });

        //因为队列里存的是智能指针,所以取出来以后用*取内容
        value = std::move(*data_queue.front());    
        data_queue.pop();
    }
    
    std::shared_ptr<T> wait_and_pop()
    {
        std::unique_lock<std::mutex> lk(mut);
        data_cond.wait(lk, [this] {return !data_queue.empty(); });

        //这里就直接取出智能指针就好了
        std::shared_ptr<T> res = data_queue.front();   // ⇽-- - 3
        data_queue.pop();
        return res;
    }
    
    bool empty() const
    {
        std::lock_guard<std::mutex> lk(mut);
        return data_queue.empty();
    }
};
```

但是这代码还有缺陷
[[13.无锁并发队列]] 我们说过这个缺陷
因为队列push和pop时采用的是一个mutex，所以同一时刻仅有一个线程pop或者push, 其实可以一个线程push的同时,另一个线程可以pop

队列和栈最本质的区别是队列是首尾操作。
我们可以考虑将push和pop操作分化为分别对尾和对首部的操作。对首和尾分别用不同的互斥量管理就可以实现真正意义的并发了。

下面的代码大佬用链表自己实现了队列
```cpp
template<typename T>
class threadsafe_queue_ht
{
private:
	struct node
	{
		std::shared_ptr<T> data; //还是用智能指针存储数据
		std::unique_ptr<node> next; //独占指针指向下一个节点
	};
	std::mutex head_mutex; // 保护头节点的互斥锁
	std::unique_ptr<node> head; // 头节点（独占所有权）
	//std::unique_ptr<node>  可以就理解为C风格的node*
	std::mutex tail_mutex; // 保护尾节点的互斥锁
	node* tail;  // 尾节点指针
	//因为下面设计的原因,所以这里tail为C风格指针
	std::condition_variable data_cond; // 条件变量（用于等待数据）

	std::unique_ptr<node> get_tail()
	{
    	//拿tail之前上锁
		std::lock_guard<std::mutex> tail_lock(tail_mutex);
		return tail;
	}

    //pop操作4
	std::unique_ptr<node> pop_head()
	{
    	//得到旧的head结点
		std::unique_ptr<node> old_head = std::move(head);
		//head移动到下一位
		//都用move 防止拷贝
		head = std::move(old_head->next);
		return old_head; 
	}

    //pop操作3
	std::unique_lock<std::mutex> wait_for_data()
	{
    	//先上锁
		std::unique_lock<std::mutex> head_lock(head_mutex);
		//判断head和tail是否指向相同,相同就是空队列
		data_cond.wait(head_lock, [&] {return head.get() != get_tail(); }); //5
		//unique_lock可以用move的方式,把锁转移到外面
		//到外面的函数,这个锁可以看做一直保持在那里
		return std::move(head_lock);
	}

    //pop操作2
	std::unique_ptr<node> wait_pop_head()
	{
    	//拿到head锁
		std::unique_lock<std::mutex> head_lock(wait_for_data());
		return pop_head();  //执行真正的pop操作
	}
	
	std::unique_ptr<node> wait_pop_head(T& value)
	{
		std::unique_lock<std::mutex> head_lock(wait_for_data());
		value = std::move(*head->data);
		return pop_head();
	}
	
public:

	threadsafe_queue_ht() :  // ⇽-- - 1
		head(new node), tail(head.get()){}  //默认构造
	//就是构造了一个空节点node 然后head,tail都指向它
	//这里是在head里创建,然后tail那里get一下就好了(get拿到智能指针的裸指针)
	//因为head是unique_ptr 所以肯定不能让tail同时指相一个node
	//所以tail才被设计成node*

	threadsafe_queue_ht(const threadsafe_queue_ht& other) = delete;
	threadsafe_queue_ht& operator=(const threadsafe_queue_ht& other) = delete;

    //pop操作1
	std::shared_ptr<T> wait_and_pop() //  <------3
	{
    	//拿到旧的head的指针(此时新head应该被往前移动了)
		std::unique_ptr<node> const old_head = wait_pop_head();
		return old_head->data; 
		//离开这个函数以后,old_head会被自动析构,那这个节点就会被自动析构
	}

	void wait_and_pop(T& value)  //  <------4
	{
		std::unique_ptr<node> const old_head = wait_pop_head(value);
	}

	bool empty()
	{
		std::lock_guard<std::mutex> head_lock(head_mutex);
		return (head.get() == get_tail());
	}

	void push(T new_value)  //<------2
	{
    	//先创建数据的智能指针
		std::shared_ptr<T> new_data(std::make_shared<T>(std::move(new_value)));
		//再创建节点的智能指针
		std::unique_ptr<node> p(new node);
		//拿到新创建的节点裸指针
		node* const new_tail = p.get();
		{
    		//上锁
    		std::lock_guard<std::mutex> tail_lock(tail_mutex);
    		tail->data = new_data; //把数据压到当前tail(因为tail都指向空节点)
    		tail->next = std::move(p);  //把新创建的节点设置为next
    		tail = new_tail; //把tail移动到p(空节点)
    	}
    	data_cond.notify_one();  //通知
	}
};
```
