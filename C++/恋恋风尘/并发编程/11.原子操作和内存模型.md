# 改动序列

在一个C++程序中，每个对象都具有一个改动序列，<mark style="background: #FFF3A3A6;">它由所有线程在对象上的全部写操作构成，</mark>其中第一个写操作即为对象的初始化
<mark style="background: #ABF7F7A6;">每个对象都具有一个改动序列,大部分情况下，这个序列会随程序的多次运行而发生变化，但是在程序的任意一次运行过程中，所含的全部线程都必须形成相同的改动序列。</mark>
    ![[Pasted image 20250714193931.png]]
    ![[Pasted image 20250714194003.png]]

改动序列基本要求
1. 只要某线程看到过某个对象，则该线程的后续读操作必须获得相对新近的值，并且，该线程就同一对象的后续写操作，必然出现在改动序列后方。
2. 如果某线程先向一个对象写数据，过后再读取它，那么必须读取前面写的值。
3. 若在改动序列中，上述读写操作之间还有别的写操作，则必须读取最后写的值。
4. 在程序内部，对于同一个对象，全部线程都必须就其形成相同的改动序列，并且在所有对象上都要求如此. 
5. 多个对象上的改动序列只是相对关系，线程之间不必达成一致

# 原子类型

标准原子类型的定义位于头文件`<atomic>`内
通过`atomic<>`定义一些原子类型的变量，如`atomic<bool>`,`atomic<int>` 这些类型的操作全是原子化的。

从C++17开始，所有的原子类型都包含一个静态常量表达式成员变量，`std::atomic::is_always_lock_free`。
这个成员变量的值表示在任意给定的目标硬件上，原子类型X是否始终以<mark style="background: #ABF7F7A6;">无锁</mark>结构形式实现。
    ![[Pasted image 20250714194925.png]]
    就是说对这个数据做操作,操作本身就是原子的
    ![[Pasted image 20250714195012.png]]
    true就是在任意硬件上,这个变量类型都支持原子操作
    false就是有硬件,不支持这个变量类型的原子操作,就可能不是线程安全的

只有一个原子类型不提供`is_lock_free()`成员函数：`std::atomic_flag` (一个无锁操作的最基本的结构,所以如`atomic<bool>`都可以基于它实现)。

`std::atomic_flag`的`test_and_set`成员函数是一个原子操作，他会先检查`std::atomic_flag`当前的状态是否被设置过，
1. 如果没被设置过(比如初始状态或者清除后,此时`std::atomic_flag`是false)，将`std::atomic_flag`当前的状态设置为`true`，并返回`false`(代表设置之前是false)。
2. 如果被设置过则直接返回`ture`。

# 实现自旋锁

自旋锁   在多线程环境下保护共享资源的同步机制
就是  当一个线程尝试获取锁时，如果锁已经被其他线程持有，那么该线程就会不断地循环检查锁的状态，直到成功获取到锁为止。
普通的线程加锁,一个加上,一个加不上,加不上的线程此时就会挂起
```cpp
#include <iostream>
#include <atomic>
#include <thread>

//我们自己实现了一个锁的类
class SpinLock {
public:
    void lock() { //上锁
        //flag.test_and_set(按上面介绍的来)
        //flag是false flag变true 返回false
        //false是true  返回true(此时就会陷入循环)
        //std::memory_order_acquire设置了内存序(一般用在读)
        //1 处
        while (flag.test_and_set(std::memory_order_acquire)); // 自旋等待，直到成功获取到锁
    }

    void unlock() { // 释放锁
        //std::memory_order_release设置了内存序(一般用在写)
        //flag.clear  设置flag时false
        //2 处
        flag.clear(std::memory_order_release); 
    }

private:
    std::atomic_flag flag = ATOMIC_FLAG_INIT;  //用到原子类型atomic_flag
    //ATOMIC_FLAG_INIT相当于初始化flag为false(初始状态)
};

void TestSpinLock() {
    SpinLock spinlock;
    std::thread t1([&spinlock]() {
        spinlock.lock();
        for (int i = 0; i < 3; i++) {
            std::cout << "*";
            }
        std::cout << std::endl;
        spinlock.unlock();
        });


    std::thread t2([&spinlock]() {
        spinlock.lock();
        for (int i = 0; i < 3; i++) {
            std::cout << "?";
        }
        std::cout << std::endl;
        spinlock.unlock();
        });


    t1.join();
    t2.join();
}
```
自旋锁虽然是锁
但是上面我们并没有用mutex,就是代码实际并没上锁,是代码本身在实现上锁
所以自旋锁的代价其实比挂起要小 因为其实是实现了无锁

# 宽松内存序
(介绍内存序到底是个啥)

cpu内存结构图
![[Pasted image 20250714220510.png]]
StoreBuffer就是一级Cache， Catche是二级Cache，Memory是三级Cache。

要是没有一定的规则,可能就会发生问题
比如cpu1,cpu2同时从catche中取出a,同时修改a,然后写回catche,就会出问题

可以用MESI协议(写失效协议)保证内存一致性
同一时间, 只有一个 CPU 核心负责写入数据，其他的核心，只能同步读取到这个写入。
在这个 CPU 核心写入 cache 之后，它会去广播一个“失效”请求告诉所有其他的 CPU 核心。

MESI 协议对应的四个不同的标记，分别是：
M：代表已修改（Modified）
E：代表独占（Exclusive）
S：代表共享（Shared）
I：代表已失效（Invalidated）
    ![[Pasted image 20250714221514.png]]
    ![[Pasted image 20250714221723.png]]
    我们可以这么理解，如果变量a此刻在各个cpu的StoreBuffer中，那么CPU1核修改这个a的值，放入cache时通知其他CPU核写失效，因为同一时刻仅有一个CPU核可以写数据

两个改动序列的术语
"`synchronizes-with`" : 同步
    "A `synchronizes-with` B" 的意思就是 A和B同步，简单来说如果多线程环境下，有一个线程先修改了变量m，我们将这个操作叫做A，之后有另一个线程读取变量m，我们将这个操作叫做B，那么B一定读取A修改m之后的最新值。

"`happens-before`" : 先行
    "A `happens-before` B" 的意思是如果A操作先于B操作，那么A操作的结果对B操作可见。

介绍了上面这些,再来看`std::memory_order_relaxed` 内存序
1. 作用于原子变量 
2. 不具有`synchronizes-with`关系 
3. 对于同一个原子变量，在同一个线程中具有`happens-before`关系, 在同一线程中不同的原子变量不具有`happens-before`关系，可以乱序执行。 
4. 多线程情况下不具有`happens-before`关系

2就是说 不同线程比如对于同一个变量的操作  的顺序是不一定的  可能顺序是混乱的

(比如先对a写10  后对b写9  具体a,b谁先被修改不一定的)

在一个线程中，如果某个表达式已经看到原子变量的某个值a，则该表达式的后续表达式只能看到a或者比a更新的值。
```cpp
std::atomic<bool> x, y;
std::atomic<int> z;

void write_x_then_y() {
    x.store(true, std::memory_order_relaxed);  // 1
    y.store(true, std::memory_order_relaxed);  // 2
}

void read_y_then_x() {
    //取y
    while (!y.load(std::memory_order_relaxed)) { // 3
        std::cout << "y load false" << std::endl;
    }

    //取x
    if (x.load(std::memory_order_relaxed)) { //4
        ++z;
    }
}

void TestOrderRelaxed() {
    std::thread t1(write_x_then_y);
    std::thread t2(read_y_then_x);
    t1.join();
    t2.join();
    //断言z一定不为0
    assert(z.load() != 0); // 5
}
```
断言assert 可以看[[assert 断言]]

理想情况是
t1  x为true,y为true
然后t2  3那里y因为是true所以退出循环  然后z++
最后断言那里不会抛出错误

但是可能y先为true  然后y是true退出循环
然后x可能还没有变true  那z不会++

虽然我运行结果是理想情况,z被++成功
![[Pasted image 20250714231448.png]]

解释
    从cpu架构分析
    假设线程t1运行在CPU1上，t2运行在CPU2上，那么t1对x和y的操作，t2是看不到的。
    比如当线程t1运行至1处将x设置为true，t1运行至2处将y设置为true。
    这些操作仅在CPU1的store buffer中，还未放入cache和memory中，CPU2自然不知道。
    如果CPU1先将y放入memory，那么CPU2就会读取y的值为true。那么t2就会运行至3处从while循环退出，进而运行至4处，此时CPU1还未将x的值写入memory，
    t2读取的x值为false，进而线程t2运行结束，然后CPU1将x写入true, t1结束运行，最后主线程运行至5处，因为z为0,所以触发断言。


```cpp
void TestOderRelaxed2() {
	std::atomic<int> a{ 0 };
	std::vector<int> v3, v4;

    //让a变为偶数
	std::thread t1([&a]() {
		for (int i = 0; i < 10; i += 2) {
			a.store(i, std::memory_order_relaxed);
		}
		});

    //让a变为奇数
	std::thread t2([&a]() {
		for (int i = 1; i < 10; i += 2)
			a.store(i, std::memory_order_relaxed);
		});

    //将a push进v3
	std::thread t3([&v3, &a]() {
		for (int i = 0; i < 10; ++i)
			v3.push_back(a.load(std::memory_order_relaxed));
		});

    //将a push进v4
	std::thread t4([&v4, &a]() {
		for (int i = 0; i < 10; ++i)
			v4.push_back(a.load(std::memory_order_relaxed));
		});

	t1.join();
	t2.join();
	t3.join();
	t4.join();

	for (int i : v3) {
		std::cout << i << " ";
	}

	std::cout << std::endl;
	for (int i : v4) {
		std::cout << i << " ";
	}
	std::cout << std::endl;
}
```

    通过`memory_order_relaxed`的方式仅能保证对a的操作是原子的(同一时刻仅有一个线程写a的值，但是可能多个线程读取a的值)。
    但是多个线程之间操作不具备同步关系，也就是线程t1将a改为7，那么线程t3不知道a改动的最新值为7，它读到a的值为1。但是

# 先行(Happens-before)
Happens-before

## 顺序先行(sequenced-before)

单线程情况下前面的语句先执行，后面的语句后执行。
a sequenced-before b   就是操作a先于操作b，那么操作b可以看到操作a的结果
比如下面的
```cpp
int main(){
    //操作a
    int m = 100;
    //操作b
    std::cout << "m is " << std::endl;
}
```

"sequencde-before"具备传递性
比如操作 a “sequenced-before” 操作 b, 且操作 b “sequenced-before” 操作 m, 则操作 a “sequenced-before” 操作 m.
(这个就知道一下,上面那个称之为传递,  其实有点废话)

___
## 线程间先行

"inter-thread-happens-before"，即 多线程情况的"happens-before".

我们前面提到的"synchronizes-with" (同步)可以构成 这里的多线程"happens-before"。
如果线程 1 中的操作 a “synchronizes-with” 线程 2 中的操作 b, 则操作 a “inter-thread happens-before” 操作 b.

此外 synchronizes-with 还可以 “后接” 一个 sequenced-before 关系组合成 inter-thread happens-before 的关系:
比如操作 a “synchronizes-with” 操作 b, 且操作 b “sequenced-before” 操作 m, 则操作 a “inter-thread happens-before” 操作 m.
    就是a和b同步 b在m之前  那么a在m之前同步

 Inter-thread happens-before 关系则可以 “前接” 一个 sequenced-before 关系以延伸它的范围:
如果操作 a “sequenced-before” 操作 k, 且操作 k “inter-thread happens-before” 操作 b, 则操作 a “inter-thread happens-before” 操作 b.

inter-thread happens-before 关系具有传递性
如果操作 a “inter-thread happens-before” 操作 k, 且操作 k “inter-thread happens-before” 操作 b, 则操作 a “inter-thread happens-before” 操作 b.

## 依赖关系

依赖关系有 carries dependency 和 dependency-ordered before.

单线程情况下a “sequenced-before” b, 且 b 依赖 a 的数据, 则 a “carries a dependency into” b. 
称作 a 将依赖关系带给 b, 也理解为b依赖于a。
```cpp
void TestDependency() {
    // 1 处
    std::string str = "hello world!";
    // 2 处
    int i = 3;
    // 3 处
    std::cout << str[i] << std::endl;
}
```
3处代码需要依赖1处和2处两个变量的值，所以达成依赖关系。
所以  1 “sequenced-before” 3，且3 依赖 1的数据，则 1 "carries a dependency into" 3
同样的道理 2 "sequenced-before" 3, 且3依赖2 的数据，则2 "carries a dependency into" 3.

<mark style="background: #FFF3A3A6;">"carries a dependency into" 也被归为"happens-before"。</mark>

线程1执行操作A(比如对i自增)，线程2执行操作B(比如根据i访问字符串下表的元素), 如果线程1先于线程2执行，且操作A的结果对操作B可见，我们将这种叫做 A "dependency-ordered before" B.

<mark style="background: #FFF3A3A6;">有人会说这不是前面说到的A "synchronizes with " B吗？你可以这么理解。就当作他们达到的效果是一致的，只不过A "dependency-ordered before" B 更细化一点，表述了一种依赖</mark>

# Happens-before不代表指令执行顺序

Happens-before仅是C++语义层面的描述，表示 a "Happens-before" b<mark style="background: #FFF3A3A6;">仅能说明a操作的结果对b操作可见。</mark>
但是Happens-before不代表指令实际执行顺序，C++编译器可以对不相关的指令任意编排达到优化效果
```cpp
int  Add() {
    int a = 0, b = 0;
    //1 处
    a++; 
    // 2 处
    b++;
    // 3 处
    return  a + b;
}
```
操作1一定是happens-before 操作2 的(a "sequenced-before" b)，就是我们理解的 `a++` 先于 `b++`。
(a的操作)
但是计算机的指令可能不是这样，一条C++语句对于多条计算机指令。
有可能是先将b值放入寄存器eax做加1，再将a的值放入寄存器edx做加1
