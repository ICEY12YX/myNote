# memory_order_seq_cst
`memory_order_seq_cst`全局严格顺序
可以用于 `store`, `load` 和 `read-modify-write` 操作, 实现 `sequencial consistent` 的顺序模型.

下面代码用的是  无顺序约束
```cpp
std::atomic<bool> x, y;
std::atomic<int> z;

void write_x_then_y() {
    //x和y通通设定为true
    x.store(true, std::memory_order_relaxed);  // 1
    y.store(true, std::memory_order_relaxed);  // 2
}

void read_y_then_x() {
    //取y  如果为true,非一下是false 离开循环
    while (!y.load(std::memory_order_relaxed)) { // 3
        std::cout << "y load false" << std::endl;
    }

    //取x  x为true z就++
    if (x.load(std::memory_order_relaxed)) { //4
        ++z;
    }

}

void TestOrderRelaxed() {

    std::thread t1(write_x_then_y);
    std::thread t2(read_y_then_x);
    t1.join();
    t2.join();
    //断言z不等于0  (等于0才报错)  
    assert(z.load() != 0); // 5
}
```
结果
    ![[Pasted image 20250715171437.png]]
    虽然这里没有断言报错  
    但是还是可能断言报错的
    就是可能y先为true  然后y是true退出循环
    然后x可能还没有变true  那z不会++

要是将代码的内存序改为`memory_order_seq_cst`
```cpp
std::atomic<bool> x, y;
std::atomic<int> z;

void write_x_then_y() {
    //x和y通通设定为true
    x.store(true, std::memory_order_seq_cst);  // 1
    y.store(true, std::memory_order_seq_cst);  // 2
}

void read_y_then_x() {
    //取y  如果为true 离开循环
    while (!y.load(std::memory_order_seq_cst)) { // 3
        std::cout << "y load false" << std::endl;
    }

    //取x  x为true z就++
    if (x.load(std::memory_order_seq_cst)) { //4
        ++z;
    }

}

void TestOrderRelaxed() {

    std::thread t1(write_x_then_y);
    std::thread t2(read_y_then_x);
    t1.join();
    t2.join();
    assert(z.load() != 0); // 5
}
```
此时就一定不会断言报错
因为`memory_order_seq_cst`保证代码执行的顺序
y为true时  x肯定为true了
结果
    ![[Pasted image 20250715172334.png]]

虽然这样好
但是实现 sequencial consistent 模型有一定的开销. 
现代 CPU 通常有多核, 每个核心还有自己的缓存. 
为了做到全局顺序一致, 每次写入操作都必须同步给其他核心.(就是可能要往其他核心的缓存里都写一份,不重新去那些缓存里写一份,那可能别的核心会读到旧值)
为了减少性能开销, 如果不需要全局顺序一致, 我们应该考虑使用更加宽松的顺序模型.
(做无锁并发的时候,很少用`memory_order_seq_cst`)

# memory_order_relaxed
`memory_order_relaxed`无约束顺序
可以用于 store, load 和 read-modify-write 操作, 实现 relaxed 的顺序模型
上一节讲过它的特点[[11.原子操作和内存模型]]  宽松内存序  那里

```cpp
void TestOrderRelaxed() {
    std::atomic<bool> rx, ry;

    std::thread t1([&]() {
        rx.store(true, std::memory_order_relaxed); // 1
        ry.store(true, std::memory_order_relaxed); // 2
        });


    std::thread t2([&]() {
        //ry是true就退出循环
        while (!ry.load(std::memory_order_relaxed)); //3
        //断言rx一定为true(为false就报错)
        assert(rx.load(std::memory_order_relaxed)); //4
        });

    t1.join();
    t2.join();
}
```
其实跟上面第一个代码差不多意思

此时t2执行退出3循环   进而执行4，此时t2看到的rx值为false触发断言。

# Acquire-Release

上面的代码怎样保证2 同步于 3 是解决问题的关键， 我们引入 Acquire-Release 内存顺序。

在 acquire-release 模型中, 会使用 `memory_order_acquire`, `memory_order_release` 和 `memory_order_acq_rel` 这三种内存顺序

对原子变量的 load 可以使用 `memory_order_acquire` 内存顺序. 这称为 acquire 操作.
对原子变量的 store 可以使用 `memory_order_release` 内存顺序. 这称为 release 操作.

read-modify-write 操作即读 (load) 又写 (store), 它可以使用` memory_order_acquire`, `memory_order_release` 和 `memory_order_acq_rel`:
1. 如果使用 `memory_order_acquire`, 则作为 acquire 操作;
2. 如果使用 `memory_order_release`, 则作为 release 操作;
3. 如果使用 `memory_order_acq_rel`, 则同时为两者.
(这个就看看)

Acquire-release 可以实现 synchronizes-with 的关系. 
如果一个 acquire 操作在同一个原子变量上读取到了一个 release 操作写入的值,
则这个 release 操作 “synchronizes-with” 这个 acquire 操作.
```cpp
void TestReleaseAcquire() {
    std::atomic<bool> rx, ry;

    std::thread t1([&]() {
        rx.store(true, std::memory_order_relaxed); // 1
        //ry这里使用release释放同步
        ry.store(true, std::memory_order_release); // 2
        });


    std::thread t2([&]() {
        //ry这里使用acquire获取同步
        while (!ry.load(std::memory_order_acquire)); //3
        //断言rx永远为true
        assert(rx.load(std::memory_order_relaxed)); //4
        });

    t1.join();
    t2.join();
}
```
这里是2操作 “synchronizes-with” 3操作  (在两个线程中)
从内存序角度解释
    memory_order_release保证这个操作之前的读写不乱序
    memory_order_acquire保证这个操作之后的读写不乱序
    ![[Pasted image 20250715175953.png]]![[Pasted image 20250715180044.png]]
    加上release以后,能保证线程2在读ry的时候(就是3操作) , rx已经被修改为true了(就是1操作做过了)
    所以此时就放心往下执行就好了,不用去缓存里重新写一份 这样麻烦的事情

或者从理论层面上(别管)
    2操作 “synchronizes-with” 3操作 
    3操作 "sequenced-before" 4操作  (同一个线程中)
    2操作  “inter-thread happens-before” 4操作
    [[11.原子操作和内存模型]]   线程间先行

# Release sequences
(就是多个操作应用release 形成一个序列)

多个线程对<mark style="background: #FFF3A3A6;">同一个变量</mark>release操作，另一个线程对这个变量acquire，那么只有一个线程的release操作和这个acquire线程构成同步关系。
```cpp
void ReleasAcquireDanger2() {
    std::atomic<int> xd{ 0 }, yd{ 0 };
    std::atomic<int> zd;

    std::thread t1([&]() {
        xd.store(1, std::memory_order_release);  // (1)
        yd.store(1, std::memory_order_release); //  (2)
        });

    std::thread t2([&]() {
        yd.store(2, std::memory_order_release);  // (3)
        });


    std::thread t3([&]() {
        //yd不是0(比如1,2那就是true  非一下是false)就退出循环
        while (!yd.load(std::memory_order_acquire)); // (4)
        //断言xd等于1
        assert(xd.load(std::memory_order_acquire) == 1); // (5)
        });

    t1.join();
    t2.join();
    t3.join();
}
```
2和4形成同步
3和4形成同步
但是同时只能有一个同步关系

如果2和4形成同步
那xd肯定等于1  不会触发断言报错

如果3和4形成同步
那xd可能不会等于1  可能触发断言报错

还有一个也可以叫release sequence
针对一个原子变量 M 的 release 操作 A 完成后, 接下来 M 上可能还会有一连串的其他操作. 如果这一连串操作是由
1. 同一线程上的写操作 (release以后 有别的操作改了M)
2. 任意线程上的 read-modify-write(读改写) 操作 这两种构成的  (release以后  有别的线程改了M)
则称这一连串的操作为以 release 操作 A 为首的 release sequence. 
(这里的写操作和 read-modify-write 操作可以使用任意内存顺序.)

如果一个 acquire 操作在同一个原子变量上读到了一个 release 操作写入的值, 
或者读到了以这个 release 操作为首的 release sequence 写入的值, 
那么这个 release 操作 “synchronizes-with” 这个 acquire 操作.

```cpp
void ReleaseSequence() {
    std::vector<int> data;
    std::atomic<int> flag{ 0 };

    std::thread t1([&]() {
        data.push_back(42);  //(1)
        //release(可以理解为上面说的release sequence的头  操作A)
        flag.store(1, std::memory_order_release); //(2)
    });

    std::thread t2([&]() {
        int expected = 1;
        //compare_exchange_strong 就是让flag和expected比较
        //flag等于expected(就是1)  然后把flag置为2 
        //然后此时整个flag.compare_exchange_strong 置为true 非一下就是false就退出循环
        while (!flag.compare_exchange_strong(expected, 2, std::memory_order_relaxed)) // (3)
            expected = 1;  //先不管
        }
    );

    std::thread t3([&]() {
        //flag>=2 循环退出
        while (flag.load(std::memory_order_acquire) < 2); // (4)
        //断言数组里42已经被加进去了
        assert(data.at(0) == 42); // (5)
        });

    t1.join();
    t2.join();
    t3.join();
}
```
如果 要5断言成功
那就 flag>=2  
那就 3操作成功  这里要求flag为1
那就 2操作成功

其实就是2操作是A  然后3操作是release sequence中的一步
所以3操作`synchronizes-with`4操作

# memory_order_consume
`memory_order_consume` 其实是 `acquire-release` 模型的一部分
但是它比较特殊, 它涉及到数据间相互依赖的关系.

比如
```cpp
p++;   // (1)
i++;   // (2)
p[i]   // (3)
```
3依赖于1  3依赖于2
或者就简单理解为acquire加了一层 "依赖"的关系

memory_order_consume 可以用于 load 操作. 
使用 memory_order_consume 的 load 称为 consume 操作. 
如果一个 consume 操作在同一个原子变量上读到了一个 release 操作写入的值, 或以其为首的 release sequence 写入的值, 
则这个 release 操作 “dependency-ordered before” 这个 consume 操作.
(就是把acquire改成了consume)
```cpp
void ConsumeDependency() {
    std::atomic<std::string*> ptr;
    int data;

    std::thread t1([&]() {
        std::string* p = new std::string("Hello World"); // (1)
        data = 42; // (2)
        //把p写进ptr(用到指针,就是ptr此时也指向"Hello World"了)
        ptr.store(p, std::memory_order_release); // (3)
        });

    std::thread t2([&]() {
        std::string* p2;
        //等待 ptr 非空
        //非空以后 p2也非空  那就退出循环
        while (!(p2 = ptr.load(std::memory_order_consume))); // (4)

        //断言
        assert(*p2 == "Hello World"); // (5)
        assert(data == 42); // (6)
        });

    t1.join();
    t2.join();
}
```

# 单例模式改良

我们之前用智能指针双重检测方式实现的单例模式
[[05.线程安全的单例模式]]  智能指针 那里 的几个代码
那几个代码总的来说都有问题
![[Pasted image 20250715194308.png]]
优化一下
```cpp
//利用智能指针解决释放问题
class SingleMemoryModel
{
private:
    SingleMemoryModel() {}
    SingleMemoryModel(const SingleMemoryModel&) = delete;
    SingleMemoryModel& operator=(const SingleMemoryModel&) = delete;
public:
    ~SingleMemoryModel() {
        std::cout << "single auto delete success " << std::endl;
    }

    //返回一个shared_ptr,指向static single
    static std::shared_ptr<SingleMemoryModel> GetInst() {
        //读_b_init  用acquire
        if (_b_init.load(std::memory_order_acquire)) { 
            return single;
        }

        //没有实例化就加锁
        s_mutex.lock();

        //因为上面上了锁,所以此时不可能再有线程往后执行,去修改_b_init,所以安全性可以保证,就不用std::memory_order_acquire了
        if (_b_init.load(std::memory_order_relaxed)) {
            s_mutex.unlock(); //实例化了,那就先解锁(记得解锁!),再直接返回
            return single;
        }
        
        single = std::shared_ptr<SingleMemoryModel>(new SingleAuto);
        //多一句 写_b_init 用release
        //用release 保证上面这条语句完全执行完成  再往后执行
        //就不会有上面的问题
        _b_init.store(true, std::memory_order_release);
        s_mutex.unlock();  //上面_b_init修改了,再解锁,保证上锁期间没有别的线程可以修改_b_init
        return single;
    }
private:
    static std::shared_ptr<SingleMemoryModel> single;
    static std::mutex s_mutex;
    static std::atomic<bool> _b_init ;  //搞一个原子变量(初始为false) 表示有么有实例化过一个single的共享智能指针shared_ptr
};
```

调用
```cpp
void TestSingleMemory() {

        std::cout << "thread t1 singleton address is 0x: " << SingleMemoryModel::GetInst() << std::endl;

        std::cout << "thread t2 singleton address is 0x: " << SingleMemoryModel::GetInst() << std::endl;
        });

}
```
