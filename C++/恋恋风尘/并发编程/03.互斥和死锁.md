# 锁的使用

通过mutex对共享数据进行加锁,防止多线程访问共享区造成数据不一致问题。
```cpp
std::mutex mtx1;  //锁
int shared_data = 100;

void use_lock() {
    while (true) {
        mtx1.lock(); //锁上,这样t2就没办法执行加锁,就会等在那里,直到t1这里解锁
        shared_data++;
        std::cout << "current thread is " << std::this_thread::get_id() << std::endl;
        std::cout << "sharad data is " << shared_data << std::endl;
        mtx1.unlock();  //解锁
        std::this_thread::sleep_for(std::chrono::microseconds(10));
    }

}

void test_lock() {
    //t1对shared_data进行++操作
    std::thread t1(use_lock);

    //t2对shared_data进行--t1对shared_data进行++操作操作
    std::thread t2([]() {
        while (true) {
            mtx1.lock();
            shared_data--;
            std::cout << "current thread is " << std::this_thread::get_id() << std::endl;
            std::cout << "sharad data is " << shared_data << std::endl;
            mtx1.unlock();
            std::this_thread::sleep_for(std::chrono::microseconds(10));
        }
        });

    //等待t1,t2执行完
    //但是两个子线程我们写的都是无限循环,所以t1,t2会不断执行下去
    t1.join();
    t2.join();
}
```

`std::this_thread::sleep_for(std::chrono::microseconds(10));` 为什么要写这个,会比较好

# lock_guard的使用

用lock_guard自动加锁和解锁
(和智能指针一样,防止我们每次new了指针,忘记delete释放,  这里防止加锁以后忘记解锁)
```cpp
//把上面的use_lock改写成lock_guard
void use_lock() {
    while (true) {
        std::lock_guard<std::mutex> lock(mtx1);
        shared_data++;
        std::cout << "current thread is " << std::this_thread::get_id()
                                         << std::endl;
        std::cout << "sharad data is " << shared_data << std::endl;
        std::this_thread::sleep_for(std::chrono::microseconds(10));
    }
}
```
但是上面那样写,有点问题,就是睡的时候锁没有被释放,因为要执行到作用域结束,lock_guard的锁才会被释放

所以像下面那样添加作用域会比较好
```cpp
//把上面的use_lock改写成lock_guard
void use_lock() {
	while (true) {
		{
			std::lock_guard<std::mutex> lock(mtx1);
			shared_data++;
			std::cout << "current thread is " << std::this_thread::get_id()
				<< std::endl;
			std::cout << "sharad data is " << shared_data << std::endl;
		}
		std::this_thread::sleep_for(std::chrono::microseconds(10));
	}
}
```

`std::lock_guard<std::mutex> lock(mtx1);`
以后看到这句,就和`mtx1.lock();` 一样的, 当做加锁操作就好了

# 如何保证数据安全

实现一个栈对象,让栈在多线程操作的时候保持安全
```cpp
template<typename T>
class threadsafe_stack1
{
private:
    //内部还是用的std::stack
    std::stack<T> data;  //std::stack本身就是模版,所以这里要用到模版
    mutable std::mutex m;
public:
    threadsafe_stack1() {}  //无参构造
    threadsafe_stack1(const threadsafe_stack1& other)  //拷贝构造
    {
        //把other的锁加上(并保证自动解锁)
        //这样保证其他线程暂时操作不来other,让other可以专心复制给现在这个实例
        std::lock_guard<std::mutex> lock(other.m);  
        data = other.data;
    }

    //不允许赋值操作,拷贝赋值删掉
    threadsafe_stack1& operator=(const threadsafe_stack1&) = delete;
    
    void push(T new_value)
    {
        //push之前加锁
        std::lock_guard<std::mutex> lock(m);
        //直接move进来,减少一次拷贝
        data.push(std::move(new_value));
    }

    //问题代码
    T pop()
    {
        //pop之前加锁
        std::lock_guard<std::mutex> lock(m);
        auto element = data.top();  //得到栈顶元素
        data.pop();  //元素出栈
        return element;  //返回栈顶元素
    }

    bool empty() const
    {
        //清空之前加锁
        std::lock_guard<std::mutex> lock(m);
        return data.empty();  //清空
    }
};
```
`mutable std::mutex m;` 为什么要写mutable?
    因为大部分函数我们习惯会写成const,就是不修改成员变量
    但是mutex锁,我们要经常加锁解锁变来变去
    所以加上mutable

上面的代码有问题,下面制造一个问题,具体看看问题哪来的
```cpp
void test_threadsafe_stack1() {
    threadsafe_stack1<int> safe_stack;
    safe_stack.push(1);

    std::thread t1([&safe_stack]() {  //用引用的方式捕捉safe_stack
        if (!safe_stack.empty()) {  //判断栈不为空
            //不加这句可能看不出问题
            //t1,t2都睡一会,让t1,t2pop的时机差不多
            std::this_thread::sleep_for(std::chrono::seconds(1));
            safe_stack.pop();  //不为空,就pop数据
            }
        });

    //和t1做的事情一样
    std::thread t2([&safe_stack]() {
        if (!safe_stack.empty()) {
            std::this_thread::sleep_for(std::chrono::seconds(1));
            safe_stack.pop();
        }
    });

    //勿忘写这个
    t1.join();
    t2.join();
}
```
上面的问题是empty()的调用时机问题
    就是假如栈中只有一个元素了
    t1,t2先都判断完empty()以后,返回非空
    然后t1,t2近乎同时pop,就有问题了,因为只用一个元素好pop

解决办法是使用异常
```cpp
struct empty_stack : std::exception
{
    const char* what() const throw();
};

template<typename T>
class threadsafe_stack
{
private:
    //内部还是用的std::stack
    std::stack<T> data;  //std::stack本身就是模版,所以这里要用到模版
    mutable std::mutex m;
public:
    threadsafe_stack1() {}  //无参构造
    threadsafe_stack1(const threadsafe_stack1& other)  //拷贝构造
    {
        //把other的锁加上(并保证自动解锁)
        //这样保证其他线程暂时操作不来other,让other可以专心复制给现在这个实例
        std::lock_guard<std::mutex> lock(other.m);  
        data = other.data;
    }

    //不允许赋值操作,拷贝赋值删掉
    threadsafe_stack1& operator=(const threadsafe_stack1&) = delete;
    
    void push(T new_value)
    {
         //push之前加锁
        std::lock_guard<std::mutex> lock(m);
        //直接move进来,减少一次拷贝
        data.push(std::move(new_value));
    }

    std::shared_ptr<T> pop()
    {
        //pop之前加锁
        std::lock_guard<std::mutex> lock(m);
        if (data.empty()) throw empty_stack();
        std::shared_ptr<T> const res(std::make_shared<T>(data.top()));    
        data.pop();
        return res;
    }

    void pop(T& value)
    {
        //pop之前加锁
        std::lock_guard<std::mutex> lock(m);
        if (data.empty()) throw empty_stack();
        value = data.top();
        data.pop();
    }

    bool empty() const
    {
        //清空之前加锁
        std::lock_guard<std::mutex> lock(m);
        return data.empty();  //清空
    }
};
```

```cpp
void pop(T& value)  //传进来一个引用类型,用来接收data.top(),也是防止拷贝
{

    std::lock_guard<std::mutex> lock(m);
    if (data.empty()) throw empty_stack();
    value = data.top();
    data.pop();

    //就不用返回了
}
```

```cpp
{
    std::lock_guard<std::mutex> lock(m);
    
    if (data.empty()) return nullptr;  //不抛出异常,而是返回空指针,外面再去判断有么有pop成功
    
    std::shared_ptr<T> const res(std::make_shared<T>(data.top()));    
    data.pop();
    return res;
}
```

# 死锁怎么造成的

就是循环等待对方解锁
比如t1先加锁A  再加锁B
t2先加锁B  再加锁A
然后t1加锁A ,t2加锁B  以后,  开始互相等待
```cpp
std::mutex t_lock1;
std::mutex t_lock2;
int m_1 = 0;
int m_2 = 1;

void dead_lock1() {
    while (true) {
        std::cout << "dead_lock1 begin " << std::endl;
        t_lock1.lock();  //加锁1
        m_1 = 1024;  //改数据1
        t_lock2.lock();  //加锁2
        m_2 = 2048;  //改数据2
        t_lock2.unlock();  //解锁2(解锁就是需要后加锁的先解锁,就是临近的先解锁)
        t_lock1.unlock();  //解锁1
        
        std::this_thread::sleep_for(std::chrono::milliseconds(5));
        std::cout << "dead_lock2 end " << std::endl;
    }
}

void dead_lock2() {
    while (true) {
        std::cout << "dead_lock2 begin " << std::endl;
        t_lock2.lock();  //加锁2
        m_2 = 2048;  //改数据2
        t_lock1.lock();  //加锁1
        m_1 = 1024;  //改数据1
        t_lock1.unlock();  //解锁1
        t_lock2.unlock();  //解锁2
        
        std::this_thread::sleep_for(std::chrono::milliseconds(5));
        std::cout << "dead_lock2 end " << std::endl;
    }
}

void test_dead_lock() {
    std::thread t1(dead_lock1);
    std::thread t2(dead_lock2);
    t1.join();
    t2.join();
}
```
上面的代码运行之后在某一个时刻一定会导致死锁
(虽然我运行了很久都没发生死锁)

实际工作中避免死锁的一个方式就是将<mark style="background: #FFF3A3A6;">加锁和解锁的功能封装为独立的函数</mark>
保证在独立的函数里执行完操作后就解锁，<mark style="background: #FFF3A3A6;">不会导致一个函数里使用多个锁的情况</mark>
```cpp
//加锁和解锁作为原子操作解耦合，各自只管理自己的功能
//atomic_lock1只做修改m_1的工作,并且修改完以后就解锁了!!!
void atomic_lock1() {
    std::cout << "lock1 begin lock" << std::endl;
    t_lock1.lock();
    m_1 = 1024;
    t_lock1.unlock();
    std::cout << "lock1 end lock" << std::endl;
}

//atomic_lock2只做修改m_2的工作,并且修改完以后就解锁了!!!
void atomic_lock2() {
    std::cout << "lock2 begin lock" << std::endl;
    t_lock2.lock();
    m_2 = 2048;
    t_lock2.unlock();
    std::cout << "lock2 end lock" << std::endl;
}

void safe_lock1() {
    while (true) {
        atomic_lock1();  //调用自己写的原子操作
        atomic_lock2();
        std::this_thread::sleep_for(std::chrono::milliseconds(5));
    }
}

void safe_lock2() {
    while (true) {
        atomic_lock2();
        atomic_lock1();
        std::this_thread::sleep_for(std::chrono::milliseconds(5));
    }
}

void test_safe_lock() {
    std::thread t1(safe_lock1);
    std::thread t2(safe_lock2);
    t1.join();
    t2.join();
}
```
重点是封装成函数以后, 修改完数据以后就解锁了
这样t1,t2加锁顺序不一样,也不会导致死锁

# 同时加锁

如果真的想同时加多个锁怎么办
那有办法,同一时间就把两个锁加号
```cpp
//假设这是一个很复杂的数据结构,假设我们不建议执行拷贝构造
class som_big_object {
public:
    som_big_object(int data) :_data(data) {}  //普通构造
    
    //拷贝构造
    som_big_object(const som_big_object& b2) :_data(b2._data) {}
    
    //移动构造
    som_big_object(som_big_object&& b2) :_data(std::move(b2._data)) {}
    
    //重载输出运算符
    friend std::ostream& operator<< (std::ostream& os, const som_big_object& big_obj) {
        os << big_obj._data;  //输出时直接输出_data
        return os;
    }

    //重载赋值运算符
    //必须重载,否则这个类没办法执行等号运算符(会报错)
    //同样不重载移动运算符,xxx=std::move(yyy) 就会报错
    som_big_object& operator= (const som_big_object& b2) {
        if (this == &b2) {  //避免自赋值,还拷贝的情况
            return *this;
        }
        _data = b2._data;
        return *this;
    }

    //这里没用到移动赋值,所以就不写了

    //交换数据
    friend void swap(som_big_object& b1, som_big_object& b2) {
        //用move实现交换,防止拷贝
        som_big_object temp = std::move(b1);
        b1 = std::move(b2);
        b2 = std::move(temp);
    }
private:
    int _data;  //假装这是复杂的数据结构
};

//定义一个类对上面的类做管理
class big_object_mgr {
public:
    big_object_mgr(int data = 0) :_obj(data) {}  //普通构造
    
    void printinfo() {
        std::cout << "current obj data is " << _obj << std::endl;
    }

    //演示三种交换(这三句是为了,给函数前面加上friend,好在外面访问big_object_mgr的私有成员)
    friend void danger_swap(big_object_mgr& objm1, big_object_mgr& objm2);
    friend void safe_swap(big_object_mgr& objm1, big_object_mgr& objm2);
    friend void safe_swap_scope(big_object_mgr& objm1, big_object_mgr& objm2);
    
private:
    std::mutex _mtx;  //一个互斥量
    som_big_object _obj;  //上面写的复杂数据结构
};

//危险的交换
void danger_swap(big_object_mgr& objm1, big_object_mgr& objm2) {
    //打印线程id
    std::cout << "thread [ " << std::this_thread::get_id() << " ] begin" << std::endl;

    //相等就不换了
    if (&objm1 == &objm2) {
        return;
    }

    //不相等
    //先给objm1加锁
    std::lock_guard <std::mutex> gurad1(objm1._mtx);
    //此处为了故意制造死锁，我们让线程小睡一会(就是让两个锁错开加)
    std::this_thread::sleep_for(std::chrono::seconds(1));
    //再给objm2加锁
    std::lock_guard<std::mutex> guard2(objm2._mtx);
    swap(objm1._obj, objm2._obj);  //交换

    std::cout << "thread [ " << std::this_thread::get_id() << " ] end" << std::endl;
}

//测试上面的danger_swap
void test_danger_swap() {
    big_object_mgr objm1(5);
    big_object_mgr objm2(100);

    //调用的时候故意,t1先加objm1的互斥量,t2先加objm2的互斥量
    std::thread t1(danger_swap, std::ref(objm1), std::ref(objm2));
    std::thread t2(danger_swap, std::ref(objm2), std::ref(objm1));
    t1.join();
    t2.join();

    objm1.printinfo();
    objm2.printinfo();
}

//安全的交换
void safe_swap(big_object_mgr& objm1, big_object_mgr& objm2) {
    std::cout << "thread [ " << std::this_thread::get_id() << " ] begin" << std::endl;
    if (&objm1 == &objm2) {
        return;
    }

    //一下加两个锁
    std::lock(objm1._mtx, objm2._mtx);
    //领养锁
    std::lock_guard <std::mutex> gurad1(objm1._mtx, std::adopt_lock);

    //此处为了故意制造死锁，我们让线程小睡一会
    std::this_thread::sleep_for(std::chrono::seconds(1));

    //领养锁2(这句应该也可以写上面)
    std::lock_guard <std::mutex> gurad2(objm2._mtx, std::adopt_lock);

    swap(objm1._obj, objm2._obj);
    std::cout << "thread [ " << std::this_thread::get_id() << " ] end" << std::endl;
}

//测试上面的safe_swap
void test_safe_swap() {
    big_object_mgr objm1(5);
    big_object_mgr objm2(100);

    std::thread t1(safe_swap, std::ref(objm1), std::ref(objm2));
    std::thread t2(safe_swap, std::ref(objm2), std::ref(objm1));
    t1.join();
    t2.join();

    objm1.printinfo();
    objm2.printinfo();
}

//简化上面的安全的交换(C++17的优化)
void safe_swap_scope(big_object_mgr& objm1, big_object_mgr& objm2) {
    std::cout << "thread [ " << std::this_thread::get_id() << " ] begin" << std::endl;
    if (&objm1 == &objm2) {
        return;
    }

    //不用领养了,而是用std::scoped_lock,同时守卫两个锁
    std::scoped_lock guard(objm1._mtx, objm2._mtx);
    //等价于
    //std::scoped_lock<std::mutex, std::mutex> guard(objm1._mtx, objm2._mtx);
    
    swap(objm1._obj, objm2._obj);
    std::cout << "thread [ " << std::this_thread::get_id() << " ] end" << std::endl;
}
```
`friend std::ostream& operator<< (std::ostream& os, const som_big_object& big_obj)`重载运算符>>  可以参考[[5.重载运算符]]

不重载移动运算符,xxx=std::move(yyy) 就会报错
原因是  (详情情况[[触发移动构造,移动赋值的时机]])

执行test_danger_swap测试danger_swap,发现会产生死锁
    ![[Pasted image 20250707190116.png]]
    原因是我们故意调用的时候故意,t1先加objm1的互斥量,t2先加objm2的互斥量
    但是罪魁祸首还是danger_swap写的不好

`std::lock_guard <std::mutex> gurad1(objm1._mtx, std::adopt_lock);` 
    就是`std::lock(objm1._mtx, objm2._mtx);`只负责加锁,不负责解锁,我们不想自己写解锁

    就是这个锁不是你生的,你不用负责加锁,但是你要负责解锁

# 层级锁

有时候我不想同时上两个锁
而是确实想先上一个锁,再上一个锁
我们下面封装一个hierarchical_mutex,实现对锁加上"层次"
就是锁1必须先上,锁2必须后上,  顺序错了就会报错
```cpp
//层级锁
class hierarchical_mutex {
public:
    explicit hierarchical_mutex(unsigned long value) :_hierarchy_value(value),
        _previous_hierarchy_value(0) {}  //普通构造(把当前层级值传进来)

    //拷贝构造和拷贝赋值都删了
    hierarchical_mutex(const hierarchical_mutex&) = delete;
    hierarchical_mutex& operator=(const hierarchical_mutex&) = delete;

    //上锁
    void lock() {
        check_for_hierarchy_violation();  //检查要加的锁的层级值
        _internal_mutex.lock();  //没问题,上锁
        update_hierarchy_value();  //更新层级
    }

    //解锁
    void unlock() {
        //要解锁的锁 是否就是 最近一次加的锁
        if (_this_thread_hierarchy_value != _hierarchy_value) {
            throw std::logic_error("mutex hierarchy violated");
        }

        //没问题
        //就更新一下_this_thread_hierarchy_value
        _this_thread_hierarchy_value = _previous_hierarchy_value;
        _internal_mutex.unlock();  //解锁
    }

    //判断能不能加锁
    //这个函数先不管吧
    bool try_lock() {
        check_for_hierarchy_violation();
        if (!_internal_mutex.try_lock()) {
            return false;
        }

        update_hierarchy_value();
        return true;
    }
private:
    std::mutex _internal_mutex;  //互斥量
    unsigned long const _hierarchy_value;  //当前层级值
    unsigned long _previous_hierarchy_value;  //上一个锁的层级值
    
    //本线程记录的层级值(就是最近一次加锁  这个锁的层级值)
    static thread_local unsigned long _this_thread_hierarchy_value;

    //检查要上的锁的层级 是否大于等于 最近一次加锁的层级值
    void check_for_hierarchy_violation() {
        if (_this_thread_hierarchy_value <= _hierarchy_value) {
            //大了,顺序不对,就抛出异常
            throw std::logic_error("mutex  hierarchy violated");
        }
    }

    //更新
    void update_hierarchy_value() {
        //改上一个锁的层级值
        _previous_hierarchy_value = _this_thread_hierarchy_value;
        //改最近一次锁的层级值 
        _this_thread_hierarchy_value = _hierarchy_value;
    }
};

//这两行是同一句
//因为是static的成员变量,所以要初始化(注意此时static的成员变量要放cpp里,不能放.h里)
//这里是让_this_thread_hierarchy_value变为最大,这样任何锁都可以加上了
thread_local unsigned long hierarchical_mutex::_this_thread_hierarchy_value(ULONG_MAX);

void test_hierarchy_lock() {
    hierarchical_mutex hmtx1(1000);  //锁的层级需要我们自己写
    hierarchical_mutex hmtx2(500);
    std::thread t1([&hmtx1, &hmtx2]() {  //没问题
        hmtx1.lock();
        hmtx2.lock();
        hmtx2.unlock();
        hmtx1.unlock();
        });

    std::thread t2([&hmtx1, &hmtx2]() {  //加不了锁
        hmtx2.lock();
        hmtx1.lock();
        hmtx1.unlock();
        hmtx2.unlock();
        });

    t1.join();
    t2.join();
}
```
