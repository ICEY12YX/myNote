传递子线程函数的参数：<mark style="background: #ABF7F7A6;">直接传递即可</mark>，注意：传递参数分为三种方式，<mark style="background: #ABF7F7A6;">值传递，引用传递，指针传递。</mark>
```cpp
void test(int i,const int& refI,const int* pi){
    //分别对应值传递,引用传递,指针传递
}

int main(){
    int i = 10;
    std::thread myThread(test,i,i,&i);
    myThread.detach()
}
```

但是我们可以试一下会发现,值传递 和 引用传递,这个传进子进程的地址和main里的i是不一样的, 而指针传递, 地址是一样的

<mark style="background: #ABF7F7A6;">在使用detach时不要传递指针</mark>，或者说在设置子线程函数时，不要设置指针参数。因为值传递和引用传递并未直接传递地址，而指针传递却直接传递地址。所以当使用deatch时，传指针就会导致错误，指针已经被系统回收，所以不要千万不要传指针。
    就是比如说子线程里面在操作主线程传进来的指针,主线程执行完毕但是子线程还在执行,主线程中指针指向的地址会被回收,此时就算子线程是detach了,也会报错,因为那个指针内存被回收了

<mark style="background: #ABF7F7A6;">在使用detach时不要使用隐式类型转化，因为很有可能子线程参数还没来的及将参数转化为自己的类型，主线程就已经执行完毕了</mark>
```cpp
void test(const std::string& str){
    //分别对应值传递,引用传递,指针传递
}

int main(){
    std::thread myThread(test,"hello");
    myThread.detach()
}
```
上面"hello"是const char* 类型,而要传的是string类型,虽然会有隐式转化,但是可能隐式转化还没来的及发生,主线程就结束了,这个时候查bug根本没法查

总结就是:
普通类型用值传递
类类型用引用传递
<mark style="background: #ABF7F7A6;">类类型传递引用会首先调用一次复制构造函数生成一个临时变量，故而导致地址不相同。如果采用值传递，需要两次复制构造函数，开销更大</mark>

根据上面的演示，<mark style="background: #ABF7F7A6;">使用引用传递会调用一次复制构造函数，导致函数无法对引用对象进行修改</mark>，于是std::ref诞生了，它可以使子线程在传递参数时不再调用复制构造函数。
    可以说 是为了能在子线程里改传进来的类(因为引用本身就是别名,应该可以和在主线程一样可以改)
    也可以说 是为了避免拷贝
