只是通过引用计数实现的方式也引来了<mark style="background: #ABF7F7A6;">引用成环</mark>的问题，这种问题靠它自己是没办法解决的，所以在C++11的时候将shared_ptr和weak_ptr一起引入了标准库，用来解决循环引用的问题
```cpp
//这里先声明为了下面A类里面能不报错
class B;  //这里绝对不能写大括号,否则会导致B类重复定义

class A {
public:
	std::shared_ptr<B> sharedBc;
};

class B {
public:
	std::shared_ptr<A> sharedAc;  //后面加了个c,意指class,为了和下面main中的变量名区分开
};

int main() {
	std::shared_ptr<A> sharedA = std::make_shared<A>();
	std::shared_ptr<B> sharedB = std::make_shared<B>();

	sharedA->sharedBc = sharedB;  //这里构成循环引用的
	sharedB->sharedAc = sharedA;
}
```

那循环引用是不是因为最后sharedA->sharedBc没有被释放?

    就是说追根溯源是因为sharedA->sharedBc和sharedB->sharedAc,所以A,B对象释放不来,仍然保持1个引用计数
    然后因为A,B对象释放不来,所以sharedA->sharedBc没有被释放

大佬总结说:"这是两个堆内存,我指你,你指我,导致内存泄漏"
    两个堆内存应该是指  sharedA->sharedBc指向B对象  sharedB->sharedAc指向A对象
    而sharedA本身指向A对象,所以可以简化成 A对象(内部)指向B对象
    同理B对象(内部)指向A对象

解决办法
```cpp
//这里先声明为了下面A类里面能不报错
class B;  //这里绝对不能写大括号,否则会导致B类重复定义

class A {
public:
	std::weak_ptr<B> weakBc;  //只用把一个改成weak_ptr
};

class B {
public:
	std::shared_ptr<A> sharedAc;  //后面加了个c,意指class,为了和下面main中的变量名区分开
};

int main() {
    std::shared_ptr<B> sharedB = std::make_shared<B>();
	std::shared_ptr<A> sharedA = std::make_shared<A>();

	sharedA->weakBc = sharedB;  //B对象引用计数=1
	sharedB->sharedAc = sharedA; //A对象引用计数=2
	
	// main() 结束时：
    // 1. sharedA 析构 → A 的引用计数-1=1（B::sharedAc 仍持有）
    // 2. sharedB 析构 → B 的引用计数-1=0 → 释放 B 对象
    //    - B 释放时，B::sharedAc 析构 → A 的引用计数-1=0 → 释放 A 对象
    // 结果：A 和 B 都被正确释放！

    //如果析构顺序反一下(上面定义顺序反一下)
    // 1. sharedB 析构 → B 的引用计数-1=0 → 释放 B 对象
    //    - B 释放时，B::sharedAc 析构 → A 的引用计数-1=1 （sharedA 仍持有）
    // 2. sharedA 析构 → A 的引用计数-1=0
    // 结果：A 和 B 都被正确释放！
}
```
