<mark style="background: #ABF7F7A6;">三种继承方式不影响子类对父类的访问权限，子类对父类只看父类的访问控制权</mark>
    就是说,不管是哪种继承,子类访问父类中的变量,函数,还是按变量,函数用的什么权限修饰符, 和继承用的什么权限修饰符没关系
    (这个原因其实是,要把下面一并看完,可以得出的)
    (就是继承后虽然会转权限,但是转的权限是相对于子类来说的,就是,是在子类里转,在子类里某个public成员变private了,或者说把父类成员先按原本的权限拉进子类,再转.  所以这个成员在子类里还能访问,但是在外部或者再继承一次就访问不到了)
    (这里比较难理解,请把代码和博客里的代码看看完,就能理解了)

<mark style="background: #ABF7F7A6;">public、protected、private三种继承方式，相当于把父类的public访问权限在子类中变成了对应的权限。</mark> 如protected继承，把父类中的public成员在本类中变成了protected的访问控制权限；private继承，把父类的public成员和protected成员在本类中变成了private访问控制权。

public继承（最常用，表示"is-a"关系）
```cpp
class Animal {
public:
    void eat() {}       // 公有
protected:
    void breathe() {}   // 保护
private:
    void digest() {}    // 私有
};

class Dog : public Animal { // public继承
public:
    void bark() {
        eat();     // ✅ 可访问（public→public）
        breathe(); // ✅ 可访问（protected→protected）
        // digest(); ❌ 不可访问（private永远不可见）
    }
};

int main() {
    Dog d;
    d.eat();   // ✅ 可访问（仍是public）
    // d.breathe(); ❌ 不可访问（在派生类中是protected）
}
```

protected继承（罕见，表示"实现继承"）
```cpp
class Base {
public:
    int x;
protected:
    int y;
};

class Derived : protected Base {
public:
    void foo() {
        x = 10; // ✅ public→protected
        y = 20; // ✅ protected→protected
    }
};

int main() {
    Derived d;
    // d.x = 30; ❌ 不可访问（在派生类中是protected）
}
```

private继承（极少用，表示"has-a"关系）
这里注意,private继承(前面的继承也一样,下面相当于把public的成员先拉进子类里,然后转一下权限为private,所以子类里还能用,但是外部用不来了)
```cpp
class Engine {
public:
    void start() {}
};

class Car : private Engine { // private继承
public:
    void drive() {
        start(); // ✅ 可访问（public→private，仅在类内可用）
    }
};

int main() {
    Car c;
    // c.start(); ❌ 不可访问（在派生类中是private）
}
```

类相当于定义了一个新类型，该类型生成在堆或栈上的对象时内存排布和c语言相同。但是c++规定，<mark style="background: #ABF7F7A6;">C++在类对象创建时就 应该也必须有 在对应内存将数据初始化的能力，这就是构造函数</mark>
    就是说,类在实例化的时候,就会初始化
    这个初始化,指的就是调用构造函数
    要是自己写的构造函数,可以加上成员初始化列表,给一些成员变量附上初值
    要是不写构造函数,那系统就会调用默认的构造函数
    但是默认的构造函数是<mark style="background: #FFF3A3A6;">什么都不做</mark>,就是不会对任何成员变量赋初值,这个时候直接访问某个成员变量,得到的是未定义的值
    所以还是需要自己写构造函数的

构造函数有以下类型。
1.<mark style="background: #ABF7F7A6;">普通构造函数</mark>
2.<mark style="background: #ABF7F7A6;">复制(拷贝)构造函数：用另一个对象来初始化对象对应的内存</mark>
3.移动构造函数：也是用另一个对象来初始化对象(后面再讲)
4.默认构造函数：当类没有任何构造函数时，编译期会为该类生成一个默认的的构造函数，在最普通的类中，默认构造函数什么都没做，对象对应的内存没有被初始化。(知道就行)
    注意 构造函数要和类名同名
    注意 习惯上普通构造的形参后面加'_'
```cpp
class CPPTest{  //写class和struct都是一样的
public:
    CPPTest(int a_ , int b_):a(a_),b(b_){}  //普通构造
    CPPTest(const CPPTest& cppTest):a(cppTest.a),b(cppTest.b){}  //复制构造

private:
    int a;
    int b;
}
```

当类对象被销毁时，就会调用析构函数。
<mark style="background: #ABF7F7A6;">栈上对象的销毁时机就是函数栈销毁时</mark>。
<mark style="background: #ABF7F7A6;">堆上的对象销毁时机就是该堆内存被手动释放时</mark>，如果用new申请的这块堆内存，那调用delete销毁这块内存时就会调用析构函数。
    就是说析构函数是对象销毁的时候触发
    那什么时候对象销毁呢?  两种情况
    对象在栈上,那就是作用域结束时(就是上面说的函数栈销毁时)
    对象在堆上,那就是调用delete时(就是堆内存被手动释放时)
    <mark style="background: #FFF3A3A6;">注意 析构函数不能被重载, 也不能带参数</mark>
<mark style="background: #FFF3A3A6;">注意 不写析构函数也会生成一个默认的析构,就是什么都不干</mark>
```cpp
class CPPTest{  //写class和struct都是一样的
public:
    CPPTest(int a_ , int b_):a(a_),b(b_){}  //普通构造
    CPPTest(const CPPTest& cppTest):a(cppTest.a),b(cppTest.b){}  //复制构造

    ~CPPTest(){}  //析构函数

private:
    int a;
    int b;
}
```
所以说在栈上时,(想调用析构函数,或者说销毁对象),什么都不用干,等到出作用域的大括号{ }就好了
在堆上时,delete一下

所以按上面那样说,好像析构函数没啥用,反正系统也会自己生成一个默认的
<mark style="background: #ABF7F7A6;">如果当类对象销毁时有一些我们必须手动操作的步骤时，析构函数就派上了用场</mark>
    下面这个时候就要手动写一个析构
```cpp
class CPPTest{  //写class和struct都是一样的
public:
    CPPTest(int a_ , int b_ , int c_):a(a_),b(b_),pi(new int(c_)){}  //普通构造
    CPPTest(const CPPTest& cppTest):a(cppTest.a),b(cppTest.b)
    ,pi(new int(*cppTest.c)){}  //复制构造

    ~CPPTest(){  //析构函数
        delete pi;
    }  

private:
    int a;
    int b;
    int* pi;
}
```
上面是目前为止(目前学过的),唯一需要手动写析构的地方,就是 **类中有动态分配的内存（手动 `new`/`new[]`）**
要是不在析构中delete,那就算对象delete掉,这个new出来的内存不会被释放,就会导致内存溢出
