<mark style="background: #ABF7F7A6;">静态变量区在编译时就已经确定地址</mark>
```cpp
unsigned g_i = 0;  //全局变量(编译时就确定好位置了)

unsigned test() {
	static unsigned callCount = 0;  //静态变量(编译时就确定好位置了)
	return ++callCount;
}

int main() {
	test();
	test();
	test();
	unsigned testCallCount = test();
	std::cout << testCallCount << std::endl;  //输出4
	
	std::cin.get();
}
```
其中static unsigned callCount = 0这句,在编译时就运行了,之后每次调用这个函数,这句不会再次运行,就是callCount不会再次初始化

引用就是作用阉割的指针 <mark style="background: #ABF7F7A6;">(可以视为“类型* const”)</mark>  所以引用必须上来就赋初值，不能设置为空,并且<mark style="background: #FFF3A3A6;">引用一旦初始化后，就不能改变其指向的对象</mark>
```cpp
int i = 20;
int& ref = i;
int* const pi = &i; 
```
上面2,3两句其实是一样的,都起到一个指向i的作用(第三句加const,保证pi不会改变指向,引用也不能改指向)
就是调用的时候,pi需要用到&,*  而ref就和用i本身一样用就好了

为什么设计引用是不可改变指向的?
    ![[Pasted image 20250606164620.png]]


编译器不将引用视作对象，<mark style="background: #ABF7F7A6;">操作引用相当于操作引用指向的对象。也就从根本是杜绝了引用篡改内存的能力。</mark>
    就是说,引用不能改指向,所以只能操作指向的对象,而指针(只要不用int* const这种),就可以随便改指向,操作任意一片内存
