### Python 基础语法笔记 (八)：文件读写与“指针”解密

#### 模块 1：覆盖写入 (`w`) 与相对路径

```python
text = "This is a sample text for testing the code.\nIt contains multiple lines.\nThis is the third line."

my_file = open("sample.txt", "w")  # 打开文件, 如果文件不存在, 会创建一个新文件
# 只写sample.txt应该是以现在的位置为基础的相对路径

# open的第二个参数 "w" 表示写入模式, 如果文件已经存在, 会覆盖原有内容
# 疑问: 另外还有哪些

my_file.write(text)  # 写入内容到文件
my_file.close()  # 关闭文件  必须关上!
# 疑问: 为什么必须关上?
# 好像不关上jypter也不会报错

```
* **路径疑问解答**：
    只写 `sample.txt` 代表**相对路径**，文件会直接创建在你当前运行这个 Jupyter 脚本的同一个文件夹里。
* **模式疑问解答**：
    除了常用的 `w` (覆盖写)、`a` (追加写) 和 `r` (只读)，未来你在处理 AI 图像或模型权重时，还会高频用到 **`rb` (读二进制文件)** 和 **`wb` (写二进制文件)**。

* **为什么必须关**：
    当你用 `open()` 时，操作系统会锁定这个文件，并**开辟一块内存“缓冲区”**。
    如果你不 `close()`，那就内存浪费了
* **为什么 Jupyter 不报错？**：
    因为 Python **有底层的“垃圾回收机制”**。Jupyter 溺爱新手，当它发现一个文件对象不用了，会在后台偷偷帮你关掉。
    但在真实的 AI 服务器环境中，如果你的循环里打开了成千上万个文件却不关，会直接导致操作系统“文件句柄耗尽”而死机崩溃。

 > [!NOTE] **🌟 现代 AI 推荐语法：上下文管理器 (强烈推荐)**
>每次都要手动写 `.close()` 既繁琐又容易忘。在现代 Python 开发中，我们几乎 100% 使用 **`with`** 关键字。当**代码运行离开缩进区域**时，Python 会**自动帮你关闭文件**！
>**现代写法：**
>```python
>with open("sample.txt", "w") as my_file:
(这里有缩进)my_file.write(text)
#只要跳出缩进，文件已自动安全关闭！
>```

#### 模块 3：追加模式 (`a`) 与创建规则

```python
append_text = "\nThis is an appended line.(追加文字)"
my_file = open("sample.txt", "a")  # 打开文件, 如果文件不存在, 会创建一个新文件
#  "a" 表示追加模式, 如果文件已经存在, 会在原有内容后追加新内容

# 疑问: 是不是不管什么模式,打开文件文件不存在就创建?
my_file.write(append_text)  # 写入内容到文件
my_file.close()

```

* **疑问解答 (不存在就创建？)**：
    **并不是所有模式都会自动创建！** 
    `w` (写) 和 `a` (追加) 模式下，如果文件不存在，系统会贴心地帮你创建一个空文件。
    **但是，在 `r` (读) 模式下，如果文件不存在，系统会直接报错** (`FileNotFoundError`)，因为它没东西可读。

#### 模块 4：读取文件与“指针”之谜

```python
my_file = open("sample.txt", "r")  # 打开文件, 如果文件不存在, 系统会报错
content = my_file.read()  # 读取文件内容
print(content)  # 打印文件内容

# 注意如果上面content的两句不注释掉,这里就读不出来东西,输出空数组
# 注释掉就能正常输出打印(我猜大概是指针的问题)
# 疑问:为什么会出现上面的问题?
# 输出类似['This is a sample text for testing the code.\n', 'It contains multiple lines.\n', 'This is the third line.\n', 'This is an appended line.(追加文字)']
# 你可以发现\n也被分到每行元素中(反正一行就是一个元素)

my_file.close()

```

```python
my_file = open("sample.txt", "r")  # 打开文件, 如果文件不存在, 系统会报错
content_lines = my_file.readlines()  # 读取文件内容, 按行存储到列表中
# 疑问: 此时content_lines应该是空的相当于一个列表?
print(content_lines)

# 输出类似['This is a sample text for testing the code.\n', 'It contains multiple lines.\n', 'This is the third line.\n', 'This is an appended line.(追加文字)']

my_file.close()
```

```python
my_file = open("sample.txt", "r")  # 打开文件, 如果文件不存在, 系统会报错
content = my_file.read()  # 读取文件内容
print(content)  # 打印文件内容

content_lines = my_file.readlines()  # 读取文件内容, 按行存储到列表中
print(content_lines)
# 注意如果上面content的两句不注释掉,这里就读不出来东西,输出空数组
# 注释掉就能正常输出打印(我猜大概是指针的问题)
# 疑问:为什么会出现上面的问题?

my_file.close()
```

* **解释**：
    `readlines()` 极其常用，它会把文件里的每一行变成列表（List）里的一个字符串元素，而且会老老实实地保留换行符 `\n`。
**⭐️疑问解答 (指针之谜)**：
    当你执行 `my_file.read()` 时，文件的“读取指针”会从文件头一路狂奔，读取所有字符，最后停在**文件最末尾**。
    如果你紧接着再去执行 `my_file.readlines()`，由于指针已经到了尽头，后面什么都没有了，所以它只能读出一个空列表 `[]`。
* **解决办法**：
    要么像你一样注释掉第一句；要么用 `my_file.seek(0)` 强行把指针重新拉回文件开头。
