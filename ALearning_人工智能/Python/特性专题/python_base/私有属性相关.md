___
#私有属性
___
在 Python 里，保护属性不被外部乱改的机制非常有意思。它没有那种绝对“锁死”的机制，而是通过**命名规则**来实现的，主要分为两个级别：“君子协议”和“障眼法”。

### 级别一：单下划线 `_` （君子协议）

如果你在一个属性名字前面加上**一个下划线**（比如 `self._age`），这在 Python 界是一个约定俗成的信号。

它等于在告诉其他写代码的人：“这是一个内部使用的属性，请你尽量不要在类的外部去读取或修改它。”

```python
class Person:
    def __init__(self):
        self._age = 18  # 单下划线，表示这是内部数据

p = Person()
# 强行访问或修改是可以成功的，但非常不推荐这种行为
print(p._age) 
p._age = 20

```

**注意**：Python 并不会真的去阻止你访问单下划线的属性，这全凭程序员的自觉。
<mark style="background: #FFF3A3A6;">相当于没用,这个只是约定俗成的命名规范</mark>
### 级别二：双下划线 `__` （障眼法，真正的私有属性）

如果你想用更强硬的手段保护属性，就在属性名前面加上**两个下划线**（比如 `self.__balance`）。

加上双下划线后，你在类的外部就**绝对无法直接通过这个名字**访问到它了。如果强行访问，Python 会直接报错，装作不认识这个属性。

#### 代码演示

我们拿“银行账户”来举例，账户余额（balance）肯定不能让外部随便改：
```python
class BankAccount:
    def __init__(self, name, balance):
        self.name = name          # 普通属性，外部可以随便看
        self.__balance = balance  # 双下划线属性，外部直接访问会报错

    # 类里面的方法，可以自由访问和修改双下划线属性
    def get_balance(self):
        return self.__balance

    # 如果外部想修改余额，必须通过我们提供的方法，这样我们就可以加入限制条件
    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            print(f"成功存入 {amount} 元。")
        else:
            print("错误：存入的金额必须大于 0！")

account = BankAccount("张三", 1000)

# 1. 访问普通属性
print(account.name)  # 成功输出: 张三

# 2. 强行访问私有属性（会报错）
# print(account.__balance) 
# 报错：AttributeError: 'BankAccount' object has no attribute '__balance'

# 3. 通过类提供的方法来访问和修改
print(account.get_balance())  # 成功输出: 1000
account.deposit(500)          # 成功输出: 成功存入 500 元。

```

### ⭐️ Python 的“障眼法”是怎么运作的？

为什么加了双下划线，外部就访问不到了呢？

其实，Python 并没有真正把这个属性“锁”进保险箱，而是偷偷**给它改了个名字**（这种机制叫 Name Mangling，名称改编）。
<mark style="background: #FF5582A6;">其实相当于, 内部把属性名定义成了`__balance`</mark>  ?
    并不是, 是 `_BankAccount__balance`
    当 Python 看到 `self.__balance` 时，它会在后台偷偷把这个属性重命名为 `_类名__属性名`（也就是 `_BankAccount__balance`）。
所以，当你在外部尝试访问 `account.__balance` 时，Python 去找这个名字，当然找不到，于是就报错了。
___
## 更优雅的做法
Python 确实提供了一个非常优雅的解决方案：**`@property` 装饰器**。

⭐️它的核心作用就是“伪装”：你可以像写函数一样去写各种保护逻辑，但在外部使用时，Python 允许你像访问普通属性一样，**不用加括号**就能直接读取或修改它。

### 如何使用 `@property`？

我们要完成两步：

1. **获取值（Getter）**：用 `@property` 装饰一个方法<mark style="background: #FF5582A6;">(应该说是属性)</mark>，让它变成只读属性。
2. **修改值（Setter）**：用 `@属性名.setter` 装饰另一个同名方法，让它负责处理赋值逻辑。

---

### 代码演示：优雅的银行账户

我们把上一节的 `BankAccount` 用 `@property` 重新包装一下：

```python
class BankAccount:
    def __init__(self, name, balance):
        self.name = name
        self.__balance = balance  # 依然是双下划线的私有属性

    # 第一步：把获取余额的方法，伪装成普通属性
    @property
    def balance(self):
        # 这里的函数名 balance，就是外部访问时的属性名
        return self.__balance

    # 第二步：把修改余额的方法，伪装成普通的赋值操作
    # 注意装饰器的名字必须是 @函数名.setter
    @balance.setter
    def balance(self, new_amount):
        # 这里可以加入各种严格的检查逻辑
        if new_amount >= 0:
            self.__balance = new_amount
        else:
            print("错误：余额不能被修改为负数！")

# --- 见证优雅的时刻 ---
account = BankAccount("张三", 1000)

# 1. 获取值：不需要写 account.balance()，直接像普通属性一样读取
print(account.balance)  # 输出: 1000

# 2. 修改值：不需要写 account.set_balance(1500)，直接用等号赋值
account.balance = 1500  
print(account.balance)  # 输出: 1500

# 3. 触发保护逻辑：当你尝试赋一个违规的值时，Setter 里的逻辑会拦住你
account.balance = -500  # 输出: 错误：余额不能被修改为负数！
print(account.balance)  # 余额依然安全，输出: 1500

```

### 拆解 `@property` 的精妙之处

* ⭐️**同名法则**：
    你会发现，**读取的方法和修改的方法，名字完全一样**（在这个例子里都叫 `def balance(self):`）。这在 Python 里是被允许的，因为 `@property` 和 `@balance.setter` 帮 Python 区分了它们各自的任务。
* **无缝升级**：这是 `@property` 最大的优势。假设你一开始写代码时很随意，直接用了普通属性 `account.balance`。后来你发现必须要加上防错逻辑（比如不能为负数）。
    如果不使用 `@property`，你就得把所有用到 `account.balance` 的代码都改成 `account.get_balance()`，这会让人崩溃。
    但有了 `@property`，外部调用的代码连一个字符都不用改，直接在类内部升级逻辑即可。
* ⭐️**只读属性**：如果你只写了 `@property`，没有写 `@balance.setter`，那么这个属性就是**只读**的。任何试图用等号给它赋值的行为，都会直接引发报错。这也是保护核心数据不被篡改的好方法。
