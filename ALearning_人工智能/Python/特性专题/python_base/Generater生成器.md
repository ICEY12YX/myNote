#Generater生成器

### 为什么输出的不是 `(2, 4, 6)`？

当你写下 `[x * 2 for x in [1, 2, 3]]`（列表推导式）时，Python 会像一个勤劳的工人，**立刻**把 2、4、6 算出来，然后塞进一个列表里交给你。这会立刻占用内存空间。

但是，当你用圆括号写下 `(x * 2 for x in [1, 2, 3])` 时，Python 并没有去做计算，而是**给了你一张“图纸”或一台“机器”**。
打印出来的 `<generator object at ...>` 就是在告诉你：“我是一台机器，我知道怎么算出这些数字（把传进来的数乘 2），但我现在还没开始算。”

### 怎么从生成器里把数据拿出来？

既然它是机器，你需要主动去“按开关”，它才会给你吐出数据。有三种最常用的方法：

#### ⭐️1. 用 `next()` 手动按开关（一次吐一个）

`next()` 函数就是生成器的启动开关。你按一次，它就算一次，吐出一个值，然后**停机等待**。

```python
my_gen = (x * 2 for x in [1, 2, 3])

print(next(my_gen))  # 输出: 2 （算出了 1*2，然后停下）
print(next(my_gen))  # 输出: 4 （算出了 2*2，然后停下）
print(next(my_gen))  # 输出: 6 （算出了 3*2，然后停下）

# 如果你再按一次，因为没有数据了，Python 会直接报错（StopIteration）
# print(next(my_gen)) 

```

#### 2. 用 `for` 循环自动按开关（最常用）

Python 的 `for` 循环非常聪明，==它遇到生成器时，会自动在后台不断地帮你调用 `next()`==，直到机器里没有原料为止。

```python
my_gen = (x * 2 for x in [1, 2, 3])

for num in my_gen:
    print(num)
# 自动输出: 2, 4, 6

```

#### 3. 强行打包成列表或元组

如果你不想一点点拿，就想一次性拿到所有成品，==可以强制把它塞进 `list()` 或 `tuple()` 里==，这等于强迫机器立刻满负荷运转，把所有产品做出来。

```python
my_gen = (x * 2 for x in [1, 2, 3])
my_list = list(my_gen)  
print(my_list)  # 输出: [2, 4, 6]

```

---

### 为什么要设计“生成器”这种东西？

你可能会想：这不就是脱裤子放屁吗？直接给我列表不好吗？

想象一个场景：你需要处理 **1 亿**个数字。

* **如果你用列表**：Python 会在瞬间把 1 亿个数字全部算出来，堆在内存里。你的电脑内存可能瞬间就被撑爆了，程序直接崩溃。
* **如果你用生成器**：
    Python 只在内存里保存了“乘 2”这个**计算规则**。无论你处理 3 个数字还是 1 亿个数字，==生成器本身占用的内存几乎都是**零**。==
    ⭐️你用 `next()` 要一个，它就在内存里算一个，算完交给你，就丢掉。

**所以，生成器是 Python 里对付海量数据、节省内存的超级神器。**

### ⚠️ 生成器的一个致命陷阱：阅后即焚

生成器里的数据是**一次性消耗品**。流水线上的东西吐出来就没有了，它不能像列表那样反复去读。

```python
my_gen = (x * 2 for x in [1, 2, 3])

print(list(my_gen))  # 第一次强行打包，输出: [2, 4, 6]
print(list(my_gen))  # 第二次再去打包，输出: [] （机器已经空了！）

```

如果你想再用一次，必须重新执行代码再造一台新机器。
