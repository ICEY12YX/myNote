在 C 语言中，程序必须先整体通过编译器的严格检查，生成可执行文件后才能运行。但 Python 的机制完全不同，它是一门**解释型语言**，用大白话说就是：**从上往下，边看边干**。
___
### Python 的实际执行步骤 - 基本执行顺序
#函数编译顺序 


```python
APPLE = 88  # 全局变量
def functionD(c):
    a = 10
    b = APPLE
    return a + b + c

c = 9
print(functionD(c))
```
以你提供的代码为例，当 Python 运行这个文件时，它的轨迹是这样的：

* **第一步：注册全局变量**
    执行 `APPLE = 88`。Python 在全局内存里腾出一块地方放 88，并贴上 `APPLE` 的标签。
* **第二步：扫描函数（但不执行）**
    遇到 `def functionD(c):`，Python 知道这里定义了一个函数。
    **核心重点来了：此时系统只负责把这个函数“打包登记”到内存中，绝对不会进去执行里面的任何代码！** 
    不执行代码, 但是会扫描一遍函数, **把局部变量位置留好**
        ⭐当 Python 看到 `def` 时，它会像一页页翻书一样，快速把函数内部的代码**扫读**一遍，只为了做一件事：**找等号 `=`**。 
        一旦它在函数体里扫到了 `APPLE = 99` 这个等号，它底层的 C 语言核心就会立刻触发规则：“既然你要在函数里给 `APPLE` 赋值，那 `APPLE` 就必须是这个函数的**局部变量**。” 于是，它把 `APPLE` 这个名字**登记**在了该函数的“局部变量花名册”上。
         _注意：此时它仅仅是登记了名字，绝对没有真正去执行赋值动作。_
* **第三步：继续注册全局变量**
    跳过函数体，系统继续往下读，执行 `c = 9`。在全局内存中存入 9，贴上标签 `c`。
* **第四步：调用并深入函数内部**
    遇到 `print(functionD(c))`。直到这一刻，Python 才真正“唤醒”并跳进 `functionD` 内部开始工作：
    1. 接收传入的参数 `c`（值为 9）。
    2. 执行 `a = 10`（生成局部变量）。
    3. 执行 `b = APPLE`。系统在函数内部找不到 `APPLE`，于是往外找，在第一步的全局内存中找到了 88。
    4. 计算 `return 10 + 88 + 9`，将结果 107 扔回给外面的世界。

* **第五步：打印结果**
外层的 `print()` 接收到返回值，将 107 打印到屏幕上。

---

⭐Python 是一种“随叫随到”的语言。对于**函数内部引用的外部变量**（如 `APPLE`），它不需要在 `def` 函数之前就严格声明。只要在**你真正调用这个函数的那一刻**，这个变量已经在前面的步骤（或者之前的内存记忆中）被定义好了，程序就能完美运行。

### 全局变量- 编译顺序
#全局变量 

#### 错误解释
```python
APPLE = 88  # 全局变量
def functionD():
    a = 10
    b = APPLE
    
    # APPLE = 99 
    # 疑问：为什么写这句会报错 local variable 'APPLE' referenced before assignment?
    # 意思是APPLE 被引用了 (在被赋值之前)
    return a + 10

```

 Python 的机制非常特殊，它有一条铁律：

* **⭐解密 Python 机制 (划重点)**：
    Python 的设计逻辑是：**只要你在函数内部对某个变量进行了“赋值操作”（写了等号），Python 就会在函数刚开始扫描时，强行把这个变量判定为“本函数的局部变量”**。
    (其实就是上面的 "扫描函数"的过程)


让我们还原一下报错时的“案发现场”：
0. 外层,`APPLE`被注册成全局变量
1. Python 开始扫描 `functionD`，它看到了 `APPLE = 99`。
     Python 心想：“哦！原来这个函数里有一个**局部变量**叫 `APPLE`，我记下了。”（此时它已经彻底无视了外面的全局变量 `APPLE = 88`）。
❗️ **注意**: 此时并不是覆盖, 而是有两个`APPLE`, 我们原意取外面那个, 但是py在局部建了一个,取了这个局部的(看下面具体解释)
2. 接着，函数开始正式执行。运行到 `b = APPLE` 这一行时，Python 试图去读取局部变量 `APPLE` 的值。
3. **惨案发生**：虽然 `APPLE` 被判定成了局部变量，但赋值操作 `APPLE = 99` 还在下一行呢！系统发现“局部变量 APPLE 还没被赋值呢，你怎么就先用起来了？”，于是立刻崩溃，抛出你看到的错误：`local variable 'APPLE' referenced before assignment`。

**具体解释:**
<mark style="background: #FF5582A6;">不是覆盖,是糊涂不知道取哪个</mark>
(因为py内部是c, 所以这部分可能类似c的入栈过程)
    在 Python 的内存管理中，全局变量和局部变量住在两个完全不同的“作用域（命名空间）”里。
        - **全局宇宙：** 最外层执行 `APPLE = 88` 时，全局空间里诞生了一个大老板叫 `APPLE`，它拥有 88 这个值。
        - **局部宇宙（函数内部）：** 当 Python 扫描 `functionD` 时，看到了 `APPLE = 99` 这行赋值代码。它的底层逻辑是：“既然你在函数里写了等号，我就强行把你判定为局部变量”。于是，Python 在这个局部宇宙里，**新建**了一个也叫 `APPLE` 的局部变量。

此时，内存里同时存在两个 `APPLE`。一个在外面（88），一个在里面（准备被赋值为 99）。

Python 有个“就近原则”铁律：**只要局部宇宙里登记了这个名字，那么在这个函数内部，所有的操作都只会对着这个局部变量发号施令，外面的全局变量会被彻底“屏蔽”无视掉。**

这就好比你们公司有个叫“张伟”的董事长（全局变量）。但是你们部门内部也新招了一个叫“张伟”的实习生（局部变量）。 在你们部门开会时（函数内部），老板喊一声“张伟去倒水”，肯定是实习生去倒，董事长的存在被“屏蔽”了。但他并没有被“覆盖”或开除，董事长依然在外面好好地当着他的董事长。

所以才会发生上面的惨案
___
#### 为什么加 `global` 就对了？

如果你要在函数内部修改全局变量，必须先写一句 `global APPLE` 声明一下。

```python
APPLE = 88

def functionD():
    global APPLE   # 第一步：举牌子声明
    a = 10
    b = APPLE      # 此时读取的是全局的 88
    APPLE = 99     # 此时修改的也是全局的 APPLE
    return a + 10
print(functionD())
```

`global APPLE` 就像是在函数最开头举起了一块牌子，明确告诉 Python 的扫描器：“**听好了，接下来无论你看到我对 `APPLE` 做了什么赋值操作，它都是外面那个全局变量，千万别把它当成局部变量！**”

有了这句声明，Python 就不再犯迷糊了，读取和修改的都会是外面的那个 `APPLE`。
