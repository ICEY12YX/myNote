#tuple元组
# 其他一些用法
元组（Tuple）和列表（List）确实非常像，你可以把元组看作是“被上了锁的列表”。

⭐️它们之间最大的区别只有一点：**元组是不可变的（Read-Only）**。一旦元组被创建，里面的元素就绝对不能被增加、删除或修改。

因为这个“不可变”的特性，元组的常用方法比列表少得多。
### 1. 和列表完全一样的操作（查找与切片）

所有**只读不写**的操作，元组和列表是完全一样的。

* **按位置取值**：`my_tuple[0]`，`my_tuple[-1]`
* **切片魔法**：`my_tuple[1:3]`，`my_tuple[::-1]`
* **找位置**：`my_tuple.index(值)` （找到这个值第一次出现的位置）
* **数个数**：`my_tuple.count(值)` （统计这个值出现了几次）

### 2. 元组“失去”的方法

因为元组不能被修改，所以你在列表里学过的那些带有破坏性或修改性质的方法，**元组统统没有**：

* 没有 `append()`, `insert()`, `extend()`（不能加）
* 没有 `pop()`, `remove()`, `clear()`（不能删）
* 没有修改元素的语法（`my_tuple[0] = 99` 会直接报错）
* 没有 `sort()`, `reverse()`（因为这会改变元素原来的位置。如果非要排序，只能用内置函数 `sorted(my_tuple)`，它会生成并返回一个新的**列表**）

### 3. 元组的独门绝技：解包（Unpacking）

#元组解包 
元组虽然没有自己独有的“内置方法”，但它在 Python 里有一种极其常用、非常帅气的专属语法，叫作**解包**。

顾名思义，解包就是把元组里的包裹拆开，把里面的元素直接一口气分给几个变量。

#### 基础解包

如果你有一个包含 3 个元素的元组，你可以直接用 3 个变量把它们“接住”：

```python
# 创建一个元组
my_tuple = (10, 20, 30)

# 魔法开始：直接解包赋值
a, b, c = my_tuple

print(a)  # 输出: 10
print(b)  # 输出: 20
print(c)  # 输出: 30

```

⭐️*注意：左边变量的数量，必须和右边元组里的元素数量一模一样。*

#### 神奇的变量交换

在其他语言里，想要交换两个变量的值，通常需要引入第三个临时变量（比如 `temp = a; a = b; b = temp`）。
但在 Python 里，借助元组的解包机制，一行代码就能搞定：
```python
x = 1
y = 99

# 直接交换 x 和 y 的值
x, y = y, x

print(x)  # 输出: 99
print(y)  # 输出: 1

```

*(在执行 `y, x` 时，Python 实际上在后台悄悄打包了一个元组 `(99, 1)`，然后立马解包分别赋给了 `x` 和 `y`)*
<mark style="background: #FF5582A6;">( 所以x, y这种写法本质是元组 )</mark>

### 一、 元组的常见处理方式

#### 1. 拼接与重复（生成新元组）

虽然你不能修改原来的元组，但你可以用加号 `+` 和乘号 `*` 把它们组合成一个**全新的元组**。

```python
t1 = (1, 2)
t2 = (3, 4)

# 拼接：生成一个全新的元组
t3 = t1 + t2
print(t3)  # 输出: (1, 2, 3, 4)

# 重复：把元素复制几份，也是生成新元组
t4 = t1 * 3
print(t4)  # 输出: (1, 2, 1, 2, 1, 2)

```

#### 2. 遍历读取

就是用for...in循环

#### 3. “曲线救国”：转换成列表再修改

如果你非要修改一个元组怎么办？标准的做法是：**先变成列表，改完，再变回元组。**

```python
t = (1, 2, 3)
# 1. 变成列表
temp_list = list(t)
# 2. 随意修改
temp_list.append(4)
# 3. 变回元组
t = tuple(temp_list)
print(t)  # 输出: (1, 2, 3, 4)

```

### 二、 元组有推导式吗？（一个巧妙的陷阱）

这是一个非常好的问题！很多初学者觉得：既然列表推导式用中括号 `[]`，那元组推导式肯定就是用圆括号 `()` 咯？

**答案是：Python 里没有真正的“元组推导式”。**

如果你用圆括号写了一个类似推导式的东西，Python **不会**直接给你一个元组，而是会给你一个叫作生成器（Generator）的神奇对象。

```python
# 看起来像元组推导式
my_gen = (x * 2 for x in [1, 2, 3])

print(my_gen)  
# 输出的不是 (2, 4, 6)，而是一长串奇怪的名字：<generator object <genexpr> at ...>

```

- **为什么会这样？**
    你可以把列表推导式理解为“一次性把所有菜做出来端上桌”**。
    而加上圆括号的生成器，则是一个**“按需生产的流水线”。它不会立刻计算出所有结果，而是你向它要一个，它才算一个（这在处理几百万个数据时非常节省内存）。
#Generater生成器 [[Generater生成器]]


- **怎么用推导式得到真正的元组？**
    很简单，在生成器外面套一层 `tuple()` 强制转换一下，让流水线立刻开工并打包：

```python
my_tuple = tuple(x * 2 for x in [1, 2, 3])
print(my_tuple)  # 输出: (2, 4, 6)

```

### 三、 什么场景下会想到用元组？

既然列表那么好用，为什么 Python 还要设计元组？当你遇到以下三种场景时，请毫不犹豫地使用元组：

#### ⭐️场景 1：函数返回多个值（Python 的默认潜规则）

当你写一个函数，想同时返回好几个结果时，直接用逗号隔开就行。Python 会**自动**把它们打包成一个元组返回。

```python
def get_user_info():
    name = "张三"
    age = 18
    # 看起来返回了两个值，实际上 Python 自动打包成了元组 (name, age)
    return name, age 

# 利用前面学过的“解包”，完美接住返回值
user_name, user_age = get_user_info()

```

#### ⭐️ 场景 2：充当字典的键（Key）

❗️ 字典的规则是：**作为查找标签（Key）的东西，绝对不能被改变。**
列表是可变的，所以不能当字典的标签；而元组是上了锁的，所以可以。比如表示地图上的坐标：

```python
# 用 (经度, 纬度) 这个元组作为字典的标签
locations = {
    (116.4, 39.9): "北京",
    (121.4, 31.2): "上海"
}

```
