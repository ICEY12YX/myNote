# Multiple linear regression
## multiple features

#multiple_linear_regression 多元线性回归（多特征线性回归） 
    就是开始考察多个维度的输入对输出的影响
    用大白话来说，以前的线性回归只能靠“房子面积”这一个指标来猜房价；而多元线性回归就是允许我们同时参考“面积、卧室数、楼层数、房龄”等好几个不同指标（即多个特征），把每个指标乘上各自的权重再加起来，从而更准地预测结果

#vector 向量 
    在数学和写代码里，向量其实就是“排成一排（或一列）的一串数字列表”，比如把一套房子的四个特征数字打包放在一起，或者把模型的四个权重参数打包放在一起，就叫一个向量，常在字母头上画个小箭头（如 $\vec{w}$、$\vec{x}$）来表示

#dot_product 点积（内积）
    线性代数里两个向量之间的一种极简运算，用一个小圆点 $\cdot$ 表示（如 $\vec{w} \cdot \vec{x}$）；
    算起来就是把两串数字里位置对应的数两两相乘，然后再全部加起来（即 $w_1 x_1 + w_2 x_2 + \dots + w_n x_n$）

认识一下符号
- **特征下标 $x_j$**：

    - 用带下标的 $x_j$（读作 $x$ sub $j$）来表示第 $j$ 个特征

- **定位具体某一个特征值 $x_j^{(i)}$**：
    - 如果指代“第 $i$ 个训练样本里的第 $j$ 个特征”，我们就同时写上标 $i$ 和下标 $j$，即 $x_j^{(i)}$。

## vectorization

#vectorization 向量化 
    数学上, 就是把公式像上节课那样简化的写
    代码上, 用大白话来说，向量化就是在写代码时，不要自己用 `for` 循环或者手敲加号把数字一个个乘起来再相加，而是直接把整串数字（向量）打包交给数学库（如 NumPy），让电脑底层的并行硬件（CPU 或 GPU）一口气同时把所有乘法和加法算完——这样写出来的代码不仅只有短短一行，而且跑起来快得飞起。

向量化的好处
- 代码变得更短
- 运行得快 (利用numpy或其他库)
    numpy内部通过直接调用 **GPU** 硬件来并行计算处理, 大幅加速代码运行

代码里怎么实现 向量化    ---- 其实就是讲np语法

- **定义**：
    - 在 Python 代码里，我们用 **NumPy** 数组（array）来定义这些变量，例如：`w = np.array([1.0, 2.5, -3.3])`
- 模型怎么用代码实现
    - 不使用向量化, 纯手敲硬算
        如果特征数量 $n$ 不是 $3$，而是 $100$ 甚至 $100,000$（十万），那你手敲代码会累死，而且电脑算起来效率也极其低下。
    - 不使用向量化——使用 `for` 循环
        电脑跑起来慢
    - 借助numpy实现 向量化  用np.dot函数
![[01-1793384587056.webp]]

**在机器学习里养成“条件反射”**：以后只要在数学公式里看到求和号 $\sum w_j x_j$ 或两个向量相乘，写 Python 代码时**永远优先想能不能用 `np.dot` 代替 `for` 循环**

看一下np内部怎么处理的, 运行的为什么这么快

#parallel_processing 并行处理（并行计算） 
    用大白话来说，“不向量化的 `for` 循环”就像超市只有一个收银员，16 件商品必须排着队一件接一件慢慢扫码（串行计算）；而“向量化的并行处理”就像超市一下子开了 16 个收银台，16 件商品在同一秒钟“唰”地一下同时扫完，再用专门的高速硬件一瞬间把总价加出来——这就是向量化能像变魔术一样快出几十上百倍的底层秘密。
    类似neon 应该

同样的算法，不向量化的版本和向量化的版本跑起来速度差距巨大，这背后靠的是计算机底层硬件的执行方式差异

左图
不向量化的 `for` 循环（排队一步步算）

右图
硬件一口气同时算
- 计算机一次性拿到向量 $\vec{w}$ 和 $\vec{x}$ 的全部数值，在同一个时间步（in a single step）里，把每一对 $w$ 和 $x$（从 `w[0]*x[0]` 到 `w[15]*x[15]`）**全部同时并行相乘（all at the same time in parallel）**。
- 计算机拿起乘出来的这 $16$ 个数字，动用专门的硬件（specialized hardware）非常高效地把它们一下子全加在一起，完全不需要像前面那样分 $16$ 次挨个相加。
![[01-1793440886921.webp]]

问题假设
有 $16$ 个特征，对应 $16$ 个权重参数 $w_1$ 到 $w_{16}$（这里为了演示简单，先暂时忽略参数 $b$）。
假设已经算出了这 $16$ 个权重的导数项（derivative terms）$d_1$ 到 $d_{16}$
现在你要按梯度下降公式更新这 $16$ 个参数（假设学习率 $\alpha = 0.1$）
$$w_j = w_j - 0.1 d_j \quad (j = 1, \dots, 16)$$
左图
不使用向量化的写法

右图 向量化
在底层并行处理硬件中，
    计算机会一次性抓起向量 `w` 里的全部 $16$ 个值，**并行地（in parallel）** 减去 $0.1$ 乘以向量 `d` 里的全部 $16$ 个值，并在**同一步里同时**把算好的 $16$ 个新结果重新赋值回 `w`。
    代码也就一行
所以就是并行乘, 并行减, 赋值回去
![[01-1793441090823.webp]]
**速度差距有多大**：如果只有 $16$ 个特征，速度差别可能还不算太明显；但如果你有**几千个特征**以及**非常庞大的训练集**，向量化带来的运行时间差异将是天壤之别——它直接决定了你的代码是**一两分钟就跑完**，还是得**干等好几个小时**！

💡 **避坑/重难点补充**：
1. **向量化不只是 `np.dot`**：上一节我们学了用 `np.dot(w, x)` 把“相乘再累加”向量化；而这一节的 `w = w - 0.1 * d` 展示了 NumPy 数组的==**逐元素运算（Element-wise Operation）**==。只要 `w` 和 `d` 是长度相同的 NumPy 数组，直接写 `w - 0.1 * d`，NumPy 就会自动在底层把 `d` 的每个元素乘上 `0.1`，再和 `w` 对应位置的元素相减，最终返回的依然是一个打包好的新数组 `w`！

#normal_equation 正规方程
梯度下降是找最优 $\vec{w}$ 和 $b$ 的绝佳方法，但在线性回归中，其实还存在另外一种不需要迭代的数学方法, 即正规方程
    它能借助高级线性代数库，无需循环迭代，直接**一步到位（all in one go）** 解出最优的 $\vec{w}$ 和 $b$。
缺点:
- **无法推广到其他算法**：不像梯度下降哪里都能用，正规方程**只能用于线性回归**，完全没法迁移到逻辑回归（logistic regression）、神经网络（neural networks）或本专项课程后面的任何其他算法中。
- **特征多时非常慢**：当特征数量 $n$ 很大（比如上万个特征）时，正规方程的计算速度会变得非常慢。
![[01-1793442402055.webp]]
其他你可能要知道的:
- 几乎没有机器学习从业者会自己手写实现正规方程；但如果你调用成熟的机器学习库（如 scikit-learn）里的线性回归接口，它在后台（backend）有可能会直接用正规方程来帮你解出 $\vec{w}$ 和 $b$。

一步到位大概是怎么做的?
    直接令所有参数的偏导数等于 0，然后直接解出方程组的封闭解（Closed-form solution）。

# Gradient descent in practice
## feature scaling

#feature_scaling 特征缩放 
    用大白话来说，如果不同特征的输入值大小差太多（比如“房子面积”动辄上千平方英尺，而“卧室数”只有 0 到 5 间），就会把代价函数 $J$ 的等高线挤压成又高又瘦的细长椭圆，害得梯度下降在窄胡同里来回弹跳、走得巨慢无比；
    而“特征缩放”就是把所有特征都按比例缩放到差不多的大小范围（比如统统变到 $0$ 到 $1$ 之间），把等高线重新揉圆，让梯度下降能走一条笔直的捷径飞快冲到谷底。

问题假设
设定两个范围悬殊的特征:
- $x_1$（房子面积 size of the house）：取值范围通常在 $300$ 到 $2000$ 平方英尺之间（**数值范围很大**）。
- $x_2$（卧室数量 number of bedrooms）：取值范围在 $0$ 到 $5$ 间之间（**数值范围很小**）。
真实输出是500k
这个时候参数是什么比较合理?  

先随便带数字进去
**❌ 第一种参数猜想（大特征配大权重：$w_1 = 50, w_2 = 0.1$）**：
    明显最终得到的数字过于大了
**✅ 第二种参数猜想（大特征配小权重、小特征配大权重）**：
    房价刚好是 $50$ 万美元（$500,000$ 美元），跟真实房价一模一样，是一组合理得多的参数！
总结
    当某个特征 $x_i$ 的可能取值范围**很大**（如面积高达 $2000$）时，一个好模型学出来的对应参数 $w$ 往往会**比较小**
    反过来，当某个特征 $x_i$ 的可能取值范围**很小**（如卧室数只有几间）时，合理的对应参数 $w$ 往往会**比较大**（如 $50$）。
![[01-1793444136891.webp]]

上面看起来像是废话
但是反应出一些问题

左边 -- 原始训练数据的散点图
右边 -- 代价函数 $J$ 的等高线图
    细长椭圆
首先图看上去就 "不咋好看"
![[01-1793446725853.webp]]
因为等高线又高又瘦，梯度下降很可能就会就会在狭窄的椭圆壁之间**来回折返弹跳（bouncing back and forth）好长一段时间**，要绕很久的弯路才能极其缓慢地挪到全局最低点（global minimum）。

怎么办呢  #feature_scaling 做缩放
    把原本范围天差地别的特征，统一缩放到**彼此相当的数值范围**
    比如让缩放后的 $x_1$ 范围变成 $0$ 到 $1$，同时让 $x_2$ 的范围也变成 $0$ 到 $1$。
- **数据散点图变匀称**
- **代价函数等高线变回“正圆”**
- **梯度下降效果更好**
    找到一条**笔直得多**的 到圆心的捷径
![[01-1793447160490.webp]]

💡为什么梯度下降会在“细长椭圆”里来回折返弹跳？
    在微积分和几何上，梯度（导数）的方向永远是**垂直于等高线切线**的（即指向当前位置最陡的下坡方向）。
    当等高线是个正圆时，垂直于圆周的方向正好直指圆心（最低点）；
    但当等高线是个极扁的细长椭圆时，垂直于椭圆长边的方向指向的是“对面椭圆壁”而不是“椭圆中心”，所以梯度下降才会在两面墙之间疯狂走“之”字形（Zig-Zag）来回弹跳！

💡这样缩放以后,学出来的参数会发生变化（比如房子面积缩小了 1000 倍，学出来的权重 w1​ 就会自动放大 1000倍来抵消）
但是只会带来数值上的变化而已, 不会说这个放大1000倍的参数就是错的
    然后因为缩放过了, 最后输出的时候需要缩放回来,得到真实值
    这个应该就是训练前对数据进行 #normalization 归一化

#mean_normalization 均值归一化 
    用大白话来说，就是把特征数据先减去它的平均值（让数据不再全部大于 $0$，而是以 $0$ 为中心有正有负地对称分布），然后再除以“最大值减最小值”的跨度，从而把所有特征都整齐地压缩到大约 $-1$ 到 $+1$ 之间的范围里。

 #z_score_normalization Z-score 标准化（标准差归一化） 
     机器学习里最常用的一种特征缩放方法：先拿每个特征减去它的平均值 $\mu$（让中心对齐到 $0$），再除以它的标准差 $\sigma$（衡量数据有多分散的指标），最终让所有特征的数值范围都落在 $0$ 附近（差不多在 $-3$ 到 $+3$ 之间）。
就是这个 $$x' = \frac{x - \mu}{\sigma}$$
特征缩放方法一：直接除以最大值
把最大值控制在1

什么时候缩放?
一般来说, 目标是让每个特征 $x$ 的范围大约落在 **$-1$ 到 $+1$ 附近**。
标准也可以放宽松, 在 $-3$ 到 $+3$，或者 $-0.3$ 到 $+0.3$ 之间，全都完全没问题（completely okay）。
像下面有些例子可以不缩放, 有些必须缩放
    最后一个, 跨度不大但基准值很大, 也需要缩放
        虽然最大值和最小值差得不多，但它的数值本身在 $100$ 左右，跟其他已经缩放过的特征比起来依然太大了，会导致梯度下降变慢，所以这种情况做特征缩放也很有帮助。

## checking gradient descent for convergence
如何判断梯度下降是否在正常工作并成功收敛？

判断收敛 #converge 
    找到代价函数的 #global_minimum 了吗

方法一（最推荐）：画“学习曲线”肉眼观察 #learning_curve
    **横轴是梯度下降已经运行的迭代次数（number of iterations）**，纵轴是代价 $J(\vec{w}, b)$。
    （注：机器学习里其实有好几种不同类型的学习曲线，课程后面还会见到其他类型）
正常工作时:
    每经过一次迭代，代价 $J$ 都应该减小
判断收敛:
    看线到后面有没有区域平坦
异常:
    某次迭代后代价 $J$ 反而增加了，那就说明**要么是学习率 $\alpha$ 选得不好（通常意味着 $\alpha$ 设得太大了），要么是你的代码里有 Bug**。
![[01-1793451066326.webp]]
- 梯度下降收敛所需的迭代次数在不同应用场景下差异极大：有的应用可能跑 $30$ 次迭代就收敛了，而另一个应用可能需要 $1,000$ 次甚至 $100,000$ 次（十万次）迭代。
- 因为事前很难预知到底需要跑多少步才能收敛，所以画这样一张学习曲线图，就能非常直观地帮你看出什么时候模型差不多训练好了。

方法二：自动收敛测试
- 引入希腊字母 $\epsilon$（读作 epsilon），让 $\epsilon$ 代表一个非常小的数字，比如 $0.001$（即 $10^{-3}$）。
- 如果在某一次迭代中，**代价 $J(\vec{w}, b)$ 减少的量小于这个极小数 $\epsilon$**，那就说明你很可能已经走到了左边曲线变平的那一段，此时程序就可以直接**宣布收敛**
![[01-1793451715494.webp]]
- 在实际操作中，**想要挑出一个刚巧合适的阈值 $\epsilon$ 其实相当困难**。
    如果 $\epsilon$ 设得稍微大了一点，当梯度下降遇到坡度比较平缓的地方（还没到谷底，只是走得慢了），算法就会误以为已经到底而**提前停工（欠拟合）**；
    如果设得太小，又可能在谷底耗费大量无意义的算力
- 因此，比起依赖自动收敛测试，老师自己平时更倾向于直接看左边这样的**学习曲线图**
而且看图还有一个额外好处 —— 万一梯度下降跑得不对劲，图像能提前给你发出非常直观的预警。

## choosing the learning rate

通过观察上一节学的 #learning_curve 的异常 , 可以判断此时需不需要调整 #learning_rate 

异常现象一：代价 $J$ 忽高忽低（上下震荡）
要么是**代码里有 Bug**，要么是你的**学习率 $\alpha$ 设得太大了**。
    看代价函数图可以知道, **学习率 $\alpha$**  太大了, 步子迈太大了
    换小点的学习率就好了

异常现象二：代价 $J$ 持续单调上升 
也可能是学习率太大  
或者代码bug
    比如在写代码更新 $w_1$ 时，不小心把减号写成了**加号**
![[01-1793452132071.webp]]
调试技巧
因为
    只要梯度下降的代码实现是正确的，那么**当学习率 $\alpha$ 足够小时，代价函数 $J$ 在每一次迭代后都必须减小**
所以如果发现梯度下降不工作，可以这样排查
    **先把 $\alpha$ 设成一个极其微小的数字**，然后看代价 $J$ 会不会在每次迭代时都老老实实下降。
    如果把 $\alpha$ 设得非常非常小，$J$ 依然没有在每一步都下降（甚至有时候还会上升），那就基本坐实了**你的代码里肯定某个地方有 Bug**
        把 $\alpha$ 设得极小**纯粹是为了排查 Bug**，在实际训练模型时，极小的 $\alpha$ 绝不是最高效的选择，因为学习率太小，梯度下降收敛速度可能极其缓慢。

老师一般这么做
**每次约放大 3 倍的尝试序列**：
- 可以先从 $0.001$ 开始试；接着把它放大 $3$ 倍试试 $0.003$；然后再放大约 $3$ 倍试试 $0.01$（它正好是 $0.001$ 的 $10$ 倍）；接着继续按大约每次放大 $3$ 倍的节奏往上试
**怎么挑出最终赢家:**
- 对于每一个候选的 $\alpha$，只需要先让梯度下降**跑寥寥几次迭代**，并画出代价 $J$ 随迭代次数变化的学习曲线。
- 一路试下去，直到找到了一个**太大的值**（开始震荡或发散）。
- 最后，挑那个能让代价 $J$ **既快速、又持续稳定下降**的值——通常就是挑**你能找到的最大合理学习率，或者比那个最大合理值稍微小一点点的数**，这往往就是最适合你模型的黄金学习率！
![[01-1793452535207.webp]]

💡**做完特征缩放后，$\alpha$ 往往可以设得更大**：
    结合前两节课的内容，如果你没做特征缩放，等高线是极窄的细长椭圆，$\alpha$ 稍微大一点就会撞墙发散；
    而做好特征缩放把等高线揉圆之后，你会发现原本会发散的较大 $\alpha$（比如 $0.1$ 或 $0.3$）现在也能稳稳当当地极速收敛了！

## feature engineering

#feature_engineering 特征工程 
    用大白话来说，就是别只会傻乎乎地拿原始给你的数据直接喂给模型，而是利用你对实际问题的常识和直觉，把原来的特征**变换或者组合**一下，造出更有用的“新特征”，从而帮机器学习算法更容易、更准确地做出预测。
    （比如把土地的“宽 $x_1$”和“深 $x_2$”乘起来，自己造出第 3 个特征“面积 $x_3 = x_1 x_2$”）

- $x_2$：土地的**深度/纵深（depth of the lot）**。
直接用上面2个原始特征建模型, 不够高效其实

## polynomial regression

#polynomial_regression 多项式回归 
    用大白话来说，就是把上一节学的“特征工程”和“多元线性回归”合体：
    当我们发现一条直线的线性回归根本拟合不好弯曲的数据点时，直接把原来的特征 $x$ 拿来求平方（$x^2$）、求立方（$x^3$）甚至开根号（$\sqrt{x}$），把算出来的这些高次方当成新的特征喂给多元线性回归——这样就能用原本只能画直线的算法，轻松画出各种弯曲的非线性曲线（non-linear functions）来贴合数据！

到目前为止，我们一直只用直线（straight lines）去拟合数据。
假设你有下面这样的数据, 明显曲线更拟合这个趋势

尝试一：二次函数  引入 $x^2$
    仔细想一下你会觉得二次模型不太合理——因为开口向下的二次抛物线到了右边**最终会往下掉（eventually comes back down）**；而在现实中，我们显然不会认为房子面积越大、房价反而越便宜（大房子通常应该更贵才对）。

尝试二：三次函数 引入 $x^3$
    曲线后面会**往上翘**, 所以选择带三次的更好
![[01-1793455878792.webp]]
顺带一提, 此时特征缩放变得空前重要
    高次幂会把数值范围拉开
$x^2$ 和 $x^3$ 的取值范围与原始特征 $x$ 相差了整整好几个数量级；因此如果你用梯度下降来训练多项式回归，**必须先做特征缩放**，把这些特征统统拉回到彼此相当的数值范围里

尝试三：三次函数 引入 $\sqrt{x}$
原因
    观察 $\sqrt{x}$ 的函数图像，随着 $x$ 增大，曲线会变得**越来越平缓（a bit less steep）**，但它**永远不会彻底变成水平线**，更**绝对不会像二次抛物线那样往下掉**——这同样是非常契合这份房价数据集的一种特征选择。

后面会学关于特征的评估流程, 科学地帮你拍板决定该保留哪些特征。
现阶段，你只需要意识到：**自己完全有权利自由选择使用什么特征**
![[01-1793457228777.webp]]

💡**多项式回归为什么不用改梯度下降的代码？**
    很多同学看到模型里出现了 $x^2, x^3, \sqrt{x}$，就担心求导公式是不是全变了？完全没变！
    在代码里，你只需要在跑梯度下降之前，先拿原始数据列 `x` 算出新列 `x_squared = x**2` 和 `x_cubed = x**3`，把它们拼成普通输入矩阵 `X = [x, x^2, x^3]` 
    就是把`x**2` 看成新的维度的数据(比如x下标2) ,那么对于权重 $w_1, w_2, w_3$ 来说，它依然是一个标准的**多元线性回归**！
