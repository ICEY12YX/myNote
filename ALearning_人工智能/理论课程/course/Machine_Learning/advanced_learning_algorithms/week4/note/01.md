# decision trees
## decision tree model

#decision_trees 决策树 
    决策树就是一种长相酷似“分叉流程图”的机器学习模型：当你拿来一个新样本（比如一只未知的小动物），模型会从最顶上的第一个问题开始，像查户口一样层层追问它的特征（比如“耳朵是尖的还是垂的？” $\rightarrow$ “脸是圆的吗？”），根据回答顺着箭头往左或往右走，直到走到最底下的终点框里，直接给出最终预测结果（“是猫”或“不是猫”）。
尽管它在高校学术论文里不像神经网络那么受追捧，但在工业界实战和各大机器学习竞赛（如 Kaggle）中，决策树以及由多棵树组成的“树集成模型（tree ensembles）”却是当之无愧的夺冠大杀器！

#categorical_values #categorical_features 类别型特征（离散特征） 
    指那些取值不是连续数字，而是只能在屈指可数的几个固定选项\里挑一个的特征。
    比如这节课里动物的耳朵形状只能是“尖耳”或“垂耳”，胡须只能是“有”或“无”，这种非此即彼或只有几个固定档位的特征就叫类别型特征。

#root_node #decision_nodes #leaf_nodes 根节点、决策节点与叶节点 

* **决策节点（Decision Nodes）**：树中间所有的椭圆形节点（包含根节点在内），它们负责察看某一个具体特征，并根据特征的取值决定让你往左分叉走还是往右分叉走；

* **叶节点（Leaf Nodes）**：位于整棵树最底部的那些长方形方框，走到这里就不再往下分叉提问了，直接拍板给出最终的预测结论（比如预测是猫还是狗）。

问题假设
希望能根据动物的几项外观特征，训练出一个分类器，帮你快速判断送来的动物到底是不是猫
 这里有一份包含 $10$ 个训练样本的数据集（里面正好有 $5$ 只猫和 $5$ 只狗）
-  **输入特征 $X$（前 3 列）**：分别记录了每只动物的 **耳朵形状**、**脸型** 以及 **是否有胡须**。
- **目标输出标签 $Y$（最后 1 列）**：是猫记为 $1$，不是猫记为 $0$
因此这是一个标准的 **二分类任务**

## learning process

#purity #impurity 纯度与不纯度 
    给一堆混在一起的猫狗样本做分类时，“纯度（purity）”衡量的就是一个集合里的动物到底有多“清一色”：
        如果切分出来的小组里 **100% 全是猫**（或者 **100% 全是狗**），没有半点掺杂，那这个节点就叫 **完全纯净（completely pure，不纯度为 0）**；
        反过来，如果猫和狗五五开混成一锅粥，那就是 **不纯度（impurity）极高**。
    决策树在每一个分叉口挑特征提问时，==核心目标就是想尽办法 **让切分出来的左右两边尽可能“纯”（最大化纯度 / 最小化不纯度）**！==

#depth #maximum_depth 节点的深度与最大深度 
    一个节点的“深度（depth）”指的就是 **从最顶上的根节点走到这个节点需要跳几步（number of hops）**：
        最顶端的根节点原地不动（$0$ 步），所以处于 **第 0 层（Depth 0）**；往下一层跳 $1$ 步是 **Depth 1**；再往下一层跳 $2$ 步是 **Depth 2**。


一般搭建决策树的步骤
    就是觉得每层每个节点 判断哪个特征

所以就可以挂上叶子结束了

每个节点到底该选哪个特征来切分
- **核心挑选原则——最大化纯度（Maximize Purity）**
    也就是希望切分出来的子集 **尽可能接近“清一色全是猫”或“清一色全是狗”**。

打个比方，假如我们手里有一个特征叫 **“这只动物是否有猫的 DNA”**（虽然实际上并没有这个特征）。
    如果在根节点用它切分，左分支就会得到 **5/5 全是猫**，右分支得到 **0/5 是猫**。左右两个数据子集都达到了 **完全纯净**，那它无疑是个绝佳的切分特征。
![[01-1794262731970.webp]]
上面分别对三个特征进行决策  分出来两边两类的比例各有不同
    决策树学习算法必须在这三者中挑出能让左右子分支标签纯度最高的那一个；因为一旦得到了高度纯净的样本子集，你直接预测“是猫”或“不是猫”就能把绝大多数样本猜对。
    进一步决策还能减少步骤

什么时候该停手不再往下切分?
1. **标准一：当节点已经达到 100% 纯净时**
    直到某个节点里的样本 **100% 全是猫，或者 100% 全是狗（不是猫）** 时停止切分，顺理成章地建一个叶节点给出分类预测。

2. **标准二：当继续切分会导致树超过设定的“最大深度（Maximum Depth）”时**
    你可以人为设定一个允许树生长的 **最大深度** 参数；一旦再往下切分就会超出这个最大深度，算法就停止切分。
    1. 为了确保决策树不会长得 过于庞大笨重
    2. 还可以让过拟合不容易发生
        和 #regression 问题  模型公式太复杂一个道理

注意
    ==根节点走到自己需要 $0$ 跳，所以处于 **Depth 0**；==
    它正下方一层的节点处于 **Depth 1**，再往下一层的节点处于 **Depth 2**。


3. **标准三：当切分带来的“纯度提升幅度”低于某个阈值时**
    如后面的视频所示，如果切分某个节点带来的纯度提升微乎其微（或者更准确地说，不纯度的下降量低于某个阈值，再往下分收益太小），那可能就懒得再切了
        ——目的同样是为了保持树更小，并降低过拟合风险。


4. **标准四：当节点里的“样本数量”低于某个阈值时**
    如果落到某个节点的样本数少于设定的阈值，也可以决定停止切分。

## measuring purity

#entropy 熵（信息熵 / 不纯度指标） 
    “熵（记作 $H(p_1)$）”就是决策树里专门用来给一堆样本的 **“混乱掺杂程度（不纯度 impurity）”打分的尺子**：
        分数最低是 **$0$ 分**（代表这堆样本里清一色全是猫、或者清一色全是狗，一点杂质都没有，==纯度最高==）；
        分数最高是 **$1$ 分**（代表猫和狗正好五五开各占一半，最混杂、最难猜，不纯度封顶）；
        如果猫狗比例介于全纯和五五开之间（比如 5 猫 1 狗），算出来的熵就会落在 $0$ 到 $1$ 之间——越靠近五五开，熵就越接近 $1$。

#gini_criteria 基尼准则（基尼不纯度） 
    在开源机器学习工具包（如 Scikit-learn）里经常看到的==另一种==衡量节点“不纯度”的打分函数。
    它的函数曲线长相和作用跟“熵（Entropy）”几乎一模一样（也是在全纯时为 $0$，五五开时冲到最高点再回落到 $0$），用来建决策树的效果同样很好。

基尼准则（Gini Criteria）：
    除了熵之外，还有其他同样遵循“从 $0$ 升上去再降回 $0$”规律的函数；比如你以后用开源工具包时，可能会听到一个叫 **基尼准则（Gini criteria）** 的指标，它的曲线长相跟熵函数非常相似，用来构建决策树效果也很好。

💡 **避坑**：
 **写 Python 作业代码时（如何优雅避开 `log2(0)` 报错）**：
    虽然数学上我们口头约定 $0 \log_2(0) = 0$，但在 Python 编程作业里，如果你直接对 $p_1 = 0$ 或 $p_1 = 1$ 调用 `np.log2(p1)`，NumPy 会立刻算出 `-inf`（负无穷），再乘以 `0` 就会吐出致命的 `nan`（Not a Number）导致整个函数报错！
    所以在写 `compute_entropy(y)` 函数时，一定要先加一句判断：**如果 `p1 == 0` 或 `p1 == 1`，直接 `return 0`**，只有当 $0 < p_1 < 1$ 时才去跑那条对数公式！

## choosing a split: Information Gain  

#information_gain 信息增益 
    “ 信息增益”就是 **切分前后的“熵（混乱度）下降了多少”**。
    比如切分前一个节点里猫狗五五开，混乱度（熵）高达 $1$；如果你挑了一个好特征把样本一分为二，切完后左右两边的加权平均混乱度降到了 $0.72$，那么混乱度一共减少了 $1 - 0.72 = 0.28$
    ——这个减少的量 $0.28$ 就叫 **信息增益**！决策树在每个节点挑特征时，规则极其简单粗暴：**把所有候选特征的信息增益都算一遍，谁的信息增益最大（也就是谁把混乱度砍下去最多），就选谁来切分**！

#weighted_average_entropy 加权平均熵 
    当一个节点切分成左、右两个子分支后，左边有一个熵，右边也有一个熵，怎么把这==两个数合成一个总分来评价这次切分好不好==呢？
    不能简单把两个熵加起来除以 $2$，而要按 **“左右两边各自分到了多少样本（权重 $w^{\text{left}}, w^{\text{right}}$）”** 来算加权平均
    ——因为如果某个分支里装了绝大多数样本却依然乱成一锅粥（熵很高），那显然比“只有零星一两个样本的分支熵很高”要糟糕得多！

在构建决策树时，我们在某个节点上决定选哪个特征来切分，依据的是 **哪个特征能最大程度地降低熵（即降低不纯度、最大化纯度, 熵变小最多）**——在决策树学习中，这种“熵的减少量”就叫做 **信息增益** #information_gain  。

问题假设
还是判断猫狗的问题, 现在根节点分别是对三个不同特征进行决策
决策以后两边就各可以求出一个熵
肯定是想两个合一个看判断哪个模型好
所以用到 #weighted_average_entropy
    不是把两个熵 单纯取平均  而是加权平均
    全值是   这个分支中当前样本数/原始所有样本  <-后面会用w表示
        解释  [[加权平均熵]]
![[01-1794317217438.webp]]

但是上面那样还不是 #information_gain 
我们不直接看切分后的加权平均熵，而是去算 **相比于完全不切分时，熵到底减少了多少**
    就是拿上一层节点的熵 来减一减
        下面的例子在最顶上的根节点，一开始装了全部 $10$ 个样本（$5$ 只猫、$5$ 只狗），因此 $p_1 = \frac{5}{10} = 0.5$。
        根节点的初始熵为 **$H(0.5) = 1$**（因为猫狗各半，处于最大不纯度状态）。
![[01-1794317255873.webp]]
前面讲过的 **停止切分条件** 
    其中一个核心停止标准就是：**如果熵的减少量（即信息增益）实在太小（低于某个阈值），干脆就别费劲往下切了**！
    因为收益太小时强行切分，只会白白把树撑大，并增加 **过拟合** 的风险。
    所以这里这样做
最后显然是信息增益为0.28的模型好

总结 #information_gain 公式
* **$p_1^{\text{left}}$**：左子树中正例（猫）所占的比例（本例中 $p_1^{\text{left}} = \frac{4}{5}$）；

* **$w^{\text{left}}$**：当前父节点（根节点）的所有样本中，被分到左分支的样本比例（本例中 $w^{\text{left}} = \frac{5}{10}$；而在刚才脸型的例子里则是 $\frac{7}{10}$）；
(其他同理)
![[01-1794317366286.webp]]
注意 公式是拿着根节点的熵来减一减, 其实是表述有误
    公式里的 $H(p_1^{\text{root}})$ 并不是说不管切到第几层都永远拿最顶上第 0 层根节点的 $1$ 去减！当你往下走到第 1 层左分支（比如里面是 $4$ 猫 $1$ 狗共 $5$ 个样本，$p_1 = 0.8$）准备继续往下切分时，这个待切分的当前节点就充当了局部的“小根节点”，此时公式里的 $H(p_1^{\text{root}})$ 就应该代入 **$H(0.8) \approx 0.72$**，而 $w^{\text{left}}$ 的分母也相应变成这 $5$ 个样本！

## putting it together  

#recursive_algorithm #recursion 递归算法与递归 
    **“大套小、自己调用自己（writing code that calls itself）”**。

构建一棵完整决策树 流程
1. **从根节点起步**：将所有训练样本全部放在整棵树最顶端的 **根节点** 上。

2. **全特征比拼信息增益**：计算所有候选特征的信息增益 #information_gain ，并挑出 **信息增益最高** 的那个特征作为切分特征。

3. **切分数据集并分流样本**：根据选定的决策特征将数据集拆分为两个子集，送到左分支或右分支里。

4. **在左右分支上不断重复**：接着在左分支、右分支以及更往下的分支上，持续重复上述切分过程，直到满足 **停止条件（stopping criteria）** 为止。

5. **四大停止条件（可选用其中一种或多种组合）**：
    * 当节点内样本 **100% 属于单一类别（single class）** 时（也就是熵已经降到了 $0$
    * 当继续切分某个节点会导致整棵树超出你预先设定的 **最大深度** 时；
    * 当再做一次切分所带来的 **信息增益低于某个阈值** 时；
    * 当某个节点里的 **样本数量低于某个阈值** 时。
(最后3点都是防止过拟合, 再做下去可能收益太小了)
![[01-1794321881184.webp]]

用前面的例子完整跑一遍

**第一阶段：搞定最顶端的根节点（Root Node）**
* 把全部 $10$ 个样本放在根节点，算出全部 $3$ 个特征的信息增益，发现 **耳朵形状（ear shape）** 是最佳切分特征。
* 据此创建左右子分支，样本划分到两个左右分支。

**第二阶段：先遮住根节点和右分支，只盯着左分支（5 个样本）建“左子树”**
* **先查停止条件**：先看左分支这 $5$ 个样本满足停止条件了吗？没有，因为里面猫和狗混杂在一起。
* **把当前节点当成“新根节点”重算信息增益**：接下来逐一遍历各个特征，计算它们的信息增益
    ——**就好像当前这个节点是一棵只用这 5 个样本从头训练的新决策树的根节点一样**！
* 我们分别计算“胡须（whiskers）”、“脸型（face shape）”和“耳朵形状（ear shape）”的信息增益；
    你会发现 **按“耳朵形状”切分的信息增益变成了 $0$**，因为走到这里的 $5$ 个样本全都是清一色的尖耳朵，根本分不开！
        *这个意思是因为根节点已经按“耳朵形状”切过一刀了，掉进左分支的 $5$ 只动物 **100% 全是尖耳朵**！此时如果你在左分支再拿“耳朵形状”切一刀，$5$ 只动物会原封不动全掉进左边（$w^{\text{left}}=1$），右边分到 $0$ 只（$w^{\text{right}}=0$），算出来的信息增益必然严格等于 $H(p_1) - 1 \cdot H(p_1) = \mathbf{0}$。
        这意味着即使代码里不手动把用过的二元特征剔除掉，信息增益公式也会自动给它打 $0$ 分将其淘汰*
    在剩下的“胡须”和“脸型”之间，**脸型** 的信息增益最高，于是按脸型切分出左右子分支：
* 左子分支检查停止条件：**全是猫** $\rightarrow$ 满足条件，创建预测为 **“猫”** 的叶节点；
* 右子分支检查停止条件：**全是狗** $\rightarrow$ 满足条件，停止切分并创建预测为 **“不是猫”** 的叶节点。

* **第三阶段：转头搞定右子树（5 个样本）**
* **先查停止条件**：右分支这 $5$ 个样本同样没有达到“单一类别”的停止标准，决定继续切分。
* **同样当成独立新树从头算**：构建右子树的过程，同样就像是在一个仅包含这 $5$ 个训练样本的数据集上从零训练一棵新决策树。
* **完成切分与封顶**：计算所有候选特征的信息增益后，发现 **胡须** 特征的信息增益最高；按胡须“有或无”把这 $5$ 个样本劈开后，检查左右子分支发现都已满足停止条件，于是创建两个叶节点，分别预测 **“猫”** 和 **“不是猫”**

其实你会发现 里面蕴含 递归算法 #recursion 

如何挑选“最大深度”  作为决策树生成的限制呢
**最大深度越大 = 模型越复杂（类比高次多项式与大神经网络)**
    好比拟合一个 **更高次数的多项式**，或者训练一个 **更大的神经网络**。它能让决策树学到更复杂的模型，但如果去强行拟合过于复杂的函数，也会显著增加 **过拟合** 的风险。
* 从理论上讲，你可以使用上周学过的 **交叉验证** 来挑选最大深度
    ——即尝试不同的最大深度取值，看哪一个在交叉验证集上表现最好就选哪一个（不过在工程实践中，开源库往往还提供了比这更巧妙的方式来帮你决定这类参数）。

## using one-hot encoding of categorical features  

#one_hot_encoding 独热编码 
    以前的决策树只会处理“非此即彼（二选一）”的特征，要是突然遇到一个有 3 个甚至 $k$ 个选项的类别特征（比如耳朵形状可能是“尖耳”、“垂耳”或者“椭圆耳”），怎么在不改动原算法的前提下喂给模型呢？
    独热编码的做法：**直接把这个“三选一”的多选特征，拆成 3 道独立的“是非判断题（只填 $0$ 或 $1$ 的新特征）”**——分别是“是尖耳吗？”、“是垂耳吗？”、“是椭圆耳吗？”。对于任何一只动物，这 3 列里 **==有且仅有 1 列会被标为 $1$==（代表激活/点亮，也就是英文里的 "hot"），其余列统统填 $0$**

#binary_features 二元特征（$0/1$ 二值特征） 
    指只能取 **$0$ 或 $1$ 这两种可能值** 的特征。通过独热编码，==一个原本有 $k$ 种离散取值的类别型特征会被直接替换成 $k$ 个二元特征==，不仅能让之前学的二叉树决策树算法原封不动直接套用，还能把文字类别变成纯数字喂给神经网络或逻辑回归。

当离散特征有“超过 2 种取值”时怎么办？
    比如下面的耳朵形状 可以取三个离散值了
可以像右图那样 一个节点直接分出3个分支, 但是可能这个方法不好所以不采用
![[01-1794327651647.webp]]

所以用到 #one_hot_encoding
    其实可以理解为 
        原来是 1个特征 3个离散值
        现在是 3道判断题(每个值是 是1/不是0)  就是3个特征
![[01-1794327714381.webp]]

![[01-1794327728534.webp]]
如果一个类别型特征可以取 **$k$ 种可能的值**（在我们刚才的例子里 $k = 3$），我们就创建 **$k$ 个只能取 $0$ 或 $1$ 的二元特征（binary features）** 来替换掉它。

这 3 个数字里 **有且仅有 1 个值等于 $1$**。
    所以叫 ==独 ==热编码

这样我们又回到了“每个特征只取两种可能值之一”的原始设定；因此前面学过的决策树学习算法 **不需要做任何修改**，

独热编码 **不仅适用于决策树，同样通杀神经网络**
    把后面几个特征也全部用数字0,1表示
    那整个样本就变成 一个只有0和1的向量
    那这个当做输入 用 #logistic_regression 那套做不是一样的
        喂给 **神经网络（neural network）**、**逻辑回归（logistic regression）** 或 **线性回归（linear regression）** 都可以的
![[01-1794327788636.webp]]

## continuous valued features 

#continuous_valued_features 连续值特征 
    指取值不再局限于寥寥几个固定类别选项，而是 **可以取任意具体数字（any number，包括整数和小数）** 的特征。
    比如动物 **“体重（weight，单位：磅）”** 就是典型的连续值特征。
    决策树没法对无穷无尽的数字每个都分一条叉，它的破局妙招是 **“画一条及格线（阈值 threshold）一刀切”**——把连续数字问题直接转化成一道“体重是否 $\le 9$ 磅？”的是非判断题，再算熟悉的信息增益来挑出最划算的那一刀！

#threshold_split #midpoints 阈值切分 与 排序中点法 
    决策树在面对连续值特征时，怎么知道这一刀（阈值）该切在 $8$ 磅、$9$ 磅还是 $13$ 磅呢？
    标准做法是先把当前节点里的所有样本按体重从小到大排成一排，然后专门取 **每两个相邻样本之间的正中间数值（midpoints，中点）** 作为候选切分点（比如 $10$ 个样本排好序后中间正好有 $9$ 个空当，就测这 $9$ 个候选阈值），挨个算出信息增益，挑得分最高的那一个去跟其他特征同台PK！
        就是每个样本中间切一刀,看此时的拆分纯不纯净

问题假设
现在给区分猫/不是猫 的分类器 加一个特征
    动物体重（单位：磅 pounds）
现在怎么选节点的特征呢?
    决策树学习算法的推进方式和以前几乎一模一样, 耳朵形状、脸型、胡须这几个特征还是以前一样算 #information_gain 
        ——唯一的区别在于，体重特征  要单独做好几次决策测试, 算体重怎么决策, #information_gain 最大   
        然后再和别的离散值比较

现在画个散点图，用“是否 $\le$ 某个阈值”把连续数字一分为二
    上面一排是猫（$y = 1$），下面一排是不是猫/狗（$y = 0$）。
尝试许多个不同的候选 **阈值**，然后从中挑出 **最好的那一个（即能让信息增益达到最大的阈值）**

下面就为了演示 切了3刀
实际要切几刀?
#midpoints 相邻样本中点
    先把所有训练样本按照该连续特征的值（如体重）**从小到大排序**，然后取排好序的相邻训练样本之间的所有 **中点值（midpoints）** 作为候选阈值。
    （$10$ 个样本 $\rightarrow$ 测 $9$ 个中点,  挑出信息增益最高的那一个。）
算好以后, 再和其他特征的 熵比较一下就好了
![[01-1794328117247.webp]]

💡补充
 **为什么 $10$ 个样本只需要测 $9$ 个中点，多测几百个小数点有用吗？**
    想象 $10$ 只动物按体重排成一排站在数轴上，两两之间正好有 $10 - 1 = 9$ 个空当。在同一个空当内部（比如第 $4$ 只重 $8.8$ 磅、第 $5$ 只重 $9.2$ 磅），无论你把刀切在 $8.9$、$9.0$（中点）还是 $9.1$，分到左边的永远是那 $4$ 只，分到右边的永远是那 $6$ 只，算出来的信息增益分毫不差！
    所以每个空当只需要取正中间的 **中点（midpoint）** 测一次，就已经把所有可能的切分结果 100% 穷举干净了。

## regression Trees (optional)

#regression_trees 回归树 
    前面学的决策树都是做选择题的“分类树”（预测离散类别，比如判断是猫还是狗）；而“回归树”就是把决策树改造成用来 **猜具体数字（predict a number，比如预测一只动物重多少磅）** 的回归算法。
    它的推理走法跟分类树一模一样，也是从头顶的根节点一路回答问题走到最底下的叶节点；只不过走到终点后不再喊“是猫/不是猫”，而是把训练时掉进这个叶节点里的所有动物体重加起来 **算个平均数（take the average）**，直接拿这个平均体重当作最终预测值！

到目前为止，我们只把决策树当作分类算法来讨论；
这节，我们将把决策树推广为 **回归算法** #regression ，让它能够预测一个具体的数字。

问题假设
目标是用它们来 预测动物的体重 $Y$
    因为是预测一个连续数字 $Y$,所以是 #regression 
![[01-1794329674966.webp]]

回归树的样子 就一个地方不一样
叶子结点 输出的是分类以后样本体重的平均值
搭建好回归树以后
* **测试推理全流程**：给定一个新的测试样本，模型照常顺着决策节点一路往下走，直到抵达某个叶节点，然后直接输出该叶节点的预设数值（即训练期间落入该叶节点的所有动物体重的平均值）。
![[01-1794329754053.webp]]

    决策树在左分支和右分支里 **同时选择同一个特征来做切分是完全没问题的**，只要切分算法算出来觉得这样最好就可以这么干！
     **顺着同一条路径往下走的子孙节点** 里不再切同一个二元特征(因为切过了,再切一次肯定 #information_gain 是0了)

训练的时候怎么搞呢

    ==要设法降低每个数据子集中 **目标值 $Y$（即体重）的方差**==
    (方差代表  ==一组数字上下波动的跨度有多大== )

不同决策模型  算两边的方差
然后还是算左右两边的 #weighted_average 加权平均
然后用 根节点的方差减一减   看哪种决策模型 让方差减少的更多

# tree ensembles

## using multiple decision trees

#tree_ensemble 树集成（决策树集成模型） 
    三个臭皮匠，顶个诸葛亮
    ——单棵决策树有个很大的毛病：只要训练集里哪怕改掉区区 $1$ 个样本，整棵树就可能从树根开始彻底变得面目全非（也就是对数据微小变化太敏感、不够稳健）。
    为了治好这个毛病，我们干脆不再只种一棵树，而是一口气训练出 **一大群长相略有不同的决策树（即由多棵树组成的集合 ）**，这就叫 **树集成**！

#majority_vote 多数投票制 
    当树集成里的好几棵树面对同一个新测试样本给出不同预测时，用来拍板最终结果的表决规则。做法就是让每棵树各自独立走一遍推理投出一票，最后 **少数服从多数**
    （比如 $3$ 棵树里有 $2$ 棵猜“是猫”、$1$ 棵猜“不是猫”，最终就拍板预测为“是猫”）

决策树有个缺点  (这个应该没法根治)
    对数据中的微小变化可能 高度敏感
    仅仅改动 1 个训练样本，整棵树彻底大变样！
![[01-1794338706451.webp]]

所以面对同一个业务问题, 我们不用一棵树,用一群树
这个就是 树集成 #tree_ensemble 

一群树怎么工作 拿到问题结果?
    所有树跑一遍, 得到输出, 然后少数服从多数
    就是 #majority_vote 多数投票制 
        比如下面 2棵树投票 是猫,所以最后我们决策这是猫
这样你的整体算法就不会那么容易受到 **任何单棵树的怪异输出** 的影响
![[01-1794338760521.webp]]

💡补充:
拿同一份数据跑 100 遍建树算法，能造出树集成吗？
    不行树集成  后面会讲,需要构造每棵树的时候 训练样本都有所差别
    如果你把一模一样的 10 个样本原封不动喂给算法跑 100 遍，它长出来的 100 棵树会 **分毫不差完全一模一样**，投 100 票跟投 1 票没有任何区别

## sampling with replacement

#sampling_with_replacement 有放回抽样 
    想象把原来的 $10$ 个样本装进一个看不见的黑布袋里摇匀，每次伸手随机摸出 $1$ 个样本抄下来后，**千万别拿走，必须原封不动把它扔回袋子里（这就是“有放回 replacement”）**

#sampling_with_replacement  就比如这样  抽积木
    每次可能抽到**重复的样本**
![[01-1794338880567.webp]]

上一节说, 要造 #tree_ensemble ,怎么造呢
首先就是要确定输入样本, 这个需要一点操作
    目标是 **构造出多份与原始训练集都略微不同的随机训练集**
用到 #sampling_with_replacement 
    比如下面一共10个样本
    构造一颗树的样本  就是有放回的抽10次==(要和原样本集合同样规模)==

* **新随机训练集的出现下面情况都是正常的**：
1. 里面 **包含重复的样本**；
2. 它 **并没有包含原始训练集里的全部 $10$ 个样本**（有些原样本一次也没被抽中）——这也完全没关系！
![[01-1794338928054.webp]]

💡 **补充**：
**为什么“有重复、有漏抽”反而是件大好事？**
    “仅仅改动 $1$ 个样本，决策树就会从根节点开始长出完全不同的结构”
    正因为每次有放回抽样都会让一部分==样本翻倍出现==、另一部分样本暂时隐身，每次算出来的信息增益排名就会发生微妙变化，从而顺理成章地帮我们==种出一大批长相各异、能够互补投票的决策树！==

## random forest algorithm

#bagged_decision_tree 装袋决策树（Bagging 决策树） 
    就是把上一节学的“黑布袋有放回抽样”循环跑上 $B$ 次（比如 $B = 100$ 次）：每次从装有 $m$ 个原始样本的虚拟袋子里有放回地摸出 $m$ 个样本，拿去单独训练出一棵决策树；重复 $100$ 次就种出了 $100$ 棵略有不同的树，预测时让这 $100$ 棵树一起投票拍板。
    因为核心动作是把样本扔进虚拟袋子（bag）里抽样，所以这种树集成算法就叫“装袋决策树”

#random_forest 随机森林 
    就是树集合 的另一种称呼吧 可能用的更多
    在“装袋决策树”的基础上再加一味“随机调料”进化而来的王牌树集成算法
        在搭建树的时候, 对每次选择的决策特征也有限制, 不能全用, 要抽k个出来用(看下面)

上几节提到的 #tree_ensemble  里面的每棵树叫 #bagged_decision_tree 

如何用“有放回抽样”搭出装袋决策树 #bagged_decision_tree ？
**给定大小为 $m$ 的训练集，循环执行下面的操作 $B$ 次（从 $b = 1$ 到 $B$）**
- 使用有放回抽样创建一个大小同样为 $m$ 的新训练集。
    比如原本有 $10$ 个训练样本，就把它们放进虚拟袋子里有放回地连抽 $10$ 次，生成一份同样包含 $10$ 个样本的新训练集
- 在这份新生成的数据集上训练出一棵决策树。
(这样重复 训练出B棵树)
最后预测结果的时候, 把输入在B棵树里都跑一遍, 然后投票选出最后的结果
![[01-1794342860351.webp]]
（循环计数用的字母 $b$ 和总棵数 $B$ 也是取自 **b**ag 的首字母）！

参数 $B$（树的数量）怎么选？
    在工程实践中，构建树的总数 $B$ 通常选在 **$100$ 左右**，大家一般推荐在 **$64$ 到 $128$ 之间** 取值。
为什么不干脆建 1000 棵树？
    把树的数量 $B$ 设得更大 **永远不会损害模型性能**
    但超过某个临界点后（比如当 $B$ 远大于 $100$ 左右时），就会出现明显的 **收益递减**
        就是有提示,但是提升超级少了, 模型效果并不会再有实质性的大提升。


装袋决策树有时候会遇到一个尴尬——哪怕抽出来的训练集略有不同，假如数据集里某一个特征特别强势，所有 $B$ 棵树在最顶上的根节点（以及靠近根节点的几层）还是会不约而同地挑同一个特征来切分，导致长出来的树长得太像。
在装袋决策树的基础上只需做 **一处关键改动**，就能让算法效果好上一大截，正式化身为 **随机森林算法** #random_forest 
    为了强行拉开差异，随机森林规定：**在==每一个节点==准备挑特征切分时，不准从全部 $n$ 个特征里挑，而是先随机抓出 $k$ 个特征（通常取 $k = \sqrt{n}$）组成一个小候选池，只准在这 $k$ 个特征里挑信息增益最高的那一个**——这样长出来的森林百花齐放、差异更大，投票预测的准确率和稳健性也大幅飙升！
    解释 [[随机森林构建选k个特征]]
![[01-1794342972949.webp]]

 **为什么随机森林比单棵决策树稳健（Robust）得多？**
    通过“有放回抽样”的过程，随机森林算法实际上 **已经提前探索了训练数据中大量微小的变动**，针对这些变动训练出了不同的决策树，并对所有这些数据变动的结果进行了 **平均**。

💡 **补充**：
随机抽 $k$ 个特征是“每建一棵树抽一次”，还是“每到一个节点都重新抽一次”？
    并不是建第 1 棵树时固定抽 $k$ 个特征用到底，而是在同一棵树里，根节点随机抽一批 $k$ 个特征比拼完后，走到左子节点时 **又要重新随机洗牌再抽一批新的 $k$ 个特征**！

同时注意一个超爽的实战性质：树的总数 $B$ 调得再大 **也绝不会导致过拟合**，最多只是白费算力触发收益递减而已。

## xgboost

#deliberate_practice 刻意练习 教育学与技能训练里的经典概念

#xgboost #extreme_gradient_boosting 极端梯度提升（XGBoost）
    当今工业界商业落地和机器学习竞赛（如 Kaggle）中**使用最广泛、战斗力最强的提升决策树开源实现**。
    它不仅运行飞快、自带优秀的默认切分与停止规则，还原生内置了防过拟合的正则化机制；
    而且在底层实现上，它连随机抽样造新数据集这一步都==省了==，直接通过**给不同训练样本分配不同权重**来实现对错题的重点关注，效率高到飞起！

前面我们学的只是 建造 #random_forest 的最基本流程
如今无论在商业应用还是机器学习竞赛中，最常用、最成功的树集成实现当属 **XGBoost**
这个算法在基础步骤上有一些修改
    在 有放回抽样的时候 ,不是均等概括的抽, 而是增加分类分错的样本的抽到概率

具体流程举例
* **第 1 轮循环（$b = 1$）保持不变**：第一次进循环时，照常抽样生成一份训练集，训练出第 1 棵决策树。
* **从第 2 轮起（$b = 2, 3, \dots, B$）的核心改动**：在抽样时，我们不再以均等的 $\frac{1}{m}$ 概率去抽取每个样本，而是**让那些被前面已训练好的树分错的样本有更高的概率被抽中**！
    这步怎么做到的, 内部可能比较复杂,就不管了
这个就是一种 刻意练习
    假设你想练熟一首 5 分钟的钢琴曲，一遍遍从头到尾通弹整首曲子非常耗时；如果你先弹一遍，然后把注意力只集中在**还没弹好的那几个小片段**上反复练习，学会弹好这首曲子的效率就会高得多。

## when to use decision trees

什么时候用决策树
什么时候换回神经网络

#decision_trees 
* **最擅长的数据类型——表格型/结构化数据（Tabular / Structured Data）**：
    如果你的数据集看起来像一张巨大的电子表格（giant spreadsheet），那么决策树非常值得考虑。
    **典型例子**：比如之前的房价预测应用，特征分别是房屋面积、卧室数量、楼层数和房龄——无论是类别型特征还是连续值特征，无论是做分类任务（预测离散类别）还是做回归任务（预测具体数字），决策树在这类表格数据上都能表现得非常出色。

* **不推荐使用的禁区——非结构化数据（Unstructured Data）**：
    图像、视频、音频和文本这类很难存成电子表格格式的 **非结构化数据** 上使用决策树或树集成。

* **优势一：训练速度极快，加速“开发迭代循环”**：
    回想上周讲过的 **机器学习开发迭代循环**：如果你的模型**训练一次**要花好几个小时，就会严重拖慢你跑通这个循环去改进算法性能的速度。
    而决策树（包括树集成）训练起来通常非常快，这能让你更快地转动开发循环，从而更高效地提升学习算法的表现。

* **优势二（但别过度神化）：小型决策树具备“人类可解释性（Human Interpretable）”**：
    如果你只训练 **单棵小型决策树**（比如只有几十个节点），你可以直接把整棵树打印出来，一清二楚地看懂它究竟是如何看特征、做决定的。
    但是决策树的可解释性有时被吹过头了——因为实战中当你建了一个包含 **100 棵树** 的集成模型、且每棵树都有上百个节点时，想单靠肉眼盯着这片森林搞懂它在干什么同样非常困难，往往需要借助额外的专门可视化技术。

* **实战选型建议（认准 XGBoost！）**：
    绝大多数应用中都会首选 **XGBoost**。
    只有在你的计算预算极其受限考虑时才退回单棵决策树

#neural_networks 
* **全能型数据通吃（结构化 + 非结构化 + 混合数据）**：
    与决策树不同，神经网络在 **所有类型的数据** 上都表现出色——既包括表格型（结构化）数据，也包括非结构化数据，还包括同时包含结构化与非结构化成分的 **混合数据**。
在 **表格型结构化数据** 上，神经网络和决策树往往旗鼓相当、互有胜负（both competitive）；但在图像、视频、音频和文本等 **非结构化数据** 上，神经网络是绝对的首选算法，而不是决策树或树集成！

* **主要缺点：训练速度较慢**：

* **独门优势一：支持“迁移学习（Transfer Learning）”**：
    神经网络可以使用迁移学习, 因为在许多实际应用中我们手头只有一个很小的训练集，能够利用迁移学习在一个大得多的数据集上先进行 **预训练**，是拿到有竞争力性能表现的关键所在。

* **独门优势二：更容易把“多个模型串联起来联合训练”**：
    如果你正在搭建一个由多个机器学习模型协同工作的复杂系统，把 **多个神经网络串联在一起进行训练**，要比串联多个决策树容易得多。
        **底层技术原因**（了解直觉即可）：即便你把多个神经网络串成一串，依然可以用 **梯度下降** 把它们作为一个整体同时一起训练
![[01-1794347887757.webp]]

![[01-1794347985683.webp]]

**为什么决策树没法像神经网络那样用梯度下降把好几个模型串起来训？**
    神经网络每一层都是平滑可导的数学公式（矩阵乘法 + 激活函数），所以把 A 网络的输出直接接进 B 网络当输入，整条大流水线依然可以从右往左跑 **反向传播** 算出梯度一起更新；
    而决策树内部全是硬邦邦的 `if-else` 离散分叉（比如“体重 $\le 9$ 磅往左走”），在切分点处根本不可导，没法往回传梯度，所以只能一棵树一棵树单独训练！
