### 这个access到底啥意思?   (不好理解,先放着吧)
它决定了纹理的**使用方式**和**内存管理策略**，直接影响性能和功能。
#### **1. `SDL_TEXTUREACCESS_STATIC`（静态纹理）**

- **特点**：
    
    - 创建后内容**很少修改**
    - 存储在显存中，**访问速度最快**
        
- **适用场景**：
    
    - 游戏中的背景图片
    - 静态UI元素（如按钮图标）
#### **2. `SDL_TEXTUREACCESS_STREAMING`（流式纹理）**

- **特点**：
    
    - 需要**频繁更新内容**（如视频播放）
    - 允许通过 `SDL_UpdateTexture()` 或 `SDL_LockTexture()` 修改
    - 比静态纹理稍慢（需要CPU→GPU数据传输）
        
- **适用场景**：
    
    - 视频帧渲染
    - 实时生成的动态纹理
#### **3. `SDL_TEXTUREACCESS_TARGET`（可渲染纹理）**

- **特点**：
    
    - 可以作为**渲染目标**（类似离屏缓冲区）
    - 允许通过 `SDL_SetRenderTarget()` 指定
    - 性能开销最大
        
- **适用场景**：
    
    - 后期特效处理(先渲染到纹理，再添加模糊/发光等效果)
    - 多阶段渲染（如先渲染到纹理，再叠加效果）

## part3

```cpp
SDL_Rect sdlRect;

while (1) {
	if (fread(buffer, 1, pixel_w * pixel_h * bpp / 8, fp) != 
						pixel_w * pixel_h * bpp / 8) {
		// Loop
		fseek(fp, 0, SEEK_SET);
		fread(buffer, 1, pixel_w * pixel_h * bpp / 8, fp);
	}

	SDL_UpdateTexture(sdlTexture, NULL, buffer, pixel_w);

	sdlRect.x = 0;
	sdlRect.y = 0;
	sdlRect.w = screen_w;
	sdlRect.h = screen_h;

	SDL_RenderClear(sdlRenderer);
	SDL_RenderCopy(sdlRenderer, sdlTexture, NULL, &sdlRect);
	SDL_RenderPresent(sdlRenderer);
	
	//Delay 40ms
	SDL_Delay(40);

}
```

fread函数回顾
(sizeof(a)大小的单位应该是字节,所以上面代码这块写1,就是每次读1字节)
![[Pasted image 20250530185537.png]]

fseek函数
![[Pasted image 20250530185924.png]]
所以fread(buffer, 1, pixel_w * pixel_h * bpp / 8, fp)就是读取一帧pixel_w * pixel_h * bpp / 8这么多字节(前面的1代表每个读取单元为1字节),然后从fp中读到buffer(类比cache)
- 如果读取的字节数 **不足**（比如文件已经读完），就 `fseek(fp, 0, SEEK_SET)` 回到文件开头，**循环播放**。
- 如果读取成功，就继续渲染。

关于SDL_Delay,它是**延时函数**，用于让当前线程暂停执行指定的毫秒数。它的主要用途是 **控制帧率**、**减少 CPU 占用** 或 **实现定时等待**。
输入的参数单位是 **毫秒**
这个函数windows底层是调用了Sleep(ms),就是播完一帧以后先暂停这么多时间
所以可以用它来实现帧率
比如25fps  1s25帧
1s=1000ms   1000ms/25=40ms  即一帧显示40ms
所以要实现倍速或者慢速,那就调整参数就好了
