**代码区与常量区**: ...  <mark style="background: #ABF7F7A6;">const只不过是让编译器将变量视为常量罢了，和真正的常量有本质上的区别。</mark>

	意思是const 是“运行时常量”，而非“编译时常量”
	const 变量的值在运行时确定，而真正的常量（如 constexpr 或字面量 5、"hello"）在编译时就已经确定。
	
```cpp
int x = 10;
const int y = x;  _// y 的值在运行时确定（即使它是 const）_
constexpr int z = 10;  _// z 是真正的常量，编译时就固定_
```
	y 虽然是 const，但它的值取决于 x（运行时变量），所以它不是真正的常量，只是“不可修改的变量”。
	z 是 constexpr，它在编译时就固定，是真正的常量。


如果需要创建的对象有几十M，每次调用函数都需要创建一个这么大的对象，再复制到对应的<mark style="background: #ABF7F7A6;">容器</mark>中，那就太过耗费内存了。而且栈内存非常的小，通常不超过8M。
	
	在 C++ 中，容器（Container） 是指用于存储和管理一组数据的标准库组件，例如 std::vector、std::list、std::map 等。
	容器的主要作用是存储和管理多个数据对象，并提供高效的访问、插入、删除等操作。
	
	容器通常存储在哪里？
	栈（Stack）：如果容器对象本身（如 std::vector<int> vec;）是局部变量，那么它的控制结构（如大小、容量、指针等）存储在栈上。
	堆（Heap）：但容器内部存储的实际数据（如 vec 里的 int 元素）通常存放在堆上（除非使用特殊优化，如小对象优化）。

<mark style="background: #ABF7F7A6;">堆的唯一寻址方式就是指针，如果没有栈，根本无法使用堆。</mark>
	
	为什么说"堆的唯一寻址方式是指针"？
	堆内存没有名字：比如你 new int[100] 申请了一块堆内存，系统不会给你一个变量名直接访问它。
	
	指针是仓库钥匙：
```cpp
int* ptr = new int[100]; // ptr就是指向堆内存的"钥匙"
```
	没有 `ptr` 这把"钥匙"，你就再也找不到申请的堆内存了（这就是内存泄漏）。
	
	为什么"没有栈就无法使用堆"？
	指针本身存放在栈上
	即使堆内存是独立的，但指向堆的指针（如 ptr）本身是一个局部变量，它存放在栈上！
```cpp
void foo() {
    int* ptr = new int[100]; // ptr在栈上，它指向堆内存
    // 函数结束时ptr自动销毁，但堆内存不会！
    //所以在ptr自动销毁之前,一定要先delete,回收内存
}
```
	
	常见误区
	错误认知：认为堆是独立于栈存在的
	事实：堆的访问依赖栈上的指针，二者协同工作
	错误代码：
```cpp
int* foo() {
    int x = 10;      // x在栈上
    return &x;       //返回了x的地址(就是返回了int*类型)
    // 危险！函数结束x被销毁，返回的指针无效
}
```
