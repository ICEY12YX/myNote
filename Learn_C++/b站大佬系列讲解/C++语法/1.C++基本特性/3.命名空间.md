C++经常需要多个团队合作来完成大型项目。<mark style="background: #ABF7F7A6;">多个团队就常常出现起名重复的问题</mark>，C++就提供了命名空间来解决这个问题。
比如团队A和团队B都需要定义一个叫做Test的类。
```cpp
//ATest.h
namespace A{
	void test{}
}
```

```cpp
//BTest.h
namespace B{
	void test{}
}
```

```cpp
//ATest.cpp
#include "ATest.h"
namespace A{  //这个就是定义了某个函数或变量在某个命名空间内
	void test{
		std::cout << "A命名空间的test" << std::endl;
	}
}
```

```cpp
//BTest.cpp
#include "BTest.h"
namespace B{
	void test{
		std::cout << "B命名空间的test" << std::endl;
	}
}
```

```cpp
#include "ATest.h"
#include "BTest.h"
int main(){
	A::test();  //使用的时候命名空间名字 加上 '::',就像std::
	B::test();
}
```

我们注意到大佬上面的写法,是把声明和定义分开
而且分开的两边,都写了命名空间namespace

<mark style="background: #ABF7F7A6;">using 命名空间：：变量名。这样以后使用此变量时只要使用变量名就可以了</mark>
```cpp
#include "ATest.h"
#include "BTest.h"
using A::test;
//using B::test;  同时写这句,就会报错
int main(){
	test();  //这样就直接用A命名空间的test
}
```

<mark style="background: #ABF7F7A6;">using namspce 命名空间。这样，每一个变量都会在该命名空间中寻找</mark>
```cpp
#include "ATest.h"
#include "BTest.h"
using namespace A;
int main(){
	test();  //这样就直接用A命名空间的test
}
```

<mark style="background: #ABF7F7A6;">头文件中一定不能使用using关键字。会导致命名空间的污染</mark>

Silent Conflict静默冲突是什么?
    是 C++ 中一种特别危险的命名冲突问题，它不会直接导致编译错误，而是让程序在“不知不觉”中调用了错误的函数/类，最终引发难以调试的运行时错误或逻辑错误。
    |
	静默冲突 ≈ 编译器“偷偷”选错了实现，导致程序行为异常
	头文件中的 using 是万恶之源 → 像避免全局变量一样避免它
	显式命名空间（如 std::）虽然打字多，但能救命！
