<mark style="background: #ABF7F7A6;">auto只能推断出类型，引用不是类型，所以auto无法推断出引用，要使用引用只能自己加引用符号</mark>
```cpp
int main() {
	int i = 100;
	int& i1 = i;
	auto i2 = i1;  //这里i2就推不出引用,所以i2只是int
	auto& i3 = i1;

	std::cout << type_id_with_cvr<decltype(i2)>().pretty_name() << std::endl;
	std::cout << type_id_with_cvr<decltype(i3)>().pretty_name() << std::endl;

	std::cin.get();
}
```
![[Pasted image 20250606151622.png]]

<mark style="background: #ABF7F7A6;">auto关键字在推断引用的类型时：会直接将引用替换为引用指向的对象。其实引用一直是这样的，引用不是对象，任何使用引用的地方都可以直接替换成引用指向的对象</mark>
(其实这条是在讲引用,而不是auto)
```cpp
int i = 100;
const int& i1 = i;
auto& i2 = i1;  //这句相当于auto& i2 = i
```
意思是<mark style="background: #FFF3A3A6;">任何使用引用的地方都应等效于直接使用原对象</mark>
因为引用 本身就**不是对象**，而是 **对象的别名**

上面那一条也可以用这个来解释
auto i2 = i1;
    编译器看到 `i1` 是引用，会直接替换为 `i1` 绑定的对象 `i`
    相当于 `auto i2 = i`，所以 `i2` 是 `int` 类型

<mark style="background: #ABF7F7A6;">auto关键字在推断类型时，如果没有引用符号，会忽略值类型的const修饰，而保留修饰指向对象的const，典型的就是指针</mark>
<mark style="background: #ABF7F7A6;">auto关键字在推断类型时，如果有了引用符号，那么值类型的const和修饰指向对象的const都会保留</mark>
这个在指针方面,就是说auto保留修饰指针本身的const,忽略修饰指针指向的值的const
就是第二个const被忽略
就是<mark style="background: #FFF3A3A6;">第二个const是单纯的一种值传递,所以会被忽略</mark>
然后最后auto后面加了&引用,那两个const都会保留
```cpp
int i = 100;
//前一个const表示i1指向的内容不能变,就是不能*i1=2;
//后一个conts表示i1指向不能变
//可以理解为前一个const修饰指针指向的值
//后一个const修饰指针本身
const int* const i1 = &i;
auto i2 = i1;  //i2为const int*类型
auto& i3 = i1; //i3为const int* const
```
同样道理,下面也是单纯值传递,所以const被忽略
```cpp
const int i = 100;
auto i1 = i; //i1为int类型
auto& i2 = i; //i2为const int
```

<mark style="background: #ABF7F7A6;">因为在传递值时，修改这个值并不会对原有的值造成影响。而传递引用时，修改这个值会直接对原有的值造成影响。</mark>
(拿上面第一个举例)
意思是说auto i2 = i1只是值传递,i2再怎么改,跟i1,i都没关系,i2此时是个独立的个体,所以i2想指向别的int也可以,保证有第一个const,不让i2随便改i就好了,所以理所应该可以忽略第二个const
但是auto& i3 = i1,i3本来就是个别名,都是别名了,还和原本的i1类型不同,那肯定不行

<mark style="background: #ABF7F7A6;">可以在前面加上const，这样永远都有const的含义</mark>
就是说auto前面加const,可以把值传递忽略掉的const补上
```cpp
int i = 100;
const int* const i1 = &i;
const auto i2 = i1;  //i2为const int* const类型
```
