<mark style="background: #ABF7F7A6;">多个线程的执行顺序是乱的，具体执行方法和处理器的调度机制有关系</mark>
比如下面这段代码
    主线程,子线程都++g_num
    但是具体执行,程序员根本不知道哪个++先执行,还是同时执行
```cpp
unsigned g_num = 0;  //全局变量

void test() {
	++g_num;
}

int main() {
	std::thread myThread(test);
	myThread.detach();

	++g_num;
}
```

一个进程运行时，数据存储在内存中。如果一个数据要进行运算，必须先将数据拷贝到寄存器中。比如要对栈上的一个int i进行“++”操作，需要将i的值拷贝到寄存器中，将该值自加后再拷贝到原来的内存。
<mark style="background: #ABF7F7A6;">如果此时有两个线程均进行的是这样的操作，可能出现两个进程都拷贝了i原来的值到寄存器，然后各种加一，再拷贝到i对应内存的情况，最终导致i这个变量只自加了一次</mark>。
    可以下面的代码测试一下
    因为上面的原理,所以只会比2000000少,不会多
```cpp
unsigned g_num = 0;
std::mutex myMutex;

void test() {
	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}
}

int main() {
	std::thread myThread(test);

	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}

	myThread.join();

	std::cout << g_num << std::endl;
}
```

互斥锁的作用原理很简单，<mark style="background: #ABF7F7A6;">对共享数据加锁，当一个线程对这块数据进行操作时，别的线程就无法对该区域数据进行操作</mark>。
```cpp
unsigned g_num = 0;
std::mutex myMutex;

void test() {
	myMutex.lock();  //加锁,谁先执行到这段代码,就锁住
	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}
	myMutex.unlock();  //解锁
}

int main() {
	std::thread myThread(test);

	myMutex.lock();
	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}
	myMutex.unlock();

	myThread.join();
	std::cout << g_num << std::endl;
}
```

这种方式的互斥锁有个弊端，<mark style="background: #ABF7F7A6;">就是lock()之后容易忘记unlock()</mark>，就和指针类似。<mark style="background: #ABF7F7A6;">于是和智能指针类似，也有了lock_guard</mark>，用来防止开发人员忘了解锁
```cpp
unsigned g_num = 0;
std::mutex myMutex;

void test() {
	myMutex.lock();  //加锁,谁先执行到这段代码,就锁住
	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}
	//如果有下面这串代码,执行到抛出异常
	//那永远执行不到unlock,那主线程也永远没法执行下去了
    //if(...){
    //    throw ...
    //}

	myMutex.unlock();  //解锁
}

int main() {
	std::thread myThread(test);

	myMutex.lock();
	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}
	myMutex.unlock();

	myThread.join();
	std::cout << g_num << std::endl;
}
```

所以还是用lock_guard好, 这样我们永远也不用担心锁有没有解锁
```cpp
unsigned g_num = 0;
std::mutex myMutex;

void test() {
	std::lock_guard<std::mutex> lg(myMutex);  //类似智能指针,就加锁的时候写一句就好了
	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}
}

int main() {
	std::thread myThread(test);

	//注意,类似智能指针,lock_guard需要一个作用域,来确定什么时候解锁
	{
		std::lock_guard<std::mutex> lg(myMutex);
		for (int i = 0; i < 1000000; i++) {
			++g_num;
		}
	}
	myThread.join();
	std::cout << g_num << std::endl;
}
```

原子操作的原理：<mark style="background: #ABF7F7A6;">将一个数据设置为原子状态，使得该数据处于无法被分割的状态</mark>，意思就是处理器在处理被设置为原子状态的数据时，其它处理器无法处理该段数据，该处理器也会保证在处理完该数据之前不会处理其他数据
    就是把数据设置为不可分隔状态,一个线程处理他的时候,另一个线程没法处理
```cpp
std::atomic<unsigned> g_num = 0;
std::mutex myMutex;

void test() {
	//此时就不用加锁了
	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}
}

int main() {
	std::thread myThread(test);

	for (int i = 0; i < 1000000; i++) {
		++g_num;
	}

	myThread.join();
	std::cout << g_num << std::endl;
}
```
