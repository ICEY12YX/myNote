为什么要继承?
    假设现在游戏里有很多种枪,每种枪是一个类
    小绿,针管,喇叭
    每个枪都有射速,射程,伤害等属性
    那每种枪,都要写一遍这些重复的属性(成员变量)太麻烦了
    那就可以用到继承

简单的继承
```cpp
class Qiang{
protected:
    std::string name;
    int speed;
    int hit;
}

class xiaoLv : public Qiang{
public:

private:
    int a; //随便取的
}
```
之前讲过,继承可以有不同的修饰符权限[[1.类介绍，构造函数，析构函数]]
但其实有用的只有public,其他两个根本没用

___

父类实例可以指向子类
    底层是这样的
    父类实例会检查此时的实例成员变量
    有没有父类该有的那些成员变量
    全有,子类独有的那些成员变量,他压根不会检查
    所以父类实例可以指向子类

___

<mark style="background: #ABF7F7A6;">先调用父类的构造函数，再调用子类的构造函数，也就是说先初始化父类的成员，再初始化子类的成员</mark>
```cpp
class Qiang{
public:
    Qiang(const std::string& name_,const int speed_,const int hit_):name(name_),speed(speed_),hit(hit_){
        std::cout << "Qiang()" << std::endl;
    }
protected:
    std::string name;
    int speed;
    int hit;
}

class xiaoLv : public Qiang{
public:
    xiaoLv(const std::string& name_,const int speed_,const int hit_,const  int a_):Qiang(name_,speed_,hit_),a(a_){  //这里要写上调用父类构造函数
        std::cout << "xiaoLv()" << std::endl;
    }
private:
    int a; //随便取的
}
```

<mark style="background: #ABF7F7A6;">若父类没有默认的构造函数，子类的构造函数又未调用父类的构造函数，则无法编译</mark>
    意思是,像我们上面的代码,父类写了个构造函数,那系统就没有默认的构造函数了
    但此时我们又不在子类中显示调用自己写的父类构造函数
    (所以说,要是不写,那就调用父类默认的构造函数,前提是有默认的)
    像下面那样
    就会无法编译
```cpp
class xiaoLv : public Qiang{
public:
    xiaoLv(const std::string& name_,const int speed_,const int hit_,const  int a_):a(a_){  //这里要写上调用父类构造函数
        std::cout << "xiaoLv()" << std::endl;
    }
private:
    int a; //随便取的
}
```
