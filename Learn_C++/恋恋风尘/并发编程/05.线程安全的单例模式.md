# 局部静态变量

利用静态局部变量实现单例
静态局部变量(一个函数中定义一个局部静态变量，那么这个局部静态变量只会在函数第一次调用的时候初始化一次，以后无论调用几次这个函数，函数内的局部静态变量都不再初始化)
```cpp
class Single2 {
private:
    Single2() {}  //普通构造

    //拷贝构造,拷贝赋值删了
    Single2(const Single2&) = delete;  
    Single2& operator=(const Single2&) = delete;
public:

    //只有这个公用的静态方法
    static Single2& GetInst() {
        static Single2 single; //类里初始化一个实例(静态的,所以不会重复初始化,只会有一个)
        return single;  //返回实例的引用
    }
};
```
上述版本的单例模式在C++11 以前存在多线程不安全的情况，多个线程几乎同时调用GetInst的时候,编译器可能会初始化多个静态变量。 
但是C++11推出以后，各厂商优化编译器，能保证上面的版本线程安全。
<mark style="background: #FFF3A3A6;">所以其实这样写就行了</mark>

(下面介绍的几种,是C++11 以前,大家做的一些优化上面代码的尝试,可以看看,  但是不用太记住,因为上面那样写就好了)

# 饿汉式初始化

就是在主线程启动后，其他线程没有启动前，由主线程先初始化单例资源，这样其他线程获取的资源就不涉及重复初始化的情况了。
```cpp
//饿汉式
class Single2Hungry {
private:
    //和前面一样
    Single2Hungry() {}
    Single2Hungry(const Single2Hungry&) = delete;
    Single2Hungry& operator=(const Single2Hungry&) = delete;
public:
    static Single2Hungry* GetInst() {  //传出去的是指针
        if (single == nullptr) //如果单例类还没有实例化
        {
            single = new Single2Hungry();  //那就实例化一个
        }
        return single;
    }
private:
    static Single2Hungry* single;
};
```

调用
```cpp
//饿汉式初始化
//主线程直接初始化(不管现在用不用单例实例)
Single2Hungry* Single2Hungry::single = Single2Hungry::GetInst();

void thread_func_s2(int i)
{
    std::cout << "this is thread " << i << std::endl;
    std::cout << "inst is " << Single2Hungry::GetInst() << std::endl;
}
void test_single2hungry()
{
    //因为GetInst传回来的是指针,直接打印就得到static single的地址
    //检查到这里两次调用GetInst,得到的single地址相同
    std::cout << "s1 addr is " << Single2Hungry::GetInst() << std::endl;
    std::cout << "s2 addr is " << Single2Hungry::GetInst() << std::endl;
    for (int i = 0; i < 3; i++)
    {
        //得到子线程中得到的single地址相同
        std::thread tid(thread_func_s2, i);
        tid.join();
    }
}
```
饿汉式是从<mark style="background: #FFF3A3A6;">使用角度规避多线程的安全问题</mark>，很多情况下我们很难从规则角度限制开发人员，所以这种方式不是很推荐。

# 懒汉式初始化

用的时候再初始化,不像上面一开始就要初始化
此时就会出现多个线程同时初始化static single的问题
所以需要加锁
```cpp
class SinglePointer {
private:
    //和前面一样
    Single2Hungry() {}
    Single2Hungry(const Single2Hungry&) = delete;
    Single2Hungry& operator=(const Single2Hungry&) = delete;
public:
    static SinglePointer* GetInst() {
        if (single != nullptr) {  //已经实例化了,就直接返回
            return single;
        }

        //没有实例化就加锁
        s_mutex.lock();
        //但是万一两个实例同时判断到没有实例化,A先加锁,生成了实例,然后解锁,此时B加锁,B就不应该再次实例化
        //所以要再判断一次,有没有实例化
        if (single != nullptr) {
            s_mutex.unlock();  //实例化了,那就先解锁(记得解锁!),再直接返回
            return single;
        }

        //上面都没问题,实例化
        single = new SinglePointer();
        s_mutex.unlock();
        return single;
    }
private:
    static SinglePointer* single;
    static std::mutex s_mutex;
};
```

调用
```cpp
//static的成员变量需要主线程先定义
SinglePointer* SinglePointer::single = nullptr;
std::mutex SinglePointer::s_mutex;

//其他做法和饿汉式相同
void thread_func_lazy(int i)
{
    std::cout << "this is lazy thread " << i << std::endl;
    std::cout << "inst is " << SinglePointer::GetInst() << std::endl;
}
void test_singlelazy()
{
    for (int i = 0; i < 3; i++)
    {
        std::thread tid(thread_func_lazy, i);
        tid.join();
    }
    //何时释放new的对象？造成内存泄漏
}
```
但是懒汉式存在问题,就是不知道哪个子线程new的single实例,所以不知道delete要写哪里
都写的话就多重析构了
上面饿汉式就在主线程中delete就好了

# 智能指针

针对上面delete不知道写哪里的问题,有了智能指针的写法
用shared_ptr
每次多调用一次GetInst,就多得到一个智能指针指向single
智能指针可能有多个,但是single只有一个
最后智能指针会自动析构,当single引用计数为0的时候,会自动delete
```cpp
//可以利用智能指针完成自动回收

class SingleAuto {
private:
    //和前面一样
    SingleAuto() {}
    SingleAuto(const SingleAuto&) = delete;
    SingleAuto& operator=(const SingleAuto&) = delete;
public:
    ~SingleAuto() {
        std::cout << "single auto delete success " << std::endl;
    }

    //返回一个shared_ptr,指向static single
    static std::shared_ptr<SingleAuto> GetInst() {
        if (single != nullptr) {  //已经实例化了,就直接返回
            return single;
        }

        //没有实例化就加锁
        s_mutex.lock();
        //但是万一两个实例同时判断到没有实例化,A先加锁,生成了实例,然后解锁,此时B加锁,B就不应该再次实例化
        //所以要再判断一次,有没有实例化
        if (single != nullptr) {
            s_mutex.unlock(); //实例化了,那就先解锁(记得解锁!),再直接返回
            return single;
        }

        //上面都没问题,就实例化
        single = std::shared_ptr<SingleAuto>(new SingleAuto);
        s_mutex.unlock();
        return single;
    }
private:
    //懒汉式是直接使用指针
    //static SinglePointer* single;
    //这里用智能指针中的shared_ptr包裹 single
    //对single的使用还是一样的,就是初始化的时候写法不一样
    static std::shared_ptr<SingleAuto> single; 
    static std::mutex s_mutex;
};
```

调用

```cpp
//为了规避用户手动释放内存，可以提供一个辅助类帮忙回收内存
//并将单例类的析构函数写为私有

class SingleAutoSafe;
class SafeDeletor {  //辅助类
public:
    //实现仿函数
    void operator()(SingleAutoSafe* sf) {
        std::cout << "this is safe deleter operator()" << std::endl;
        delete sf;  //调用SingleAutoSafe的析构函数
        //因为SafeDeletor是SingleAutoSafe的友元,所以可以调用私有的析构函数
    }
};

class SingleAutoSafe {
private:
    SingleAutoSafe() {}
    ~SingleAutoSafe() {  //让析构函数变成私有的
        std::cout << "this is single auto safe deletor" << std::endl;
    }
    SingleAutoSafe(const SingleAutoSafe&) = delete;
    SingleAutoSafe& operator=(const SingleAutoSafe&) = delete;
    
    //定义友元类，通过友元类调用该类析构函数
    //SafeDeletor就可以访问SingleAutoSafe的私有函数
    friend class SafeDeletor;
public:
    static std::shared_ptr<SingleAutoSafe> GetInst() {
        if (single != nullptr) {
            return single;
        }
        
        s_mutex.lock();
        if (single != nullptr)
        {
            s_mutex.unlock();
            return single;
        }
        
        //额外指定删除器(就是在第二个参数中传入SafeDeletor())  
        //传入SafeDeletor(),是先实例化一个SafeDeletor对象
        //因为实现了仿函数,所以智能指针可以像函数那样调用SafeDeletor对象
        //然后这个函数的参数,是我们前面传的new SingleAutoSafe
        single = std::shared_ptr<SingleAutoSafe>(new SingleAutoSafe, SafeDeletor());
        //也可以指定删除函数
        // single = std::shared_ptr<SingleAutoSafe>(new SingleAutoSafe, SafeDelFunc);
        
        s_mutex.unlock();
        return single;
    }
private:
    static std::shared_ptr<SingleAutoSafe> single;
    static std::mutex s_mutex;
};
```

```cpp
public:

    {
```

比如懒汉式的使用方式，当多个线程调用单例时，
有一个线程加锁进入3处的逻辑。 
其他的线程有的在1处，判断指针非空则跳过初始化直接使用单例的内存会存在问题。 
主要原因在于`SingleAutoSafe * temp = new SingleAutoSafe()` 这个操作是由三部分组成的 
1. 调用allocate开辟内存 
2. 调用construct执行SingleAutoSafe的构造函数 
3. 调用赋值操作将地址赋值给temp
<mark style="background: #FFF3A3A6;">有可能在一些编译器中通过优化是1，3，2的调用顺序</mark>
所以其他的线程有的在1处, 取到的指针其实还没有构造好，就会造成不可预知错误。

# call_once

所以上面的单例类写法,已经被淘汰了
C++11 提出了`call_once`函数，我们可以配合一个局部的静态变量`once_flag`实现线程安全的初始化
```cpp
class SingletonOnce {
private:
    SingletonOnce() = default;
    SingletonOnce(const SingletonOnce&) = delete;
    SingletonOnce& operator = (const SingletonOnce& st) = delete;
    static std::shared_ptr<SingletonOnce> _instance;  //还是用智能指针

public :
    static std::shared_ptr<SingletonOnce> GetInstance() {
        static std::once_flag s_flag;  //初始为一个叫"未触发"的状态(false)
        std::call_once(s_flag, [&]() {
            _instance = std::shared_ptr<SingletonOnce>(new SingletonOnce);
            });  //std::call_once执行后会改变s_flag的值

        return _instance;
    }

    void PrintAddress() {
        std::cout << _instance.get() << std::endl;
    }

    ~SingletonOnce() {
        std::cout << "this is singleton destruct" << std::endl;
    }
};

std::shared_ptr<SingletonOnce> SingletonOnce::_instance = nullptr;
```

为了让单例更加通用，可以做成模板类
```cpp
template <typename T>  //就是这里用一个T代表单例类中,数据实际的类型
class Singleton {
protected:
    Singleton() = default;
    Singleton(const Singleton<T>&) = delete;  //注意模版类需要多写一个<T>
    Singleton& operator=(const Singleton<T>& st) = delete;
    static std::shared_ptr<T> _instance;  //智能指针实际包裹的是T类型
public:
    static std::shared_ptr<T> GetInstance() { //注意模版类需要多写一个<T>
        static std::once_flag s_flag;
        std::call_once(s_flag, [&]() {
            _instance = std::shared_ptr<T>(new T);
            });
        return _instance;
    }
    void PrintAddress() {
        std::cout << _instance.get() << std::endl;
    }
    ~Singleton() {
        std::cout << "this is singleton destruct" << std::endl;
    }
};

template <typename T>
std::shared_ptr<T> Singleton<T>::_instance = nullptr;  //注意模版类需要多写一个<T>
```
