# 线程可见顺序

前面说除了`memory_order_seq_cst`顺序，其他的顺序都不能保证原子变量修改的值在其他多线程中看到的顺序是一致的。
但是可以通过同步机制保证一个线程对原子变量的修改对另一个原子变量可见。

有时候我们线程1对A的store操作采用release内存序，而线程2对B的load采用acquire内存序，并不能保证A 一定比 B先执行。
(注意前面是对同一个变量采用release和acquire内存序,当然能保证同步)
<mark style="background: #FFF3A3A6;">(但是不同原子变量,是不能保证同步的)
因为两个线程并行执行无法确定先后顺序，</mark>
```cpp
#include <iostream>
#include <atomic>
#include <thread>
#include <cassert>
std::atomic<bool> x, y;
std::atomic<int> z;

void write_x()
{
    x.store(true, std::memory_order_release); //1
}
void write_y()
{
    y.store(true, std::memory_order_release); //2
}
void read_x_then_y()
{
    //x为true时 退出循环
    while (!x.load(std::memory_order_acquire));
    //y为true时  z++
    if (y.load(std::memory_order_acquire))   //3
        ++z;
}
void read_y_then_x()
{
    //y为true时 退出循环
    while (!y.load(std::memory_order_acquire));
    //x为true时  z++
    if (x.load(std::memory_order_acquire))   //4
        ++z;
}
```

调用
```cpp
void TestAR()
{
    x = false;
    y = false;
    z = 0;
    std::thread a(write_x);
    std::thread b(write_y);
    std::thread c(read_x_then_y);
    std::thread d(read_y_then_x);
    a.join();
    b.join();
    c.join();
    d.join();
    //断言z永远不会等于0
    assert(z.load() != 0); //5
    std::cout << "z value is " << z.load() << std::endl;
}
```
结果
    ![[Pasted image 20250717163110.png]]

有的读者可能会觉5处的断言不会被触发，
他们认为c和d肯定会有一个线程对z执行++操作。
1 如果c线程执行read_x_then_y没有对z执行加加操作，那么说明c线程读取的x值为true, y值为false。 
2 之后d线程读取时，如果保证执行到4处说明y为true，此时x必然为true。 
理应是  x先被store为true，y后被store为true，c线程看到y为false时x已经为true了，那么d线程y为true时x也早就为true了，所以z一定会执行加加操作。

但是上述理解是不正确的
<mark style="background: #FFF3A3A6;">即便是releas和acquire顺序也不能保证多个线程看到的一个变量的值是一致的，更不能保证看到的多个变量的值是一致的。</mark>
前几节用release和acquire能保证同步, 主要原因是把写x和y放在了一个线程里
而这里是拆成了线程a,b  就是两个线程   
所以a,b线程的执行顺序是不一定的
所以不能保证同步!!!

所以如果按下面的情况执行
那就可能引发断言报错
![[Pasted image 20250717163754.png]]
就是线程a过后是线程c
线程b过后是线程d
线程c"没看见"线程b的执行结果
线程d"没看见"线程a的执行结果
就会导致z都不会被++

可能内部此时是这种情况
![[Pasted image 20250717164036.png]]
cpu1,2,3,4分别运行a,c,b,d
然后a,b先运行 结果写进cache  正好被cpu2,4读到

所以  总结
<mark style="background: #FFF3A3A6;">即使我们采用release和acquire方式也不能保证全局顺序一致。</mark>
<mark style="background: #FFF3A3A6;">如果一个线程对变量执行release内存序的store操作，另一个线程不一定会马上读取到</mark>

# 栅栏

可以通过栅栏保证指令编排顺序

下面的代码都采用的是`memory_order_relaxed`
 所以无法保证a线程将x,y修改后b线程看到的也是先修改x，再修改y的值。
 b线程可能先看到y被修改为true，x后被修改为true
```cpp
#include <atomic>
#include <thread>
#include <assert.h>
std::atomic<bool> x,y;
std::atomic<int> z;

void write_x_then_y()
{
    x.store(true,std::memory_order_relaxed); // 1
    y.store(true,std::memory_order_relaxed);   // 2
}
void read_y_then_x()
{
    while(!y.load(std::memory_order_relaxed));  // 3
    if(x.load(std::memory_order_relaxed))  // 4
        ++z;
}

int main()
{
    x=false;
    y=false;
    z=0;
    std::thread a(write_x_then_y);
    std::thread b(read_y_then_x);
    a.join();
    b.join();
    assert(z.load()!=0);  //5
}
```

之前我们知道  可以通过`std::memory_order_release`和`std::memory_order_acquire`形成同步关系。
下面就不会触发断言报错
```cpp
void write_x_then_y3()
{
    x.store(true, std::memory_order_relaxed); // 1
    y.store(true, std::memory_order_release);   // 2
}

void read_y_then_x3()
{
    while (!y.load(std::memory_order_acquire));  // 3
    if (x.load(std::memory_order_relaxed))  // 4
        ++z;
}
```

下面是使用栅栏的代码
实现的效果和上面是一样的  都不会触发断言报错
```cpp
void write_x_then_y_fence()
{
    x.store(true, std::memory_order_relaxed);  //1
    std::atomic_thread_fence(std::memory_order_release);  //2
    y.store(true, std::memory_order_relaxed);  //3
}

void read_y_then_x_fence()
{
    while (!y.load(std::memory_order_relaxed));  //4
    std::atomic_thread_fence(std::memory_order_acquire); //5
    if (x.load(std::memory_order_relaxed))  //6
        ++z;
}
```
