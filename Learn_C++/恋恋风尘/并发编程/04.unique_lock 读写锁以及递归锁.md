# unique_lock

和`lock_guard`基本用法相同，构造时默认加锁，析构时默认解锁
<mark style="background: #FFF3A3A6;">`unique_lock`有个好处就是可以手动解锁</mark>
```cpp
//unique_lock 基本用法
std::mutex mtx;
int shared_data = 0;

void use_unique() {
    //unique_lock可自动解锁，也可手动解锁
    std::unique_lock<std::mutex> lock(mtx);  //和lock_guard一样用
    std::cout << "lock success" << std::endl;
    shared_data++;
    lock.unlock();  
    //不手动解锁,作用域结束会自动解锁
}
```

可以通过`unique_lock`的`owns_lock`判断是否持有锁
```cpp
std::mutex mtx;
int shared_data = 0;

//可判断是否占有锁
void my_owns_lock() {
    //lock可自动解锁，也可手动解锁
    std::unique_lock<std::mutex> lock(mtx);  //上锁,lock此时持有mtx,或者说管理mtx
    shared_data++;
    if (lock.owns_lock()) {
        std::cout << "owns lock" << std::endl;
    }
    else {
        std::cout << "doesn't own lock" << std::endl;
    }

    lock.unlock();  //解锁了,就不持有mtx了
    if (lock.owns_lock()) {
        std::cout << "owns lock" << std::endl;
    }
    else {
        std::cout << "doesn't own lock" << std::endl;
    }
}
```

`unique_lock`还可以延迟加锁
```cpp
std::mutex mtx;
int shared_data = 0;

 //可以延迟加锁
void defer_lock() {
    //延迟加锁
    std::unique_lock<std::mutex> lock(mtx, std::defer_lock); //就是现在先不加锁
    
    //这里再可以加锁
    lock.lock();
    //可以自动析构解锁，也可以手动解锁
    lock.unlock();
}
```


综合运用`owns_lock`和`defer_lock`
```cpp
std::mutex mtx;
int shared_data = 0;

//同时使用owns和defer
void use_own_defer() {
    //主线程中加锁
    std::unique_lock<std::mutex> lock(mtx);
    
    // 判断是否拥有锁
    if (lock.owns_lock())
    {
        std::cout << "Main thread has the lock." << std::endl;
    }
    else
    {
        std::cout << "Main thread does not have the lock." << std::endl;
    }

    //搞个子线程
    std::thread t([]() {
        //子线程延迟加锁
        std::unique_lock<std::mutex> lock(mtx, std::defer_lock);  

        // 判断是否拥有锁
        if (lock.owns_lock())
        {
            std::cout << "Thread has the lock." << std::endl;
        }
        else
        {
            std::cout << "Thread does not have the lock." << std::endl;
        }

        // 子线程加锁
        //但是这里应该加不上,因为看下面有个t.join();
        //就是要等子线程结束,主线程才能执行到大括号,然后把锁释放
        //那子线程就永远执行不下去(就卡在这里)
        lock.lock();

        // 判断是否拥有锁
        if (lock.owns_lock())
        {
            std::cout << "Thread has the lock." << std::endl;
        }
        else
        {
            std::cout << "Thread does not have the lock." << std::endl;
        }

        // 解锁
        lock.unlock();
        });
    
    t.join();
}
```


`unique_lock`也支持领养锁
```cpp
//同样支持领养操作
void use_own_adopt() {
    mtx.lock();  //先把mtx锁起来(为了演示下面的领养锁)
    std::unique_lock<std::mutex> lock(mtx, std::adopt_lock); //领养锁(之后自动释放锁)
    if (lock.owns_lock()) {  
        std::cout << "owns lock" << std::endl;  //会打印这个,此时是算占用锁的
    }
    else {
        std::cout << "does not have the lock" << std::endl;
    }
    lock.unlock();
}
```

如果这样,就只领养,不加锁
那执行到unlock的时候,程序会崩溃
因为不能对没加锁的锁 解锁

还记得上一节课的swap吗(`safe_swap函数`) [[03.互斥和死锁]]
`unique_lock`支持领养操作也支持延迟加锁，那么可以用两种方式实现前文中出现的 
`lock_guard`实现的`swap`操作
```cpp
//之前的交换代码可以可以用如下方式等价实现
int a = 10;  //上一节用的是很复杂的数据结构,这里简化成int
int b = 99;
std::mutex  mtx1;
std::mutex  mtx2;

void safe_swap() {
    std::lock(mtx1, mtx2); //一次性上两把锁
    std::unique_lock<std::mutex> lock1(mtx1, std::adopt_lock); //然后unique_lock领养
    std::unique_lock<std::mutex> lock2(mtx2, std::adopt_lock);
    std::swap(a, b);  //到这里,因为锁都上了,所以可以放心交换
    
    //错误用法
    //这里不能用mtx1和mtx2解锁,会崩溃
    //mtx1.unlock();
    //mtx2.unlock();

    //这样手动解锁时对的
    //lock1.unlock();
    //lock2.unlock();
}

void safe_swap2() {
    //也可以先unique_lock包裹,然后延迟加锁
    std::unique_lock<std::mutex> lock1(mtx1, std::defer_lock);
    std::unique_lock<std::mutex> lock2(mtx2, std::defer_lock);
    
    //一次性上两把锁
    //注意此时是对lock1,lock2上锁(和上面做对比)
    std::lock(lock1, lock2);  
    //错误用法
    //std::lock(mtx1, mtx2);
    
    std::swap(a, b);
}
```
总结注意: <mark style="background: #FFF3A3A6;">一旦mutex被unique_lock管理，加锁和释放的操作就交给unique_lock，不能调用mutex加锁和解锁</mark>


<mark style="background: #FFF3A3A6;">mutex是不支持移动和拷贝的(移动也不支持!!!)，但是unique_lock支持移动</mark>
(看源码,mutex的拷贝构造 拷贝赋值都被删了 而且又没写移动构造 移动赋值, 所以拷贝,移动都不支持[[触发移动构造,移动赋值的时机]])
(unique_lock源码里有移动构造和移动赋值 同样删掉了拷贝构造 拷贝赋值, 所以不能支持拷贝,只支持移动)
实现锁的转移
```cpp
//转移互斥量所有权
//互斥量本身不支持move操作，但是unique_lock支持
std::unique_lock <std::mutex> get_lock() {
    std::unique_lock<std::mutex> lock(mtx);  //定义了局部的lock
    shared_data++;
    return lock;  //返回lock,出了作用域以后自动解锁
}

void use_return() {
    //调用上面的函数
    //上面返回的lock,会以移动的方式,生成一个临时变量,然后再移动给这里的lock
    std::unique_lock<std::mutex> lock(get_lock());
    shared_data++;
}
```

**锁的粒度**表示加锁的精细程度
一个锁的粒度要足够大，保证可以锁住要访问的共享数据。
一个锁的粒度要足够小，保证非共享数据不被锁住
(就是只锁必要的,其他的能不锁就不锁)
```cpp
void precision_lock() {
    std::unique_lock<std::mutex> lock(mtx);
    shared_data++;
    lock.unlock();  //不把锁留到最后自动解锁,这里就手动解锁
    
    //涉及共享数据,并且比较耗时的操作,就不要放在锁内执行
    std::this_thread::sleep_for(std::chrono::seconds(1));

    //要碰共享资源了,再加锁
    lock.lock();
    shared_data++;
}
```

# 共享锁

共享锁,可以用C++17标准提出的`std::shared_mutex`,`std::shared_lock`
或者 C++14标准可以使用`std::shared_time_mutex`

在一个服务器中的数据,读操作不需要加锁,好多线程可以一起读,但是读的时候不允许写
写的时候,只有一个人可以写,并且写的时候不允许其他人读
总结就是  <mark style="background: #FFF3A3A6;">读和读共享  读和写互斥  写和写互斥</mark>
```cpp
class DNService {
public:
    DNService() {}
    //读操作采用共享锁
    std::string QueryDNS(std::string dnsname) {
        //std::shared_mutex要配套使用std::shared_lock,实现共享
        std::shared_lock<std::shared_mutex> shared_locks(_shared_mtx);

        //读操作
        auto iter = _dns_info.find(dnsname);  
        if (iter != _dns_info.end()) {
            return iter->second;
        }
        return "";
    }

    //写操作采用独占锁
    void AddDNSInfo(std::string dnsname, std::string dnsentry) {
        //独占锁,就正常用lock_guard
        std::lock_guard<std::shared_mutex> guard_locks(_shared_mtx);
        
        //写操作
        _dns_info.insert(std::make_pair(dnsname, dnsentry));  
    }
private:
    std::map<std::string, std::string> _dns_info;  //假装这就是服务器数据
    mutable std::shared_mutex _shared_mtx;  //共享锁的mutex
};
```

# 递归锁

有时候我们在实现接口的时候内部加锁，接口内部调用完结束自动解锁。
会出现一个接口调用另一个接口的情况，
如果用普通的`std::mutex`就会出现卡死，因为嵌套加锁导致卡死。
可以使用递归锁。(但是不推荐使用)
```cpp
class RecursiveDemo {
public:
    RecursiveDemo() {} //默认构造

    //查询学生的操作
    bool QueryStudent(std::string name) {
        //查询之前上锁
        std::lock_guard<std::recursive_mutex> recursive_lock(_recursive_mtx);

        //查询操作(可以不用太关注)
        auto iter_find = _students_info.find(name);
        if (iter_find == _students_info.end()) {
            return false;
        }
        return true;
    }

    //给学生添加成绩
    void AddScore(std::string name, int score) {
        //先上锁
        std::lock_guard<std::recursive_mutex> recursive_lock(_recursive_mtx);
        
        if (!QueryStudent(name)) { //先查有没有这个人(里面是对同一个_recursive_mtx加锁)
            _students_info.insert(std::make_pair(name, score));
            return;
        }

        _students_info[name] = _students_info[name] + score;
    }

    //不推荐上面那种做法,使用递归锁
    //推荐下面的做法,就是不封装成两个函数,一个函数实现整个功能,就只用上一把锁
    void AddScoreAtomic(std::string name, int score) {
        //加锁(可以就加普通的锁)
        std::lock_guard<std::recursive_mutex> recursive_lock(_recursive_mtx);

        //查询+添加成绩
        auto iter_find = _students_info.find(name);
        if (iter_find == _students_info.end()) {
            _students_info.insert(std::make_pair(name, score));
            return;
        }

        _students_info[name] = _students_info[name] + score;
        return;
    }
private:

    std::map<std::string, int> _students_info;
    std::recursive_mutex _recursive_mtx;
};
```

因为不能一个锁  锁两次
