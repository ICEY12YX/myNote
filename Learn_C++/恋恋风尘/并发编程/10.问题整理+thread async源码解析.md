# 局部变量返回值
当函数返回一个类类型的局部变量时会先调用移动构造，如果没有移动构造再调用拷贝构造。 
```cpp
class TestCopy {
public:
	TestCopy() {}
	TestCopy(const TestCopy& tp) {
		std::cout << "Test Copy Copy " << std::endl;
	}
	TestCopy(TestCopy&& cp) {
		std::cout << "Test Copy Move " << std::endl;
	}
};

TestCopy TestCp() {
	TestCopy tp;
	return tp;
}

int main() {
	TestCp();

	return 0;
}
```
但是我运行代码,没有返回任何
最终没有输出任何内容的原因与 **返回值优化（RVO, Return Value Optimization）** 有关

如果按上面说的,会优先调用移动构造,这是有好处的

比如unique_ptr,thread线程
```cpp
std::unique_ptr<int> ReturnUniquePtr() {
    std::unique_ptr<int>  uq_ptr = std::make_unique<int>(100);
    return  uq_ptr; //返回局部变量
}

std::thread ReturnThread() {
    std::thread t([]() {
        int i = 0;
        while (true) {
            std::cout << "i is " << i << std::endl;
            i++;
            if (i == 5) {
                break;
            }
            std::this_thread::sleep_for(std::chrono::seconds(1));
        }
        });

    return t;
}

int main(){
    auto rt_ptr = ReturnUniquePtr();  //自动调用移动构造
    std::cout << "rt_ptr value is " << *rt_ptr << std::endl;
    std::thread rt_thread = ReturnThread(); //自动调用移动构造
    rt_thread.join();
    return 0;
}
```

# async注意事项

`async`时，其实其内部调用了`thread`,`pacakged_task`,`future`等机制。
`async`会返回一个`future`这个`future`会在被析构时等待其绑定的线程任务是否执行完成。
```cpp
void BlockAsync() {
    std::cout << "begin block async" << std::endl;
    {
        std::async(std::launch::async, []() {
            std::this_thread::sleep_for(std::chrono::seconds(3));
            std::cout << "std::async called " << std::endl;
            });  //std::async实际会返回一个future,可以接收或直接这样没有变量接收
            //没有变量接收的话,这里就是一个临时的future
            //临时的future要出大括号,析构的时候,会等待绑定的线程结束
            //达到阻塞的效果
            //相当于启动线程,并且自动调用join了
    }
    std::cout << "end block async" << std::endl;
}
```

这个看上去很简单
但是会存在隐患
比如下面的代码
```cpp
void DeadLock() {
    std::mutex  mtx;
    std::cout << "DeadLock begin " << std::endl;
    std::lock_guard<std::mutex>  dklock(mtx);
    {
        std::future<void> futures = std::async(std::launch::async, [&mtx]() {
            std::cout << "std::async called " << std::endl;
            std::lock_guard<std::mutex>  dklock(mtx);
            std::cout << "async working...." << std::endl;
            });
    }

    std::cout << "DeadLock end " << std::endl;
}
```
我们原本想实现
主线程上锁以后,启动一个异步子线程,子线程里等主线程解锁以后,加锁

但是上面的代码没有办法实现,因为future析构的时候,子线程没完成就会阻塞在那里
而主线程也没办法前进, 就会导致死锁

要改的话
改成下面的样子就不会死锁
就是让std::future是主线程中的变量,这样作用域结束,也不会调用future的析构,就不会阻塞了
```cpp
void DeadLock() {
	std::mutex  mtx;
	std::cout << "DeadLock begin " << std::endl;
	std::lock_guard<std::mutex>  dklock(mtx);
	std::future<void> f;
	{
		f = std::async(std::launch::async, [&mtx]() {
			std::cout << "std::async called " << std::endl;
			std::lock_guard<std::mutex>  dklock(mtx);
			std::cout << "async working...." << std::endl;
			});
	}

	std::cout << "DeadLock end " << std::endl;
}
```

需求:
1. func1 中要异步执行asyncFunc函数。
2. func2中先收集asyncFunc函数运行的结果，只有结果正确才执行
3. func1启动异步任务后继续执行，执行完直接退出不用等到asyncFunc运行完
```cpp
int asyncFunc() {
    std::this_thread::sleep_for(std::chrono::seconds(3));
    std::cout << "this is asyncFunc" << std::endl;
    return 0;
}

void func1(std::future<int>& future_ref) {
    std::cout << "this is func1" << std::endl;
    future_ref = std::async(std::launch::async, asyncFunc);  //异步执行asyncFunc
    //(因为future_ref是外部传进来的引用,所以不会触发析构)
}

void func2(std::future<int>& future_ref) {
    std::cout << "this is func2" << std::endl;
    auto future_res = future_ref.get();
    if (future_res == 0) {
        std::cout << "get asyncFunc result success !" << std::endl;
    }
    else {
        std::cout << "get asyncFunc result failed !" << std::endl;
        return;
    }
}
```

如果想实现一个纯异步的线程
我们可以下面这样封装一层
```cpp
template<typename Func, typename... Args  >
//万能引用+尾置类型推导
auto ParallenExe(Func&& func, Args && ... args) -> std::future<decltype(func(args...))> {

    typedef decltype(func(args...))  RetType;
    
    //搞一个无参的回调函数bind_func(返回类型是RetType,并且无参传入)
    std::function<RetType()> bind_func = std::bind(std::forward<Func>(func), std::forward<Args>(args)...);
    //上面绑定好的回调函数传入packaged_task(注意这里也要指明回调函数类型)
    std::packaged_task<RetType()> task(bind_func);
    //从packaged_task先得到future
    auto rt_future = task.get_future();
    //把回调移动到线程中(让线程去接管)
    std::thread t(std::move(task));

    t.detach();  //真正实现异步

    return rt_future;
}

void TestParallen1() {
    int i = 0;
    std::cout << "Begin TestParallen1 ..." << std::endl;

    //大括号外可以算主线程,大括号内算子线程
    {
        ParallenExe([](int i) {  //因为ParallenExe内部调用了detach
            while (i < 3) {
                i++;
                std::cout << "ParllenExe1 thread func " << i << " times" << std::endl;
                std::this_thread::sleep_for(std::chrono::seconds(1));
            }
            }, i);
    }

    std::cout << "End TestParallen1 ..." << std::endl;
}

//第二种方式
void TestParallen2() {
    int i = 0;
    std::cout << "Begin TestParallen2 ..." << std::endl;

    auto rt_future = ParallenExe([](int i) {
            while (i < 3) {
                i++;
                std::cout << "ParllenExe thread func " << i << " times" << std::endl;
                std::this_thread::sleep_for(std::chrono::seconds(1));
            }
            }, i);

    std::cout << "End TestParallen2 ..." << std::endl;

    rt_future.wait(); //明确等待任务完成(这样main里可以不用睡一会)
    //就是上面两句cout和ParallenExe启动的子线程  这俩是异步执行的
    //执行到wait以后,会先等ParallenExe子线程中future的结果,执行完以后等到结果了,再往下执行
    //相当于这里手动阻塞了,但是上面仍然是异步在执行
}

int main()
{
    TestParallen1();
    //TestParallen2()
    //睡一会,为了让主线程结束的晚一点,等待子线程执行完
    std::this_thread::sleep_for(std::chrono::seconds(4));
    std::cout << "Main Exited!\n";
}
```
