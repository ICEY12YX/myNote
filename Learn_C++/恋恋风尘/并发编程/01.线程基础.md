# 线程发起

```cpp
void thead_work1(std::string str) {
    std::cout << "str is " << str << std::endl;
}

std::string hellostr = "hello";

//1 通过()初始化并启动一个线程
std::thread t1(thead_work1, hellostr);
```
thead_work1可以理解为回调函数
定义线程的时候 `t1(thead_work1, hellostr)`  先传入回调函数的地址,后传入回调函数的参数
因为C++会对普通函数有优化(thead_work1是个普通函数), 普通函数名就是函数的地址
当然也可以传入 `&thead_work1` 就是真正意义上的函数地址

# 线程的等待

如果直接这样写,启动线程,可能会报错
```cpp
void thead_work1(std::string str) {
    std::cout << "str is " << str << std::endl;
}

int main(){
    std::string hellostr = "hello";

    //1 通过()初始化并启动一个线程
    std::thread t1(thead_work1, hellostr);
}
```
因为 `t1` 线程可能来不及执行
或者 主线程执行完,释放资源了,然后子线程没法使用资源了

那改成这样行不行?
让主线程睡一会(就是等几秒再结束)
```cpp
void thead_work1(std::string str) {
    std::cout << "str is " << str << std::endl;
}

int main(){
    std::string hellostr = "hello";

    //1 通过()初始化并启动一个线程
    std::thread t1(thead_work1, hellostr);
    //主线程睡1秒
    std::this_thread::sleep_for(std::chrono::seconds(1));  
    //先记住这个语法!!!线程睡觉都是这么写的,记住就行
}
```
发现程序还是会崩溃
这个和睡了几秒没关系
因为 线程做了优化
主线程发现子线程没有被join或detach -> 主线程回收资源的时候,就会调用子线程的析构函数 -> 析构函数里有个terminate函数,里面有个assert断言会导致崩溃
所以不能这样做

所以用join
```cpp
void thead_work1(std::string str) {
    std::cout << "str is " << str << std::endl;
}

int main(){
    std::string hellostr = "hello";

    //1 通过()初始化并启动一个线程
    std::thread t1(thead_work1, hellostr);
   
    //2 主线程等待子线程退出
    t1.join();
}
```

# 仿函数作为参数

先定义一个仿函数
    仿函数可以把类当做函数用
```cpp
class background_task {
public:
    void operator()() {  //第二个括号可以先传进来的参数
        std::cout << "background_task called" << std::endl;
    }
};
```

仿函数传进子线程
```cpp
int main(){
    std::thread t2(background_task());
    t2.join();
}
```
会发现报错了,编译时报错
原因是编译器把t2当做函数来解释了(原因不明,就这么解释了)
这是正常的子线程
    ![[Pasted image 20250626004213.png]]

这是上面报错的子线程
    ![[Pasted image 20250626004240.png]]
    就是说t2是个函数, 返回std::thread类型,传入仿函数background_task()
    传入的参数background_task() 也被当做函数指针
    首先background_task() 作为仿函数, 实际会先调用这个类的构造函数 -> 构造函数生成一个对象 -> 对象传进子线程作为参数 -> 因为我们重载了()运算符,所以对象传进去以后可以当做函数来使用

仿函数的函数指针background_task() 为什么是 background_task(* )()  
    ![[Pasted image 20250626005852.png]]
    ![[Pasted image 20250626005923.png]]
    所以其实background_task(* )()不是仿函数的函数指针,而是根本就被解析错了

解决办法
加括号  或者  用{ }
```cpp
std::thread t2((background_task()));

std::thread t3{ background_task() };  
```

# 线程detach

定义一个结构体(默认里面成员都是public)
定义一个函数
```cpp
struct func {
    int& _i;  //引用类型  外部变量的引用
    
    func(int& i): _i(i){}
    
    void operator()() {  //让func可以以仿函数的方式使用
        for (int i = 0; i < 3; i++) {
            _i = i;  //不断改变_i的值  (即不断在使用外部的变量!!!)
            std::cout << "_i is " << _i << std::endl;
            
            std::this_thread::sleep_for(std::chrono::seconds(1));
        }
    }
};

void oops() {
    int some_local_state = 0;  //局部变量
    
    func myfunc(some_local_state);  //定义一个func类型的实例myfunc,然后调用构造函数(就是类的初始化一样的,只不过func是结构体)
    
    std::thread functhread(myfunc);  //创建子线程,因为上面实现了仿函数,所以这里传入的myfunc可以当做回调函数来使用
    
    //隐患，访问局部变量，局部变量可能会随着}结束而回收或随着主线程退出而回收
    functhread.detach();    
}
```
首先结构体func里的_i是用来存外部 主线程执行的函数oops里的some_local_state
当执行`_i = i; ` 的时候   oops里的some_local_state也会变

然后上面那样直接在oops里面 `functhread.detach(); ` 是个隐患
因为some_local_state是局部变量, 当oops函数调用结束后局部变量some_local_state就可能被释放了，而线程还在detach后台运行，容易出现崩溃。

```cpp
int main(){
    // detach 注意事项
    oops();
    
    //防止主线程退出过快，需要停顿一下，让子线程跑起来detach
    std::this_thread::sleep_for(std::chrono::seconds(1));
}
```
上面如果我们没有让主线程sleep几秒,那子线程会来不及detach,就被销毁了
然后我们sleep几秒后,子线程会被成功detach
![[Pasted image 20250626175119.png]]
但是依旧执行不完, 因为主线程结束了,主进程也要结束了,那所有子线程会被强制结束掉

总之,上面的例子 说明在线程中 <mark style="background: #FFF3A3A6;">慎用局部变量</mark>
(但是如果上面没有结构体,直接是个函数,然后传进去some_local_state好像就没事,因为线程内部默认有拷贝行为,下面会讲)

当我们在线程中使用局部变量的时候可以采取几个措施解决局部变量的问题:
1. 通过智能指针传递参数，因为引用计数会随着赋值增加，可保证局部变量在使用期间不被释放
2. 将局部变量的值作为参数传递，但是这样涉及到拷贝构造,就是这个局部变量需要有拷贝的能力(自己写或者它本身可以拷贝)
3. 将线程运行的方式修改为join,不写上面的detach  (但是这么做可能会影响运行逻辑。因为我们可能就想两个线程各自执行,而不是一个等一个)
用join的话, 比如下面这种修改方式
```cpp
void use_join() { 
	int some_local_state = 0; 
	func myfunc(some_local_state); 
	std::thread functhread(myfunc); 

    //join,让主线程等functhread子线程结束,这样functhread结束之前,函数就卡在这里,这样局部变量就不会提前被回收了
	functhread.join(); 
}
```

# 异常处理

```cpp
void catch_exception() {
    int some_local_state = 0;
    func myfunc(some_local_state);
    std::thread  functhread{ myfunc };
    
    try {
        //模拟主线程做的事情,假装这里会产生异常
        std::this_thread::sleep_for(std::chrono::seconds(1));
    }catch (std::exception& e) {  //到这里说明主线程产生异常
        functhread.join();  //先等子线程结束
        throw;  //再抛出异常
    }

    functhread.join();
}
```
为什么要等子线程结束,再抛出异常?
    比如一个主进程是充值的功能,子线程是将用户充值写进日志
    如果之后用户要查,没有这条日志就麻烦了

上面写异常处理相对麻烦,因为必须知道哪个线程catch里要写join
有没有办法线程"自动提前"join出来
有的,可以写点代码包裹子线程
```cpp
class thread_guard {
private:
    std::thread& _t;  //关联外部子线程(引用类型!!!)
public:
    explicit thread_guard(std::thread& t):_t(t){}  //explicit关键字可以查看补充笔记
    
    ~thread_guard() {  //析构函数
        //join只能调用一次,所以用joinable判断子线程有没有join过
        if (_t.joinable()) {  
            _t.join();
        }
    }

    //删除拷贝构造和赋值运算符(类似智能指针unique_ptr,就只有一个thread_guard实例可以接管某一个子线程,就是一对一的关系,避免多次析构)
    thread_guard(thread_guard const&) = delete;
    thread_guard& operator=(thread_guard const&) = delete;
};
```

上面`thread_guard` 用法
```cpp
void auto_guard() {
    int some_local_state = 0;
    func my_func(some_local_state);
    std::thread t(my_func);

    //上面都是一样的
    //就这里再用thread_guard包裹子线程
    thread_guard g(t);
    
    //本线程做一些事情
    std::cout << "auto guard finished " << std::endl;
}
```
用thread_guard包裹子线程以后
auto_guard函数结束, 先会调用g的析构函数,那个里面有子线程的join,所以实现了自动让主线程等待子线程

那会不会{}结束,就是函数结束以后, t先被销毁?

# 慎用隐式转换

```cpp
void print_str(int i,std::string const& s){
    std::cout << "i is" << i << "s is" << s << std::endl;
}

void danger_oops(int som_param) {
    char buffer[1024];
    sprintf(buffer, "%i", som_param);
    //在线程内部将char const* 转化为std::string
    std::thread t(print_str, 3, buffer);
    t.detach();
    
    std::cout << "danger oops finished " << std::endl;
}
```

# 引用参数
当线程的回调,接收的是引用
那主线程的some_param会因为子线程改了值,而被修改吗
```cpp
void change_param(int& param) {
    param++;
}

void ref_oops(int some_param) {
    std::cout << "before change , param is " << some_param << std::endl;
    
    std::thread  t2(change_param, some_param);
    t2.join();
    
    std::cout << "after change , param is " << some_param << std::endl;
}
```
(直接写这个代码,系统编译不过,为什么先别管)
反正上面那样写不行

要这样写,同时这样写,子线程里修改了引用,主线程会跟着改
```cpp
void change_param(int& param) {
    param++;
}

void ref_oops(int some_param) {
    std::cout << "before change , param is " << some_param << std::endl;
    
    std::thread  t2(change_param, std::ref(some_param));
    t2.join();
    
    std::cout << "after change , param is " << some_param << std::endl;
}
```

# 绑定类成员函数
子线程也可以绑定类的成员
```cpp
class X {
public:
    void do_lengthy_work() {
        std::cout << "do_lengthy_work " << std::endl;
    }
};

void bind_class_oops() {
    X my_x;
    std::thread t(&X::do_lengthy_work, &my_x);
    t.join();
}
```
如果thread绑定的回调函数是普通函数，可以在函数前加`&`或者不加`&`，因为编译器默认将普通函数名作为函数地址
但是<mark style="background: #FFF3A3A6;">如果是绑定类的成员函数，必须添加&</mark>

# 使用move操作

```cpp
//回调函数传入的参数p是unique_ptr,不能被拷贝,直接传入std::thread构造函数不行
//上面我们讲了std::thread构造函数默认会有拷贝行为!!!!!
void deal_unique(std::unique_ptr<int> p) {  
    std::cout << "unique ptr data is " << *p << std::endl;
    (*p)++;

    std::cout << "after unique ptr data is " << *p << std::endl;
}

void move_oops() {
    auto p = std::make_unique<int>(100);
    std::thread t(deal_unique, std::move(p)); //用std::move把p的所有权转移到子线程里面
    t.join();
    
    //不能再使用p了，p已经被move废弃
   // std::cout << "after unique ptr data is " << *p << std::endl;
}
```
