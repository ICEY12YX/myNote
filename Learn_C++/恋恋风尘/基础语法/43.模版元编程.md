# 编译期计算

编译期阶乘
```cpp
#include <iostream>

// 基础情况
template <int N>
struct Factorial {
    static const int value = N * Factorial<N - 1>::value;
};

// 递归终止
template <>
struct Factorial<0> {
    static const int value = 1;
};

int main() {
    std::cout << "5! = " << Factorial<5>::value << std::endl; // 输出：5! = 120
    std::cout << "0! = " << Factorial<0>::value << std::endl; // 输出：0! = 1
    return 0;
}
```
N减到最后是0
所以最后我们0,就写个特例化的版本`struct Factorial<0>`

注意
上面我们写的value成员变量是`static const`的
一般只写static,那成员变量就需要在外面先初始化
而加上const,就不用
为什么
    ![[Pasted image 20250703164408.png]]
    ![[Pasted image 20250703164426.png]]
    ![[Pasted image 20250703164514.png]]
    所以,不在类外初始化,其实它是没有地址,没有内存的
    上面我们只能给它一个值,供他在编译时期计算

然后C++17, 使用inline关键字,可以在类内对静态成员变量进行定义，无需在类外进行单独定义
```cpp
template<int N>
struct Factorial{
    inline static const int value = N * Factorial<N-1>::value;
};

//全特化
template<>
struct Factorial<0>{
    inline static const int value = 1;
};
```
这样在外面调用value的地址是可以的
在这种情况下，无需在类外进行定义，<mark style="background: #ABF7F7A6;">因为 inline 确保了该变量在每个翻译单元中都只有一个实例</mark>
    ![[Pasted image 20250703171358.png]]
    上面写的逻辑稍微有点问题
    类的静态成员变量需要在类内声明，在类外定义
    而这样做,当多个源文件包含同一个头文件时，会导致链接错误
    (因为多个源文件include一个同文件的时候,在类外定义的static变量会在多个源文件中都被定义一份)
    不是"如果不这样做"

编译期斐波那契数列
1,1,2,3,5,8,13,21....
```cpp
#include <iostream>

// 基础情况(通用模版)
template <int N>
struct Fibonacci {
    inline static const long long value = Fibonacci<N - 1>::value + Fibonacci<N - 2>::value;
};

// 递归终止 (全特化)
template <>
struct Fibonacci<0> {
    inline static const long long value = 0;
};

template <>
struct Fibonacci<1> {
    inline static const long long value = 1;
};

int main() {
    std::cout << "Fibonacci<10> = " << Fibonacci<10>::value << std::endl; // 输出：Fibonacci<10> = 55
    std::cout << "Fibonacci<20> = " << Fibonacci<20>::value << std::endl; // 输出：Fibonacci<20> = 6765
    return 0;
}
```
这里虽然不会用到static value的地址,所以其实可以不用inline直接声明+定义
但是万一别人拿到代码想调用地址
而且在外面初始化较为麻烦
直接写inline比较省事

# 类型计算与SFINAE

在编译期进行类型的推导和转换
比如类型萃取
(类型萃取 比如提取某个类型,看它能不能做加法,有没有做加法的属性)

检测类型是否可加
```cpp
#include <type_traits>

// 检测是否可以对T类型进行加法操作 (通用模版)
template <typename T, typename = void>
struct is_addable : std::false_type {};
//继承std::false_type,则::value是false

template <typename T>
struct is_addable<T, decltype(void(std::declval<T>() + std::declval<T>()))> : std::true_type {};
//继承std::true_type,则::value是true

// 使用
static_assert(is_addable<int>::value, "int should be addable");
static_assert(!is_addable<void*>::value, "void* should not be addable");
```
`decltype(void(std::declval<T>() + std::declval<T>()))`
    这句话的意思是说
    `decltype( )` 进行类型推导
    `void( )`  强制把里面转为void
    `std::declval<T>() + std::declval<T>()` 把T类型加起来,要是不能相加,就会触发SFINAE
    详细解释
    ![[Pasted image 20250703174030.png]]
    std::declval可以在不创建T类型实例(或者说对象)的情况下,搞出来一个T的右值引用
    因为直接写T+T肯定是不行的

# 高级模板元编程技巧

使用变参模板

变参求和
```cpp
// 基本递归模板 (默认模版)
template <int... Ns>
struct Sum;  //只用下面的偏特化版本,那默认的版本可以就声明,里面不写

// 递归终止  (全特化)
template <>
struct Sum<> {
    static const int value = 0;
};

// 递归定义 (偏特化)
//就是把int... Ns,拆成了第一个和后面一串,后面一串是新的... Ns
template <int N, int... Ns>  
struct Sum<N, Ns...> {
    static const int value = N + Sum<Ns...>::value;
    //递归写法,要记住
};

// 使用
int main() {
    int result = Sum<1, 2, 3, 4, 5>::value; // 15
    return 0;
}
```
之前都是写`template <typename... Args>`  类型变参
这里写`template <int... Ns>`  所以也可以指定类型,然后可变个参数

<mark style="background: #FFF3A3A6;">全特化一般都用在对值有明确的指定上(可以对比上面的代码,发现0,1这样指定值用的都是全特化)</mark>

类型列表和元素访问
```cpp
// 定义类型列表
template <typename... Ts>
struct TypeList {};

// 获取类型列表中第N个类型  (通用版本)
template <typename List, std::size_t N>
struct TypeAt;  //通用版本不用,所以就声明

//特例化版本
//这个时候是取到第N个
template <typename Head, typename... Tail>
struct TypeAt<TypeList<Head, Tail...>, 0> {  //取TypeList中第0个,就是Head
    using type = Head;  
};

//递归,往后取参数,往后取N次就是取到第N个
template <typename Head, typename... Tail, std::size_t N>
struct TypeAt<TypeList<Head, Tail...>, N> {  //取TypeList中第N个,就是Head
    using type = typename TypeAt<TypeList<Tail...>, N - 1>::type;
};

// 使用
using list = TypeList<int, double, char>;  
using third_type = TypeAt<list, 2>::type; // 拿到上面TypeList的第三个参数类型char
```

`TypeAt<TypeList<Head, Tail...>, 0>`这个实现了取TypeList中第0个,就是Head
但他不是一个新的语法
    首先就把这句看出普通的模版传参
    递归是先执行`TypeAt<TypeList<Head, Tail...>, N>`
    然后执行里面的`using type = typename TypeAt<TypeList<Tail...>, N - 1>::type;`
    进入递归最后进入`TypeAt<TypeList<Head, Tail...>, 0>`
    执行里面的`using type = Head;`
    所以是这句实现了"取TypeList中第0个,就是Head"
    所以其实这个数字N和最后那个0  只是方便程序员看
    其实代码里根本不起'实际'作用
