# 大白话解释

## 它在解决什么麻烦？（背景与动机）
现在的人工智能（比如各种大语言模型）在回答问题时，经常需要像我们查百科全书一样，去外部的知识库（比如维基百科）里“检索”资料，这就是所谓的“密集检索（Dense Retrieval）” 。
但在查资料之前，我们必须先决定**把百科全书切成多大的小块**存起来（这就叫“检索粒度”） 。

以前大家通常有两种切法,(两种切法存在缺陷)
- **切成“段落（Passage）”：** 通常是一段大概100个词的话 。
    麻烦的点 在于**太啰嗦**，里面经常包含很多和问题无关的废话细节，这会分散AI的注意力，让它抓不住重点 。
- **切成“句子（Sentence）”：**
    麻烦在于它**没头没尾**(指示代词上下文的缺失)。一句话里经常会出现“它”、“这座塔”这样的代词，如果脱离了上下文，AI根本不知道“它”到底指的是谁，也就无法判断这句话是不是它要找的答案 。

## 论文创新点
为了解决“段落太啰嗦”和“句子没头没尾”的问题，
作者提出了一种全新的文本切分单位，叫做“命题（Proposition）” 。

### 作者怎么定义"命题"?
原话:
    Propositions are defined as atomic expressions within text, each encapsulating a distinct factoid and pre-sented in a concise,self-contained natural lan-guage format.

就是 **“高度浓缩且独立的大白话”**
每一个命题只包含一个独立的事实，并且它自身包含了所有必要的上下文（比如把“它”替换成具体的名字），不需要依赖其他的文本就能看懂 。

### 命题划分的通俗对比
(论文里的例子)
假设有人提问：“比萨斜塔现在的倾斜角度是多少？”
- **段落（Passage）会这么存：** “在1990年到2001年的修复工作之前，这座塔倾斜了5.5度，但现在这座塔倾斜了约3.99度。这意味着塔顶偏离中心3.9米。”
    - —— （整句存,虽然信息完整, 但废话太多 ）
    
- **句子（Sentence）会这么存：** “但现在这座塔倾斜了约3.99度。” 
    - —— （精简到只保留答案信息, 但是这座塔是谁？没有上下文 ）
    
- **命题（Proposition）会这么存：** “比萨斜塔现在倾斜了约3.99度。” 
    - —— （既精准又独立，完美回答问题！ ）

(但是呢, 文字不可能自己就变成作者设想的 完美的一个个"命题")
(所以作者团队用ai 把整个英文维基百科的文章全部重新“翻译”切分成了这种命题级别的句子，建了一个叫 **FACTOID WIKI** 的知识库 。 )

## 实验大概结论
用"命题"切分, 可以对各种检索模型 有哪些方面的提升
- **找得更准（检索能力大增）：** 无论用哪种检索模型，用“命题”来搜索，都比用段落或句子搜索的效果要好得多 。
    
- **回答更好（提升下游问答任务）：** 当AI把找来的资料作为提示词来回答问题时，因为“命题”里全是高密度的干货，在相同的字数限制下，AI能吃到更多有用的信息，大大提高了回答的准确率 。这意味着模型可以在更短的输入长度下达到同样的水平，推理速度也更快了 。
    
- **专治疑难杂症（长尾问题）：** 对于那些比较生僻的知识（论文里叫长尾实体），用“命题”检索的优势比普通段落检索更大 。

## 背景与动机

## 什么是“检索粒度”（Retrieval Granularity）？
在自然语言处理（NLP）中，大模型在回答问题之前, 需要去外部知识库（比如维基百科）里检索信息 。
但在查资料之前，我们必须先决定**把百科全书切成多大的小块**存起来
这个切分的大小，就是 **“检索粒度”**。

## 现有的两种“切法”
- **切成“段落（Passage）”：** 通常是一段大概100个词左右 。
    段落长，肯定能包住正确答案，但它往往包含了太多不相关的废话 。
- **切成“句子（Sentence）”：** 按句号,逗号把文章切成一句一句话
    颗粒度倒是细了，但句子经常不具备独立性 。它**没头没尾**(指示代词上下文的缺失)。一句话里经常会出现“它”这样的代词，如果脱离了上下文，AI根本不知道“它”到底指的是谁，也就无法判断这句话是不是它要找的答案 。
___
## 核心方法论-- “命题”切分

为了解决“段落太啰嗦”和“句子没头没尾”的问题，
作者提出了一种全新的文本切分单位，叫做“命题（Proposition）” 。
### 核心概念：什么是“命题（Proposition）”？
作者对“命题（Proposition）” 有如下3条定义
    ![[Pasted image 20260530180552.webp]]
- **原则一：含义独立且完整（Distinct）。** 
    - 每一个命题只负责讲清楚一个独立的事实 。
    
- **原则二：不可再分（Minimal）。** 
    - 它是最小的原子单位，不能再被继续拆解成更短的命题了 。
    
- **原则三：自带上下文（Self-contained）。** 
    - (这是它和普通“句子”最大的区别。) 
    - 它必须包含所有必要的背景信息，比如把“它”、“这座塔”直接替换成真正的专有名词（比萨斜塔），让它即使脱离了原文，也能被任何人（或AI）一眼看懂 。

### 几种切法的直观对比
![[Pasted image 20260530173526.webp]]

### 工程实现：怎么把维基百科切成命题？
有了"命题"的构想, 句子不可能自己变成一个个完美的命题
靠人工一句一句去改肯定不现实

作者训练了一个专门的文本生成大模型，起名叫 **Propositionizer（命题生成器）** 。来自动化切分文本
这个模型的工作就是：你喂给它一段话，它直接吐出拆解好的命题列表 。
先用GPT-4生成了训练数据 ，训练 Propositionizer 模型 。最后用这个模型把整个维基百科重新切分，得到了惊人的2.5亿个‘命题’ ，建立了一个全新的语料库 。

# 实验
## 实验验证1 —— 检索是不是更准了？

**实验设置:** (两个实验实验设置差不多)
- 4个主流检索模型
    作者特意挑选了两类模型。
    一类是没做过专门问答训练的模型（无监督检索器，如 SimCSE、Contriever）
    另一类是拿海量问答数据进行过训练的（有监督检索器，如 DPR、GTR）。
- 5大题库
    包括了 NQ、TriviaQA、WebQ、SQuAD 和 EntityQuestions（EQ）这5个目前最主流的百科问答数据集 。
- 评分标准（Recall@k）
    实验中用到Recall@5, Recall@20
    指系统找出来的最靠前的 5 条线索里，有没有包含正确答案？
    包含的比例越高，说明系统越准 。

**实验本身**:
![[Pasted image 20260530192910.webp]]
(图上就是 使用预训练的4个检索模型 使用三种不同粒度的检索语料库时，在五个不同的问答数据集上的段落检索性能（Recall@k=5,20）)
(**下划线表示目标数据集的训练集划分已包含在该大模型训练数据中**)

- **对于无监督模型 ：命题检索收益高。** 
    比如使用 SimCSE 模型，用普通“段落”(Passage)检索的 Recall@5 平均分只有 28.4% ；但换成“命题”(Proposition)切分后，直接涨到了 49.5% ！平均相对提升高达 35% 。
    **结论：** 精细的文本预处理，能极大拉高基础模型的检索下限。
    
- **对于有监督模型：命题检索是“生僻题杀手”。** 
    (有点反直觉)
    对于有监督模型在训练时已经见过的旧语料（比如 NQ、TQA），命题(Proposition)和段落(Passage)的成绩差不多 。
    但是！一旦遇到它们没见过的新语料（比如 EntityQuestions 数据集），命题(Proposition)检索的优势瞬间爆发 。
    比如 DPR 模型在EQ这个数据集上，命题(Proposition)相比段落(Passage)提升了高达 25% 。
    **结论：** 命题检索具有极强的跨任务泛化能力（Cross-Task Generalization） 。

**关于泛化能力的进一步实验**: 
![[Pasted image 20260530194229.webp]]
作者专门拿 EQ这个较为冷门的数据集做了进一步分析 。
横坐标代表问题里出现的名词（实体）在百科里出现的频率 ：
    越往左越生僻（长尾知识），越往右越常见 。
纵坐标就是检索模型找对的概率。

根据图表可以看出
    看到图右侧, 当检索模型面对常见大众问题时，3种划分方式表现差不多
    但一旦遇到生僻问题（图左侧），传统的段落检索（蓝线）准确率和其他划分方式拉开差距，而命题检索（红线）依然保持着巨大的领先优势 。

这个实验图表 表明，在面对长尾冷门知识时，冗余的段落会制造致命的干扰，而高信息密度的‘命题’ 可以解决检索模型在检索冷僻事实时的痛点。

## 实验验证2 —— 大模型回答是不是更好了？

**前情提要**:
    大模型每次能“读”的字数是有限的（也是要算算力成本的）。
    为了公平对比，作者规定了一个严格的“字数限制”：不管你用哪种检索方式(或者说划分方式)，每次最多只能给大模型看前 $l=100$ 或 $l=500$ 个词（Tokens） 。

**实验设置:** (两个实验实验设置差不多)
- 4个主流检索模型
    (和上面一样)
- 5大题库
    (和上面一样)
- **大模型选择:** LLaMA-2-7B 大模型
- 评分标准（EM）
    Exact Match (EM)，也就是大模型给出的答案是不是100%精确命中了标准答案 。

**实验本身**:
严格限制给大模型的提示词长度。要么最多给 100 个词（EM@100），要么最多给 500 个词（EM@500） 。
![[Pasted image 20260530202227.webp]]
(实验使用 LLaMA-2-7B 模型的开放域问答性能（EM = 精确匹配, 就是要求模型生成的答案与标准答案完全一致才算正确）。

- **细节一：闭卷考（不给资料）成绩很惨。** 
    (表格第一行是“Closed-book”（闭卷）,完全不用检索模型)
    比如在 SQuAD 数据集上，大模型不查资料自己硬答，准确率只有的 13.0% 。
    这证明了外挂知识库（检索）的必要性。

- **细节二：在严格的 100 词限制下（EM@100），命题的爆发力极强。** 
    看表格里所有的 `@100` 列。在使用 GTR 检索器时，喂给大模型 100个词的“段落”，SQuAD数据集的准确率是 27.4%；
    但如果喂的是 100个词的“命题”，准确率直接飙升到 33.1% 。
    (因为命题干货多)

- **细节三：在 500 词限制下（EM@500），全面领先。** 
    当字数放宽到 500 时，四个检索器（SimCSE, Contriever, DPR, GTR）使用“命题”的平均得分，分别比使用“段落”高出了 4.1、3.2、2.7 和 2.8 分 。

这个时候, "命题"的优势就体现出来
    给大模型看 500 个词的**段落**：可能包含了 80% 的废话和 20% 的有用信息。
    给大模型看 500 个词的**命题**：纯干货。“更高的信息密度（Higher Density of Question-Related Information）”  天然的优势。

这证明了只要给纯干货，大模型的推理就更精准。

“为什么命题能得高分” 
**直观对比"干货"水平的实验**: 
![[Pasted image 20260530205504.webp]]
- **横坐标 (#Words)：** 给大模型输入的前 K 个单词数量（从 0 到 500） 
- **纵坐标 (Recall %)：** 这 K 个单词里面，包含标准答案的概率 

- **陡峭的攀升区（100-200词）：** (图中最左侧的起步阶段。)
    在 100 到 200 词这个极其受限的区间内，代表命题的**红线**以极其陡峭的斜率向上拉升，并且和蓝线（段落）拉开了最大的差距 。
    (所以如果在系统对延迟和显存要求极高、只能读取少量单词的场景下，命题检索能以最快的速度把正确答案‘命中’，这就是高信息密度的威力。)

- **后期的汇合区（500词）：** 
    随着横轴拉长到接近 500 词时，三根线开始慢慢靠近（虽然红线依然领先） 。
    意味着当你给的数据足够多的时候，即使是夹杂着废话的“大段落”，最终也会把正确答案给撞上。
    但代价是大模型可能做了大量无用功，浪费了算力时间。

## 总结与启发

这篇论文证明了，在检索增强生成（RAG）任务中，**文本的切分颗粒度**是一个被长期忽视但至关重要的变量。
通过将文本重构为高信息密度、自带上下文的‘命题（Proposition）’
可以在不改变任何底层检索器和大模型参数的前提下，实现**检索召回率**和**问答准确率**的双重飞跃。

### 启发
- **启发：从工程视角看，这本质上是一场“高信息密度”的性能优化。** 
    这篇论文的做法，本质上就是对大模型宝贵的上下文窗口做了一次“内存对齐”和“缓存优化”——摒弃了带有大量冗余信息的“段落”，直接把提纯后的“命题”塞给模型，用最小的计算开销（Token预算），换取了最高的推理产出。
