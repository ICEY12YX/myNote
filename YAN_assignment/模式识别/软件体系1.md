# 开发过程的应用
| 开发阶段     | 电影拍摄阶段          | 架构（SA）的作用                                                 | 为什么需要？                                             |
| -------- | --------------- | --------------------------------------------------------- | -------------------------------------------------- |
| **需求阶段** | **剧本策划阶段**      | 引入架构思维，确保**剧本（需求）可拍成电影**，且与**导演构思（架构）**一致。                | 防止写出天马行空、技术上无法实现的“需求”。比如剧本要求“一镜穿越四季”，架构师要早期评估是否可行。 |
| **设计阶段** | **分镜与美术设计阶段**   | 用架构模型（如UML图、“4+1”视图）**详细描述系统的结构**，选择成熟的**设计模式/风格**（如微服务）。 | 把模糊的导演构思，变成可执行的拍摄蓝图。让摄影师、美术、演员都知道自己要做什么。           |
| **实现阶段** | **实际拍摄阶段**      | 程序员按照**设计蓝图（架构图）** 写代码，相当于演员按分镜表演，剧组按设计图搭景。               | 确保成千上万的代码模块能像零部件一样精准拼装，而不是各行其是。                    |
| **维护阶段** | **电影上映后修复与出续集** | 在架构设计时，就提前为**修改和扩展**留好接口和空间。比如预留“彩蛋接口”。                   | 让系统像乐高一样易于修改和扩展，而不是一坨水泥，动一处塌全身。                    |
